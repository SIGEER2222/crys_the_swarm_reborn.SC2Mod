# 查链路工具说明

这套脚本的目标不是替代 Galaxy Editor，而是把最常见的“先找对象、再找引用、最后落 XML”的步骤固定下来。

## 推荐工作流

1. 先用 `find-unit-chain.ps1` 看单位主链路
2. 确认武器、效果、行为和按钮对应点
3. 需要追某个升级或按钮时，再用 `find-upgrade-chain.ps1`
4. 改完后用 `git diff` 看最终差异
5. 通过 `sync-to-live.ps1` 覆盖到游戏目录验证

## 脚本

### 1. 查单位链路

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\find-unit-chain.ps1 -UnitId Devourer
```

适合回答这类问题：

- 某单位用了什么武器
- 武器打到哪条 `Effect`
- 命中后又挂了哪些 `Behavior`
- 单位卡上有哪些 `Button`

### 2. 查升级 / 按钮 / 效果链路

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\find-upgrade-chain.ps1 -Id BanelingSpeed
```

适合回答这类问题：

- 某个升级 ID 到底定义在哪
- 哪些单位挂了它
- 哪些文件还在引用它
- 本地文本有没有对应按钮名和提示

### 3. 导出单位索引

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\export-unit-index.ps1
```

输出文件：

- `references\unit-index.tsv`

这个索引适合快速模糊查单位 ID 和中文名，不用每次翻 `GameStrings.txt`。

### 4. 构建对象索引

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build-object-index.ps1
```

输出目录：

- `references\index\units-index.json`
- `references\index\abilities-index.json`
- `references\index\effects-index.json`
- `references\index\behaviors-index.json`
- `references\index\weapons-index.json`
- `references\index\buttons-index.json`
- `references\index\requirements-index.json`
- `references\index\validators-index.json`
- `references\index\references-index.json`
- `references\index\catalog-summary.json`

这个索引适合让 AI 或脚本先看“小块结构化对象”，再决定改哪段 XML。

### 5. 常见断链校验

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\validate-common-refs.ps1
```

输出文件：

- `references\latest-validate-report.md`

当前会检查：

- `Unit -> Ability / Behavior / Weapon / Button / Requirement`
- `Ability -> Effect / Button / Requirement`
- `Effect -> Effect / Behavior / Validator`
- `Behavior -> Effect / Requirement / Validator`
- `Weapon -> Effect`
- `Requirement -> RequirementNode`

## 说明

- 这套工具优先解决“定位快”的问题，不追求一次性完整建模所有 XML 继承关系。
- 遇到父类继承、隐藏数据或编辑器专属字段时，仍建议配合 Galaxy Editor 交叉确认。
