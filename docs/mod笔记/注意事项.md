在 **StarCraft II (SC2) 的自定义模组（Mod）开发**里，单位、建筑和技能之间的“挂钩”关系主要是通过 **数据编辑器（Data Editor）** 来实现的。SC2 的 Data Editor 是基于数据库的设计，所有游戏元素都是条目（Data Entries），它们之间通过引用和属性连接。下面我给你详细梳理一下原理和实现方式。

---

## 1. 单位与技能的挂钩

在 SC2 中，**单位（Unit）本身并不会直接拥有技能，而是通过“单位技能表”或“行为（Behavior）”来关联技能**。

### 步骤

1. **技能条目（Ability）**

   * 每个技能都是一个 `Ability` 类型的数据条目。
   * `Ability` 中定义技能的类型（主动/被动/被动光环）、冷却、消耗、效果（Effect）等。
2. **单位条目（Unit）**

   * 打开单位条目，你会看到 **Abilities** 这个字段。
   * 这里可以添加一个或多个 `Ability` 的引用。
   * 添加的技能就变成该单位的技能。

### 举例

* 假设你制作一个新单位 `MyMarine`，你希望它有一个叫 `Grenade` 的技能：

  1. 在 `Ability` 里创建 `Grenade`。
  2. 在 `MyMarine` 的 `Abilities` 列表里添加 `Grenade`。
* 运行游戏时，`MyMarine` 就能使用 `Grenade`。

> 注意：有些技能是自动触发的（Passive/Behavior），有些技能需要玩家手动点击（Active）。

---

## 2. 建筑与技能的挂钩

建筑与单位一样，也通过 **Abilities** 或 **生产列表（Unit Production）** 来挂钩技能。

### 主要方式

1. **生产单位**

   * 建筑有一个字段叫 `Unit Production`。
   * 你可以指定建筑可以生产哪些单位。
   * 如果单位自带技能，生产出来后自然也拥有这些技能。

2. **建筑主动技能**

   * 建筑本身也可以挂技能（Ability），比如 `Photon Cannon` 的攻击能力就表现为一个技能。
   * 通过 **Abilities 列表**关联技能。

3. **行为（Behavior）触发**

   * 有些建筑的被动效果是通过 `Behavior` 来实现的，例如 Buff、光环、自动治疗。
   * Behavior 本身也可能触发某个 `Effect`，间接形成技能效果。

---

## 3. 技能的效果（Effect / Buff / Target）

技能本身只是一个“动作定义”，它的实际作用由 **Effect** 和 **Target** 决定。

* **Effect**：技能执行的动作，例如造成伤害、加速、召唤单位。
* **Target**：技能作用的对象，例如单位、建筑、地面位置。
* **Behavior**：持续效果或状态，比如 Buff、Debuff。

> 举例：
>
> * 一个主动技能“EMP”：
>
>   * Ability: EMP
>   * Effect: 消耗能量，对目标去除护盾
>   * Target: 敌方单位
>   * Behavior: 标记被影响的单位状态

---

## 4. 数据编辑器中挂钩关系概览

| 条目类型          | 挂钩对象                     | 说明                 |
| ------------- | ------------------------ | ------------------ |
| Unit/Building | Ability                  | 直接关联技能列表，单位或建筑获得技能 |
| Ability       | Effect / Behavior / Buff | 定义技能的实际作用和状态       |
| Building      | Unit Production          | 定义可以生产哪些单位         |
| Ability       | Target/Requirement       | 定义技能可作用对象和条件       |

---

## 5. 开发小技巧

1. **复制现有单位或技能**：不要从零开始，复制现有单位或技能再修改，可以避免很多隐藏的依赖。
2. **技能测试**：在 Data Editor 中测试时注意技能的冷却和能量消耗，方便调试。
3. **Behavior 与 Ability 的区别**：

   * Ability 更偏向“玩家操作的技能”
   * Behavior 更偏向“持续效果或状态”，可以附加在单位或技能上。

如果要将游戏里面的战役单位建筑，或者合作指挥官的单位建筑提取出来，如何做？

在 SC2 里，战役单位、合作指挥官单位，本质上也是 Data Editor 里的数据对象。
你所谓“提取出来”，通常有三种情况：

2. **复制到自己的数据里做修改**

这三种方式复杂度差很多。

# 一、SC2 的数据来源结构

SC2 的所有数据都来自：

* `Liberty.SC2Mod`（自由之翼）
* `Swarm.SC2Mod`（虫群之心）
* `Void.SC2Mod`（虚空之遗）
* `Campaign.SC2Mod`
* `Coop.SC2Mod`

等等依赖（Dependency）。

战役单位、合作指挥官单位，其实就在这些依赖里面。

例如：

* 凯瑞甘战役技能
* 阿巴瑟进化单位
* 德哈卡
* 阿拉纳克毁灭者
* 凯拉克斯机械
* 扎加拉自爆虫

都在对应 Dependency 里。

# 二、最简单的方法：添加依赖

这是最推荐的方法。

---

## 1. 打开地图或 Mod

进入：

```text
File -> Dependencies
```

添加：

* Campaign
* Void Multi
* Coop

等依赖。

---

## 2. 打开 Data Editor

搜索：

```text
Commander
Campaign
```

或者单位名：

```text
Stukov
Dehaka
Abathur
```

你会发现：

* 单位
* 武器
* 技能
* Actor
* Model
* Sound

全部已经存在。

你可以直接使用。

# 四、真正的“提取”是什么意思

很多人真正想做的是：

> 不依赖 Coop/Campaign，
> 把单位完全复制到自己的 Mod 中。

因为：

* 发布地图时不想依赖战役
* 想修改原单位
* 想避免冲突
* 想做大型独立 MOD

这就进入“数据迁移”。

---

# 五、SC2 的单位不是一个对象

这是最关键的地方。

一个“单位”实际上由几十种数据组成：

| 类型          | 作用   |
| ----------- | ---- |
| Unit        | 单位本体 |
| Actor       | 模型显示 |
| Model       | 模型资源 |
| Weapon      | 武器   |
| Effect      | 伤害逻辑 |
| Behavior    | Buff |
| Ability     | 技能   |
| Sound       | 音效   |
| Validator   | 条件判断 |
| Requirement | 科技需求 |
| Button      | UI按钮 |

所以：

> 你复制一个 Unit 并不够。

## 4. 哪些必须复制？

一般必须：

? Actor

? Effect
? Behavior
? Ability

通常不复制：

? Model（直接复用暴雪资源）
? Sound
? Texture

否则数据量会爆炸。

# 七、合作指挥官单位的坑

合作模式的数据结构极其复杂。

因为：

* 暴雪大量复用了数据
* 多层继承
* 自动升级
* Prestige
* 指挥官 Buff
* 隐藏 Behavior

比如：

```text
Dehaka
```

实际上关联：

* Essence
* Hero Respawn
* Devour
* Level Scaling
* Auto Behaviors

一堆隐藏逻辑。

所以：

> 直接 Duplicate 有时会炸。

---

### 3. Weapon

* 升级
* 科技树
* AI
