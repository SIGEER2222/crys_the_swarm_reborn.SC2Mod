## 共同规则

1. 当前默认口径是 15 级、6 项精通全满、威望只取正面收益。
2. 不要把 `initial` 当成默认玩法状态，它只用于官方基础状态审计。
3. 每个指挥官的单位、建筑、面板、被动、升级链都不一样，不能用一个模板硬套。
4. 最大的坑通常不是“有没有这个单位”，而是“这个单位是不是该指挥官的变体、满级替换、英雄模式或专属建筑版本”。
5. 写实现前，先把 `roster / buildings / command_cards / upgrades / heroes / special_mechanic` 六块资料看全。

## 阿巴瑟

- 兵种和建筑：核心是生物质驱动的进化链，不是普通虫族科技树。重点看蟑螂、破坏者、虫群宿主、飞蛇、利维坦、孢子/脊针爬虫。
- 面板：面板不是简单的召唤按钮，很多按钮实际是进化、变体或满生物质后的替换入口。
- 被动：生物质叠层、终极进化、满生物质后的终局变体是核心。
- 注意点：不要把普通跳虫、刺蛇、普通女王混进阿巴瑟；“莽兽”也不要写成普通独立兵种，必须按终局进化理解。
- 验证顺序：先核对 roster，再核对满级替换，再核对生物质和终极进化闭包。

## 阿拉纳克

- 兵种和建筑：塔达林体系为主，地面兵线清晰，建筑偏星灵常规，但科技和单位解锁关系不同。
- 面板：阿拉纳克本体、供奉我、死亡舰队、超载是主要顶栏逻辑。
- 被动：献祭、升格者增益、死亡舰队的临时单位和能量体系是关键。
- 注意点：塔达林单位、普通星灵单位、召唤单位要分开写，不要把“追猎者/不朽者/执政官”按阿塔尼斯逻辑硬套。
- 验证顺序：先看本体技能，再看献祭和死亡舰队，再看兵种科技树。
- 开发抓手：优先核对 `roster / buildings / command_cards / upgrades / hero / prestige`，再补 `sacrifice` 和 `Death Fleet` 的闭包。
- 公开核对关键词：`Soul Absorption`、`Summon Death Fleet`、`Burning Skies`、`Wrath of the Highlord`。
- 容易错的点：`Supplicant` 系列、死亡舰队召唤、塔达林升级按钮和普通星灵科技链容易互相串。

## 阿塔尼斯

- 兵种和建筑：标准星灵骨架，但围绕亚顿之矛扩展，核心是狂热者、龙骑、不朽者、巨像、航母链。
- 面板：守护之壳、轨道轰炸、太阳打击/太阳轰炸、折跃增强是主轴。
- 被动：全军护盾和折跃强化是强度来源。
- 注意点：面板和建筑升级强绑定亚顿之矛，不能当普通 Protoss 处理。
- 验证顺序：先面板，再建筑升级，再单位护盾/折跃链。
- 开发抓手：先把 `Guardian Shell`、`Orbital Strike`、`Shield Overcharge`、`Chrono Field` 四条顶栏/被动线对齐，再处理兵营、机械学与折跃门的解锁。
- 公开核对关键词：`Guardian Shell`、`Orbital Strike`、`Shield Overcharge`、`Chrono Wave`。
- 容易错的点：护盾/折跃升级、航母链、机械单位和普通星灵基础单位的层级不要混。

## 德哈卡

- 兵种和建筑：原始跳虫、原始蟑螂、原始刺蛇、原始异龙、原始守护者、原始穿刺者、暴龙兽等，满级后变体很多。
- 面板：很多技能随着等级和巢穴解锁，不能只看初始按钮。
- 被动：精华、原始洞察、虫群首领成长、等级提升后变体替换是核心。
- 注意点：德哈卡的“单位列表”不是静态清单，必须区分初始、15 级和融合后状态。
- 验证顺序：先核对英雄本体，再核对四个虫群首领，再核对等级解锁链。

## 菲尼克斯

- 兵种和建筑：净化者、艾尔、人格载体、战甲切换相关单位是主轴。
- 面板：多个英雄智能/人格模块会改变单位解锁和技能。
- 被动：战甲切换、人格继承、队伍替换是核心。
- 注意点：不要把普通星灵当成最终版本；菲尼克斯更像“人格 + 战甲 + 兵种”的组合系统。
- 验证顺序：先确认战甲，再确认人格，再确认对应兵种和科技。
- 开发抓手：把 `Armor Suit`、`Purifier Conclave`、`Champion AI`、`Tactical Data Web` 四条线分开实现，再回头统一看军团编成。
- 公开核对关键词：`Variable Deployment`、`Purifier Conclave`、`Tactical Data Web`、`Operational Efficiency`。
- 容易错的点：英雄本人、战甲人格、AI 军团 shell、净化者/艾尔单位是四套不同层级，不能合并写。

## 霍纳与汉

- 兵种和建筑：双军种体系，霍纳侧舰队、汉侧雇佣军和地面机械分别看，不要混成一条线。
- 面板：呼叫舰队、攻击战斗机、空间站调度、战术跳跃是主轴。
- 被动：双方互相提供增益是这个指挥官的核心特色。
- 注意点：Horner/Mira/雇佣军/舰队这几类对象很容易互相串。
- 验证顺序：先分清两套兵线，再看顶栏召唤，再核对共享加成。

## 凯拉克斯

- 兵种和建筑：机械防线和静态防御是主轴，光子炮台、护盾充能器、凯达琳巨石、机械单位都要分开。
- 面板：太阳能利用、重构光束、轨道轰炸、太阳耀斑是核心。
- 被动：维修、护盾、太阳能回充和建筑防御强化是重点。
- 注意点：凯拉克斯的关键不是“兵够不够”，而是“建筑能不能把整套防线跑起来”。
- 验证顺序：先面板，再建筑防御，再机械单位。
- 开发抓手：先把 `Master Machinist`、`Chrono Field`、`Khaydarin Monolith`、`Purifier Beam`、`instant warp-in` 这几条机制闭合，再看结构化建筑升级。
- 公开核对关键词：`Master Machinist`、`Khaydarin Monolith`、`Purifier Beam`、`Khalai Ingenuity`。
- 容易错的点：凯拉克斯大量依赖建筑与被动修复，若只做兵种会严重失真。

## 凯瑞甘

- 兵种和建筑：必须按刀锋女王体系处理，跳虫不是普通跳虫，刺蛇和雷兽也都有合作模式变体。
- 面板：定身波、吞噬、原始突袭、群体技能与解锁等级绑定很紧。
- 被动：能量恢复、同化资源、菌毯、单位进化与英雄状态强绑定。
- 注意点：本体形态必须是刀锋女王形态；跳虫会进化为腾跃虫，雷兽有暴龙兽方向，不能把普通虫族逻辑套进去。
- 验证顺序：先英雄本体，再单位变体，再技能点和等级解锁。
- 当前 compare 里 `SILarva` / `SIBasicBuild` 需要按凯瑞甘的基础虫族链别名处理，不要误当成真缺口。
- 开发抓手：先确认刀锋女王本体、定身波、跳击/灵能位移、虫道网络欧米茄，再补跳虫/刺蛇/雷兽的变体与升级。
- 公开核对关键词：`Mutating Carapace`、`Crushing Grip Wave`、`Leaping Strike`、`Omega Worm`、`Fury`。

## 蒙斯克

- 兵种和建筑：帝国劳工、冲锋队、皇家卫队、攻城炮、战锤、维京、战列和发射井都要按帝国体系写。
- 面板：帝国支持度、见证者、战术飞弹、辐射打击是核心。
- 被动：皇家卫队军阶、支持度和统治力系统是这个指挥官的骨架。
- 注意点：普通劳工线和皇家卫队线是两套资源逻辑，不能混。
- 验证顺序：先支持度，再皇家卫队，再核弹和炮台。

## 诺娃

- 兵种和建筑：合作模式诺娃必须用专用 SCV、专用兵营、专用重工厂、专用星港和特战单位。
- 面板：狮鹫号空袭、战术空运、战术聚变打击、全息诱饵、诺娃装备切换是核心。
- 被动：潜行/突击双形态、研究加速、装备切换和精英单位替换是重点。
- 注意点：不要把战役版 SCV/兵营/工厂/基地混进来；英雄诺娃和她的装备形态必须单独处理。
- 验证顺序：先建筑和工人，再本体技能，再面板切换和精英部队。

## 雷诺

- 兵种和建筑：合作版人族骨架，但要用雷诺自己的 SCV、兵营、工厂、星港、轨道基地和机甲线。
- 面板：MULE、女妖空袭、休伯利安号、轨道空投是主要入口。
- 被动：生化部队、机械部队、空中部队和休伯利安支援共同构成战术核心。
- 注意点：战役版对象不能混入合作模式；刺激剂、后燃、升级链都要和合作模式对齐。
- 验证顺序：先 SCV/基地，再生化线，再机械线，再休伯利安。
- 开发抓手：把 `Stimpack`、`MULE`、`Hyperion`、`Orbital Drop Pods`、`Weapon Refit`、`Advanced Optics` 作为优先核对项。
- 公开核对关键词：`Stimpack`、`Hyperion`、`Orbital Drop Pods`、`Weapon Refit`、`Advanced Optics`。
- 容易错的点：雷诺的关键不是“人族通用”，而是合作版专属 SCV、基地和兵营/工厂/星港的整套替换。

## 斯台特曼

- 兵种和建筑：机甲虫群是主轴，配合艾贡卫星、能量区、盖瑞/超级盖瑞。
- 面板：卫星覆盖、盖瑞召回、超载、机甲单位专属按钮是核心。
- 被动：艾贡区域、机油/能量联动、机械单位增益是核心强度来源。
- 注意点：这是一个“空间区块 + 机制联动”的指挥官，不能按普通虫族写。
- 验证顺序：先盖瑞和卫星，再机甲单位，再能量区和超载。

## 斯托科夫

- 兵种和建筑：感染版人族和感染版建筑是主轴，感染指挥中心、感染兵营、感染工厂、感染星港、虫巢女王都要分清。
- 面板：末日巨兽、亚历山大号、感染建筑升级包是核心。
- 被动：菌毯、感染建筑持续产出、平民死亡生物质化都是核心机制。
- 注意点：普通人族建筑不能直接替代感染版建筑；感染兵种有自己的生命期和产出逻辑。
- 验证顺序：先建筑，再感染兵，再顶栏巨兽/舰船。

## 斯旺

- 兵种和建筑：机械部队、炮塔、SCV、德拉肯激光钻机和工厂线是主轴。
- 面板：激光钻机升级、脉冲炮、空投和高级建造是核心。
- 被动：建筑修理、自动灭火、机械单位强化是重点。
- 注意点：斯旺的强度围绕建筑和维修，不是常规生化人族。
- 验证顺序：先激光钻机，再机械兵，再建筑修理和炮塔。
- 开发抓手：先把 `Vehicle Specialist`、`Combat Drop`、`Drakken Laser Drill`、`Vespene Harvester`、`Factory Upgrade Cache`、`Armory Upgrade Cache` 的闭包打通。
- 公开核对关键词：`Vehicle Specialist`、`Combat Drop`、`Drakken Laser Drill`、`Vespene Harvester`。
- 容易错的点：`Command Center`、`Factory`、`Armory` 的升级和机器人单位要按 Swann 专属后缀统一，不要把战役版或其他指挥官名残留进来。
- 额外直连名：`WraithSwann`、`330mmBarrageCannonsSwann`、`CommandCenterTrainSwann`、`FactoryResearchSwann`、`StarportTrainSwann`。
- 进一步说明：Swann 的 Wraith 是自有命名，不要再按 `SIWraith` / `SIMorphtoInfestedWraith` 的字面名去理解实现；那两条更适合当官方残差/映射检查点。

## 泰凯斯

- 兵种和建筑：不法之徒全是英雄级个体，酒吧、枪王藏身处、猛男军械库、鬼手安全屋等是核心建筑。
- 面板：红色按钮、奥丁、各个不法之徒的招募和装备是核心。
- 被动：每个英雄装备独立，数量、搭配、解锁顺序都重要。
- 注意点：这不是“正常编队”，而是“英雄小队 + 招募建筑 + 装备系统”。
- 验证顺序：先招募链，再装备链，再奥丁和高级终极装备。

## 沃拉尊

- 兵种和建筑：黑暗圣堂、追猎者、狂热者、先知、黑暗水晶塔和黑暗执政官是主轴。
- 面板：时间停止、召回、隐形相关升级是核心。
- 被动：隐形、暗影军团、黑暗水晶塔召回是核心机制。
- 注意点：这个指挥官的关键不是硬碰硬，而是隐形和节奏控制。
- 资料核对时要特别注意 `ShadowStalk` 这一类名称，它更像黑暗圣堂武士开局改造的总称，不一定对应一个独立面板按钮。
- 额外留意虚空辉光舰的 `VoidRaySwarmDamageBoost` / `VoidRaySwarmDamageBoostCancel`，这条链在当前仓库里还没有完全收口，先按真实待补能力处理。
- 验证顺序：先隐形和召回，再时间停止，再黑暗军团升级。
- 开发抓手：先对齐 `Shroud of Adun`、`Dark Pylon Recall`、`Shadow Legion`、`Void Stasis`、`Time Stop` 五条核心能力，再补黑暗圣堂/黑暗水晶塔的建筑链。
- 最新 compare 已归零；这位现在可以按“完成参考”写法接手。

## 扎加拉

- 兵种和建筑：数量型虫群，跳虫、爆虫、腐化者、爆蚊、胆汁喷射体、虫巢女王都要按合作模式版本处理。

- 资料核对时要注意 `SIBasicBuild` 这类基础建造命名，很多时候它只是虫族建造链的官方别名，和 mod 里的 `ZergBuild` 语义更接近。

### 当前测试建议

推荐测试地图：`原始mod/Maps/XM/CommanderTestBench.SC2Map`。

- `standard_base`

判定标准：

1. 基地能正常落地。
2. 兵种与建筑能完整刷出。
3. 面板能点到正确对象。
4. 变体和满级替换不缺失。
5. 运行时日志能看见当前指挥官的关键对象列表。

### 当前 live 对比结论

这轮直接对 `E:\SC2\SC2new\StarCraft II` 跑了九位指挥官的官方 vs mod 对比，当前 live 侧的共同特征是：

- `units / buildings / upgrades` 基本已经对齐。
- `abilities` 基本干净，只剩个别命名/映射痕迹。
- 主要差异集中在 `buttons / commander_perks`，而且很多是按钮命名或面板级别的差异，不是基础兵种骨架问题。

经过这轮 compare 别名修正后，当前最值得继续盯的残留项是：

| 指挥官 | 当前残留 | 先验判断 |
|---|---|---|
| 阿拉纳克 | 已收口为 0 | 目前看是清净的，可以作为正确性参照。 |
| 阿塔尼斯 | `units: 1`、`abilities: 1` | 仍需核对是否是跨指挥官误报，尤其是 `AlarakSupplicantWarpTrainCreator`。 |
| 菲尼克斯 | `units: 1`、`abilities: 1` | 目前更像误报，和塔达林/折跃相关对象串线的概率更高。 |
| 凯拉克斯 | `units: 1`、`abilities: 2` | 重点看是否仍有折跃/建筑链的命名漂移。 |
| 雷诺 | `abilities: 1` | 当前只剩一个 `255`，优先核对是否为特殊占位或脚本侧调用。 |
| 斯旺 | `units: 2`、`abilities: 6` | 还要继续看机械单位和炮塔/维修链是否有漏接。 |

这意味着后续实现时，不要再把重点放回“有没有基地/有没有基础兵种”这种第一层问题，而要转到：

1. 指挥官顶栏按钮。
2. 解锁按钮与升级包按钮。
3. 满级替换、变体和面板被动的文本/绑定。
4. 实机日志里是否能打印出当前指挥官的关键对象列表。
