## 未来规划

### 阶段 1：先验证测试地图能加载

目标：确认测试台不是纸面设计。

执行顺序：

1. 用 SC2 Editor 打开 `原始mod\Maps\XM\CommanderTestBench.SC2Map`。
2. 确认依赖能解析到 `XMFinal.SC2Mod`。
3. 进入测试地图，点击 Raynor。
4. 依次跑：
   - `standard_base`
   - `full_units`
   - `full_buildings`
   - `panel_cost_smoke`
   - `Run Smoke`
5. 保存 `[XM_DBG]` 关键日志。

通过标准：

- 地图能加载。
- 按钮能响应。
- `XMTestBench_*` 能调用到 `XMFinal`。
- Raynor `full_units` 和 `full_buildings` 能生成对象或明确输出 missing。
- `Run Smoke` 最终不会无条件 ok，而是按 warnings/errors 聚合。

### 阶段 2：补 Raynor 真实闭环

优先补 Raynor，因为它是当前第一条 profile。

建议顺序：

1. 确认 Raynor 10 个单位和 16 个建筑在当前依赖链中实际可创建。
2. 把 `CreateProfileUnit` 的计数方式改得更可靠。
3. 补 Raynor `standard_base` 专属 hook：星轨、矿骡、基础面板 caster。
4. 决定是导入官方 `CoopCasterRaynor` 依赖，还是在 XMFinal 内创建本 mod 自己的 Raynor panel caster。
5. 把 `panel_cost_smoke` 从 metadata-only 升级成真实扣费/冷却/充能验证。
6. 再做 `panel_effect_smoke`，至少验证 Hyperion 或 BansheeAirstrike 的召唤/伤害效果。

### 阶段 3：扩 Nova / Abathur

Raynor 路径稳定后，优先扩这两个，因为它们覆盖复杂机制：

- Nova：英雄形态切换、攻击方式变化、装备/技能面板、精英单位。
- Abathur：生物质、终极进化、单位变体、`heroes.json=0` 的特殊审计口径。

不要一开始扩 18 个 commander。先保证 Raynor/Nova/Abathur 三个能跑出代表性闭环。

等 3 个指挥官试点稳定后，再把当前 helper 收敛成 profile/factory：

- `CommanderRosterProfile`

- `CommanderBaseHook`

### 阶段 5：18 指挥官全量回归

1. 每个 commander 的 `full_units`。
2. 每个 commander 的 `full_buildings`。
