# 重生阿巴瑟闭包与接入口径

日期：2026-06-03

## 结论

重生阿巴瑟不是官方合作指挥官阿巴瑟，也没有官方合作指挥官那套 `15 级 / 6 精通 / 3 威望` 解锁体系。

它的真实进度来源是本地嵌套 Mod 的 `cryswarmcoop` bank、地图完成标记、进化选择、突变选择、运行时 `Abathur` upgrade 和 `Lib48DF4533.galaxy` 触发器。后续接入 XM 或整理文档时，不能从官方 `commanders/Abathur/progression.json` 反推它的兵种、等级、精通或威望。

## 不适用的官方体系

| 项 | 官方合作阿巴瑟 | 重生阿巴瑟 |
|---|---|---|
| 指挥官来源 | `游戏数据/官方合作指挥官/commanders/Abathur/` | 嵌套 Mod `crys_the_swarm_reborn.SC2Mod` |
| 等级 | 官方 `level 1..15` | 不适用，没有 15 级解锁表 |
| 精通 | 官方 6 项精通 | 不适用，不能套官方精通 |
| 威望 | 官方 3 个 `PlayerPrestige` | 不适用，不能套官方威望 |
| 进度源 | 官方 commander JSON/UserData | `cryswarmcoop` bank 的 `Maps`、`Evolutions`、`Mutations`、`Unity`、`Commanders` |
| 运行时开关 | 官方 coop runtime | `UpgradeData.xml` 里的 `Abathur` / `AbathurAnnouncer` |

本地源里能搜到 `Coop_Prestige_Tooltip` 一类文本，但那些是地图提示样式和难度提示，不是官方合作指挥官威望定义。也能搜到 `StructureMastery`、`Mastery` 字样，但它们是本地按钮/其他单位 UI 文本，不等于阿巴瑟拥有官方精通体系。

## 运行时状态键

| Bank section | Key | 作用 |
|---|---|---|
| `Commanders` | `Commander` | 指挥官选择，阿巴瑟值为 `Abathur` |
| `Maps` | 任务名 | 记录任务完成，驱动单位/进化/地图按钮解锁 |
| `Evolutions` | 族系名 | 记录每个族系当前选择的进化变体 |
| `Mutations` | 族系名 | 记录每个族系当前选择的突变/升级方向 |
| `Unity` | `Kerrigan/Army` 槽位 | 凯瑞甘/军团通用强化选择，不是阿巴瑟等级 |
| `Settings` | 难度/速度/资源共享等 | 运行设置，与阿巴瑟解锁不同源 |

`Restart` 触发器会删除 `Evolutions`、`Mutations`、`Unity`、`Maps`、`Bonuses`、`Commanders` 这些 section。这里也可以看出它的进度是 bank section 驱动，而不是官方 level table。

## 破坏者技能链

重生阿巴瑟的破坏者使用本地单位 `Ravager`，不是官方合作阿巴瑟的 `RavagerAbathur`。

| 项 | 本地链路 |
|---|---|
| 单位 | `UnitData.xml` 中 `CUnit id="Ravager"` |
| 单位能力 | `RavagerCorrosiveBile`、`BurrowRavagerDown` |
| 命令卡 | `RavagerCorrosiveBile,Execute`，按钮 `RavagerCorrosiveBile` |
| 能力定义 | `AbilData.xml` 中 `CAbilEffectTarget id="RavagerCorrosiveBile"` |
| 能力参数 | 自动施法开启，范围 `9`，自动施法范围 `9` |
| 效果线索 | `EffectData.xml` 中存在 `RavagerCorrosiveBileSearch` |
| 不要混用 | 不要套官方 `RavagerAbathurCorrosiveBile` |
| 不要混用 | `PrimalRavager`、`PlasmaTorrent`、`Blinded`、`Cauterized` 是原始破坏者/德哈卡相关线索，不是重生阿巴瑟破坏者主链 |

接入 XM 时，破坏者必须把按钮、ability、effect/search 和 burrow ability 一起接入。只接按钮会出现“按钮可点但无效果”风险；只接官方 `RavagerAbathur*` 会把本地 `Ravager` 的自定义链路接歪。

## 派生单位隔离原则

重生阿巴瑟接入时，优先用自定义派生单位 ID 承载按钮、技能和变异路线，不要直接改共享单位原型。

| 场景 | 建议 |
|---|---|
| 接入 `Ravager` | 建 `AbathurRebornRavager` 或同等私有 ID，继承本地 `Ravager`，再挂本地 `RavagerCorrosiveBile` 链 |
| 接入蟑螂变体 | `RoachVile`、`RoachCorpser`、`Igniter`、`Ravager` 都做私有映射，不改共享 `Roach` |
| 接入飞龙变体 | 购买升级挂在私有单位或私有 profile，不把 `Mutalisk` 原型改成全局阿巴瑟单位 |
| 接入爬虫 | `SpineCrawler` / `SporeCrawler` 的购买能力和科技研究分开承载，避免把防御建筑特殊升级塞进普通兵种升级 |
| 接入大型单位 | `Leviathan`、`Omegalisk`、`Brutalisk` 先按训练项和测试台确认归属，不直接当英雄或官方终极单位 |

## 当前剩余风险

| 风险 | 处理方式 |
|---|---|
| `ButtonData.xml` 可能含非法 XML 字符 | 自动生成时优先从 `GameStrings.txt`/`ObjectStrings.txt` 取按钮名，ButtonData 做容错 |
| 五档攻防目前仍是静态验证 | 已能追到 Catalog 闭包，但研究后的真实数值、按钮替换和排队状态仍要进 SC2 实机确认 |
| `XMFinal.SC2Mod/DocumentHeader` 仍未包含 `XMAbathurReborn` | 已更新 `DocumentInfo` 和 runtime/Catalog 兜底；如果 `DocumentHeader` 当前还有其他差异，仍需单独确认归属，补 `XMAbathurReborn` 依赖必须先得到用户授权 |
| `Leviathan`、`Omegalisk`、`Brutalisk` 归属可能跨链 | 先按训练命令记录，实机测试后再决定是否纳入阿巴瑟最终可用态 |
| `PrimalSunkenColony` 只有 Catalog 存在 | 未纳入重生阿巴瑟主链前，不作为重生阿巴瑟正向建筑 |
| 购买升级分布在单位自身 | 不能只扫科技建筑，否则会漏掉按钮可点但效果未接的风险 |
| 破坏者有本地链和官方链名称冲突 | 重生阿巴瑟只按本地 `Ravager` / `RavagerCorrosiveBile` 闭包接入 |
