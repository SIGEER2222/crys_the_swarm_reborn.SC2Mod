# 重生阿巴瑟兵种融入设计

更新时间：2026-06-03

## 结论

重生阿巴瑟不应该做成“所有虫群变体都能同时建造”的收藏夹。

更合适的定位是：每个生物族系只有一个当前进化方向，未选择的同族变体隐藏或不可用；巨型/实验单位走限量、冷却、终局选择或特殊资源入口；建筑也走白名单，而不是照搬源 Mod 工蜂卡面。

这样既保留重生阿巴瑟“实验体很多”的特色，也不会把面板、科技树、AI 和技能闭包压到不可维护。

## 文档边界

这份文档回答“这么多单位怎么融入 XM 玩法”。

事实闭包仍以 `02-重生阿巴瑟-闭包与接入口径.md` 为准。这里的内容是接入设计，不是说源 Mod 里当前已经这样实现。

本设计不走官方合作阿巴瑟的等级、精通、威望路径。重生阿巴瑟来源是嵌套 Mod：

`crys_the_swarm_reborn.SC2Mod/crys_the_swarm_reborn.SC2Mod`

## 设计目标

| 目标 | 说明 |
|---|---|
| 有取舍 | 同一族系不能全部同时可建造，玩家需要选择当前虫群方向 |
| 可维护 | XM 接入时按族系闭包管理，不在一个幼虫面板里堆几十个按钮 |
| 不串线 | 每个接入单位优先做重生阿巴瑟私有 ID，避免改到其他指挥官共享单位 |
| 可验证 | 每个可造单位必须能追到按钮、能力、效果、行为、需求和文本 |
| 防误纳 | `NydusNetwork`、`Naktul`、跨链 `Leviathan` 等对象不能因为源 Mod 里出现就进正向清单 |

## 核心规则

| 规则 | 设计口径 |
|---|---|
| 幼虫候选池不等于最终可造清单 | `LarvaTrainSwarm2` 里的 `Train1` 到 `Train30` 只是候选入口 |
| 同族只开一个主变体 | `Evolutions/<族系>` 当前值决定正向可造单位 |
| 未选变体隐藏 | 不在命令卡显示，也不被运行时白名单放开 |
| 巨型单位不量产 | `Brutalisk`、`Omegalisk`、`Blightbringer`、`Leviathan` 不进普通幼虫批量生产 |
| 技能随单位闭包 | 例如 `Ravager` 必须随 `RavagerCorrosiveBile`、按钮、效果、Burrow 链一起接入 |
| 建筑走白名单 | 工蜂卡面只保留重生阿巴瑟正向建筑，不照搬源 Mod 的混合按钮 |
| 负例隔离 | 只要归属不清，就先放候选/负例区，不进入正向可建造链 |

## 总体玩法模型

建议把重生阿巴瑟拆成 4 个入口：

| 入口 | 作用 | 面板位置建议 |
|---|---|---|
| 经济和建筑白名单 | 工蜂建造基础经济、科技和防御 | 工蜂建造菜单 |
| 族系主链 | 幼虫变异当前已选择的族系单位 | 幼虫命令卡 |
| 进化选择 | 每个族系选择一个方向 | 主巢/进化腔/专用“进化菜单” |
| 实验体和终局 | 巨型单位、一次性强单位、全局升级 | 主巢/虫穴/虫巢的专用子菜单 |

设计上不要把“进化选择按钮”和“生产按钮”混在一起。

生产按钮只负责建造当前选择结果。进化按钮负责改变族系方向。

## 建筑入口白名单

### 推荐正向建筑

| 类别 | 建筑 | 接入口径 |
|---|---|---|
| 基地 | `Hatchery`、`Lair`、`Hive` | `Hatchery` 由工蜂建造，`Lair/Hive` 走基地升级 |
| 采气 | `Extractor` | 默认采气建筑 |
| 基础科技 | `SpawningPool`、`EvolutionChamber` | 解锁跳虫/基础升级/防御升级 |
| 地面族系 | `BanelingNest`、`RoachWarren`、`HydraliskDen` | 解锁毒爆、蟑螂、刺蛇族系 |
| 高级科技 | `InfestationPit`、`Spire`、`GreaterSpire`、`UltraliskCavern` | 解锁宿主、施法者、飞行、雷兽、巨型飞行单位 |
| 防御 | `SpineCrawler`、`SporeCrawler` | 保留爬虫防御链 |

### 不进默认建筑白名单

| 对象 | 处理 |
|---|---|
| `NydusNetwork` | 不作为重生阿巴瑟正向建筑。它在源 Mod 中与 `Naktul`、坑道虫链路交叉，不能直接放进重生阿巴瑟建筑 |
| `GreaterNydusWorm` | 与 `NydusNetwork` 同样隔离 |
| `PrimalSunkenColony` | 源 Mod 有 `ZergBuild,Build27`，但未纳入重生阿巴瑟主链，先作为候选/待确认 |
| `PrimalTownHall` / `PrimalHive` | 原始虫群入口，不进默认重生阿巴瑟经济链 |
| `AshWorm2` | 特殊召唤/候选，不进默认工蜂建造 |
| `MercCompound`、`EngineeringBay`、`Bunker`、`Armory` | 混入的人族/佣兵建筑，不进重生阿巴瑟工蜂正向菜单 |
| `InfestedBarracks2` | 感染人族建筑候选，不进默认重生阿巴瑟建筑 |

### 工蜂设计

建议接入私有工蜂：

`AbathurRebornDrone`

来源可以继承源 Mod 的 `LeaperDrone` 行为和模型思路，但命令卡必须重做白名单。

原因：

| 观察 | 风险 |
|---|---|
| `LeaperDrone` 源卡面同时挂了 `ZergBuild`、`TerranBuild`、`ProtossBuild` | 直接照搬会把其他种族/其他指挥官建筑带进来 |
| `LeaperDrone` 卡面存在 `NydusNetwork`、`PrimalHive`、`PrimalSunkenColony`、人族建筑 | 会再次出现把负例当正向建筑的问题 |
| `LeaperDrone` 有阿巴瑟编辑器前缀和工蜂特性 | 可作为继承参考，但不能直接作为最终命令卡 |

## 族系槽位模型

重生阿巴瑟的核心不是“多单位同时存在”，而是“多族系选择”。

建议建立 9 个族系槽位：

| 槽位 | Bank key | 默认单位 | 可选变体 | 生产/解锁口径 |
|---|---|---|---|---|
| 跳虫 | `Evolutions/Zergling` | `Zergling` | `HotSRaptor`、`HotSSwarmling`、`Pygalisk`、`ZerglingToxic` | `SpawningPool` 后开启 |
| 毒爆 | `Evolutions/Baneling` | `Baneling` | `HotSHunter`、`HotSSplitterlingBig`、`FrostFiend`、`BileTitan` | `BanelingNest` 后开启 |
| 蟑螂 | `Evolutions/Roach` | `Roach` | `RoachVile`、`RoachCorpser`、`Igniter`、`Ravager` | `RoachWarren` 后开启 |
| 刺蛇 | `Evolutions/Hydralisk` | `Hydralisk` | `HydraliskLurker`、`HydraliskImpaler`、`HunterKiller`、`Hydralisk2` | `HydraliskDen` 后开启 |
| 飞龙 | `Evolutions/Mutalisk` | `Mutalisk` | `MutaliskChar`、`Mamba`、`MutaliskAnkylos`、`Mesmer` | `Spire` 后开启 |
| 宿主 | `Evolutions/Swarm Host` | `SwarmHost` | `SwarmHostSplitA`、`SwarmHostSplitB`、`BaneHost`、`VespidHost` | `InfestationPit` 后开启 |
| 雷兽 | `Evolutions/Ultralisk` | `Ultralisk` | `HotSTorrasque`、`HotSNoxious`、`UltraliskSavage`、`UltraliskKaldir` | `UltraliskCavern` 和高科技后开启 |
| 巨型飞行 | `Evolutions/Monstrous Flier` | `BroodLord` | `IzshaGuardian`、`Devourer`、`Kraken` | `GreaterSpire` 后开启，且建议限量 |
| 施法者 | `Evolutions/Caster` | `Infestor` | `Viper`、`DefilerMP` | `InfestationPit` 后开启 |

同一槽位同一时间只能有一个正向生产结果。

例如蟑螂槽位选择 `Ravager` 时：

| 内容 | 处理 |
|---|---|
| 可生产单位 | `Ravager` |
| 不显示/不放开 | `Roach`、`RoachVile`、`RoachCorpser`、`Igniter` |
| 必须闭包 | `RavagerCorrosiveBile`、`BurrowRavagerDown/Up`、按钮、效果、Actor 事件 |
| 不可混用 | 官方 `RavagerAbathur*`、德哈卡 `PrimalRavager*` |

## 基础形态 + 进化树

这个方向是更推荐的实现模型。

不是让同族的所有变体并排当独立量产单位，而是每个族系只保留一个基础形态，再从基础形态分支出不同进化结果。

| 结构 | 设计 |
|---|---|
| 1 个基础形态 | 每个族系只有一个基础可造单位 |
| 多个进化分支 | 基础形态在建造后，或通过专用进化面板，分支成不同变体 |
| 当前只保留 1 个分支 | 任一时刻只允许一个进化结果进入正向生产链 |
| 其他分支隐藏 | 不显示或不可点 |

这比“同族多个独立按钮”更像真正的进化虫群，也更容易控制面板密度。

### 进化入口建议

| 入口 | 作用 |
|---|---|
| 基础单位卡面 | 提供唯一的“基础训练”按钮 |
| 进化建筑 | 选择并锁定该族系的分支 |
| 单位自身 | 允许已造基础单位升级成已选分支 |

### 生产口径

首版建议采用“只生产基础形态”的方式。

| 阶段 | 生产表现 |
|---|---|
| 未选择分支 | 幼虫生产基础形态 |
| 已选择分支 | 幼虫仍生产基础形态，基础单位获得对应进化按钮 |
| 单位进化后 | 基础单位变为当前分支结果 |
| 后续优化 | 可以让新生产的基础单位自动进化为当前分支，但这属于 QoL，不是首版必需 |

这样做可以把幼虫命令卡压缩到每个族系一个按钮。

如果后续希望减少玩家操作，可以做“全局选择后新单位自动进化”，但内部仍应保持同一个模型：

| 内部模型 | 外部表现 |
|---|---|
| 基础形态是唯一生产入口 | 玩家看起来像直接获得选中分支 |
| 当前选择只允许一个分支 | 不会出现同族多变体同时可造 |
| 分支技能按单位闭包挂载 | 不会出现按钮空转 |

这样做的好处是：

| 好处 | 说明 |
|---|---|
| 面板干净 | 幼虫上只剩一个基础入口 |
| 语义清晰 | 玩家先造基础，再决定分支 |
| 闭包更稳 | 技能和升级只需围绕一个基础形态扩展 |
| 容易调试 | 看见基础单位就知道问题在分支，不会在一堆同名按钮里找 |

### 不建议这么做的部分

| 对象 | 说明 |
|---|---|
| `Brutalisk`、`Omegalisk`、`Blightbringer`、`Leviathan` | 更适合做终局单位，不适合再做常规基础形态 |
| `Monstrous Flier` | 可以保留一个基础飞行入口，但不建议把四个大飞行单位都变成常规量产分支 |

## 如何做到只开放一个

不能只靠“面板上少放按钮”。真正的实现要做 4 层保险：

| 层级 | 作用 | 失败后果 |
|---|---|---|
| 选择状态 | 每个族系只有一个当前选择值 | 不知道该开放哪个单位 |
| 单位白名单 | 同族候选先全部禁用，再只启用选中单位 | 按钮隐藏了但单位仍可通过其他入口生产 |
| 按钮/需求 | 未选单位的按钮不显示或不可用 | 面板上出现可点但不该出现的按钮 |
| 能力闭包 | 选中单位的技能、变形、购买升级同步开放 | 单位能造但技能不能用或无效果 |

### 状态层

每个族系只存一个值。

| 族系 | 状态 key | 示例值 |
|---|---|---|
| 蟑螂 | `Evolutions/Roach` | `Vile`、`Corpser`、`Igniter`、`Ravager` |
| 刺蛇 | `Evolutions/Hydralisk` | `Lurker`、`Impaler`、`Hunter-Killer`、`Toxic` |
| 巨型飞行 | `Evolutions/Monstrous Flier` | `Brood Lord`、`Guardian`、`Devourer`、`Kraken` |

一个 key 只能写一个字符串，所以状态源天然就是“单选”。

### 白名单层

每次刷新重生阿巴瑟科技树时，按固定顺序执行：

| 顺序 | 动作 |
|---|---|
| 1 | 读取当前玩家的族系选择 |
| 2 | 把该族系所有候选单位先设为不可用 |
| 3 | 按当前选择只设一个单位为可用 |
| 4 | 如果是变形路径，同步开放必要变形能力和中间建筑 |
| 5 | 刷新相关命令卡或需求状态 |

蟑螂族系伪代码：

```galaxy
// 重生阿巴瑟运行时刷新，不是官方等级入口。
void XMAbathurRebornApplyRoachEvolution(int player) {
    string selected;

    TechTreeUnitAllow(player, "Roach", false);
    TechTreeUnitAllow(player, "RoachVile", false);
    TechTreeUnitAllow(player, "RoachCorpser", false);
    TechTreeUnitAllow(player, "Igniter", false);
    TechTreeUnitAllow(player, "Ravager", false);

    selected = BankValueGetAsString(BankLastCreated(), "Evolutions", "Roach");

    if (selected == "Ravager") {
        TechTreeUnitAllow(player, "Ravager", true);
        // 同步开放 Ravager 本地技能闭包。
        XMAbathurRebornEnableRavagerClosure(player, true);
    }
    else if (selected == "Vile") {
        TechTreeUnitAllow(player, "RoachVile", true);
    }
    else if (selected == "Corpser") {
        TechTreeUnitAllow(player, "RoachCorpser", true);
    }
    else if (selected == "Igniter") {
        TechTreeUnitAllow(player, "Igniter", true);
    }
    else {
        TechTreeUnitAllow(player, "Roach", true);
    }
}
```

源 Mod 的 `UnitUnlocks` 触发器已经使用了类似思路：先禁用 `Roach/RoachVile/RoachCorpser/Igniter/Ravager`，再按 `Evolutions/Roach` 只放开一个。XM 接入时应保留这个“先关全族，再开一个”的思想，但要换成重生阿巴瑟自己的私有单位和模块化函数。

### 按钮层

按钮层建议二选一：

| 方案 | 说明 | 推荐度 |
|---|---|---|
| 单槽动态按钮 | 同一族系只保留一个按钮，运行时改按钮、单位和提示 | 后续最干净 |
| 多候选按钮加需求 | 每个候选按钮都存在，但只有选中的 Requirement 成立 | 首版更容易落地 |

首版更稳的是“多候选按钮加需求”，因为数据层改动少。

例如蟑螂族系：

| 按钮 | 显示条件 |
|---|---|
| `Roach` | `Evolutions/Roach` 为空或默认 |
| `RoachVile` | 当前选择为 `Vile` |
| `RoachCorpser` | 当前选择为 `Corpser` |
| `Igniter` | 当前选择为 `Igniter` |
| `Ravager` | 当前选择为 `Ravager` |

按钮即使因为数据错误露出来，也还要被单位白名单和 Use Requirement 拦住。

### 能力闭包层

选中单位后，不只是开放单位本身，还要开放它的相关命令：

| 选择 | 同步内容 |
|---|---|
| `Ravager` | 胆汁技能、Burrow、按钮、效果链、Actor 事件 |
| `HydraliskLurker` | 潜伏者变形、Burrow、潜地攻击、Lurker Den 需求 |
| `HydraliskImpaler` | 穿刺者变形、Impaler Den 需求、穿刺技能/武器 |
| `DefilerMP` | Dark Swarm、Plague、Consume、Burrow |
| `Viper` | 飞蛇技能和能量链 |

这层是防止“能生产但是技能空转”的关键。

### 切换时怎么处理旧单位

首版建议不允许局内反复切换，或者选择后锁定。

如果后续允许切换，应采用下面规则：

| 对象 | 处理 |
|---|---|
| 已生产旧单位 | 保留，不强制替换，避免玩家损失和脚本复杂度 |
| 新生产单位 | 立即按新选择生产 |
| 旧单位购买升级 | 只保留在旧单位身上，不影响新选择单位 |
| 新选择单位升级 | 重新按新单位显示购买按钮 |
| 面板 | 切换后立即刷新，旧候选按钮隐藏 |

这样可以避免“切换进化后全图单位被强行替换”导致引用、选择框、AI、技能冷却和死亡事件混乱。

## 推荐首版可建造池

首版不要追求全变体可切换。建议先做一个稳定默认池，再逐个放开选择。

| 槽位 | 首版默认 | 理由 |
|---|---|---|
| 工蜂 | `AbathurRebornDrone` | 先解决建筑白名单和经济闭包 |
| 跳虫 | `HotSRaptor` 或 `Zergling` | 早期近战量产，不压技能闭包 |
| 毒爆 | `HotSHunter` 或 `Baneling` | 早期爆发单位，按钮和需求简单 |
| 蟑螂 | `RoachVile` | 稳定地面中坚；`Ravager` 作为优先测试分支 |
| 刺蛇 | `HunterKiller` 或 `Hydralisk` | 稳定远程输出 |
| 飞龙 | `MutaliskChar` 或 `Mutalisk` | 中期空军主链 |
| 宿主 | `SwarmHostSplitA` 或 `SwarmHost` | 阵地战特色 |
| 雷兽 | `HotSTorrasque` 或 `Ultralisk` | 后期地面肉盾 |
| 巨型飞行 | `Devourer` 或 `BroodLord` | 只开放一个，避免空军后期面板膨胀 |
| 施法者 | `Infestor` | 默认施法者，技能闭包较容易先核 |

`Ravager` 不建议在技能闭包验证前作为默认主链，但必须作为第一批重点验证分支，因为用户明确担心破坏者技能“按钮能点但不生效”。

## 进化选择设计

### 选择方式

建议在主巢/虫穴/虫巢或专用建筑上提供“进化选择”子菜单。

| 操作 | 结果 |
|---|---|
| 选择某族系变体 | 写入本局或 Bank 对应族系选择值 |
| 切换变体 | 刷新生产白名单和命令卡 |
| 未选择 | 使用默认单位 |
| 已生产旧变体后切换 | 新生产走新变体，旧单位是否保留由平衡规则决定 |

### 是否允许局内切换

建议分两阶段：

| 阶段 | 规则 |
|---|---|
| 首版 | 开局或第一次选择后锁定，降低测试和同步复杂度 |
| 后续 | 允许花资源/冷却重选，但需要处理旧单位、升级和按钮刷新 |

### 面板规则

| 规则 | 说明 |
|---|---|
| 幼虫只显示当前变体 | 避免同格按钮重叠和误点 |
| 进化菜单显示候选 | 让玩家知道可选方向 |
| 未满足科技可预览但不可选择 | 选择按钮可以灰显，生产按钮不要提前出现 |
| 选择后有明确反馈 | 文本提示当前族系选择，例如“蟑螂进化：破坏者” |

## 巨型和实验单位设计

这些单位不能走普通幼虫量产：

| 单位 | 源线索 | 设计处理 |
|---|---|---|
| `Brutalisk` | `LarvaTrainSwarm2,Train29`、实验体按钮、购买升级 | 终局地面巨兽，建议限量 1 到 3 |
| `Omegalisk` | `LarvaTrainSwarm2,Train28`、专属购买升级 | 终局攻城巨兽，建议限量 1 |
| `Blightbringer` | `LarvaTrainSwarm2,Train27`、有造蛋技能 | 实验/召唤型单位，先候选，验证后再定是否进终局 |
| `Leviathan` | `LarvaTrainSwarm2,Train30`，也出现在凯瑞甘 Unity 链 | 不默认作为重生阿巴瑟英雄或量产单位；只能作为巨型飞行终局候选 |
| `Kraken` | 巨型飞行族系候选 | 可以作为 `Monstrous Flier` 的一个选择，但不和 `BroodLord/Guardian/Devourer` 同时开放 |

### 限制方式

可选限制手段：

| 手段 | 适用 |
|---|---|
| 单位上限 | `Brutalisk`、`Omegalisk`、`Leviathan` |
| 长冷却 | 终局召唤和实验体 |
| 高资源成本 | 巨型飞行和实验单位 |
| 生物质/精华阈值 | 如果 XM runtime 已有对应资源或可安全实现 |
| 只能选一个终局槽 | 在 `Brutalisk/Omegalisk/Blightbringer/Leviathan` 之间做取舍 |

首版建议只开放一个终局槽，且默认关闭 `Leviathan`。

## 技能和购买升级接入规则

不能只让单位出现在生产菜单里。

每个正向单位必须有一张闭包清单：

| 闭包项 | 必须检查 |
|---|---|
| Unit | 私有单位 ID 或明确继承源单位 |
| Actor/Model | 出生、死亡、攻击、施法事件不丢 |
| Button | 生产按钮、技能按钮、购买按钮 |
| Ability | 训练、技能、变形、Burrow、购买能力 |
| Effect | 伤害、搜索、行为应用、Set/Persistent |
| Behavior | Buff、被动、升级后行为 |
| Requirement | 显示、使用、已购买隐藏 |
| Validator | 自动施法、目标过滤、技能有效性 |
| Upgrade | 全局升级或单位购买升级 |
| Text | 中文名、提示、需求提示 |

### 破坏者优先闭包

`Ravager` 是重点风险项。

| 链路 | 必须接 |
|---|---|
| 单位 | `Ravager` 或私有派生 `AbathurRebornRavager` |
| 生产 | 蟑螂槽位选择 `Ravager` 后才开放 |
| 按钮 | `MorphtoRavager`、`RavagerCorrosiveBile` |
| 技能 | `RavagerCorrosiveBile` |
| 效果 | `RavagerCorrosiveBileSearch` 及后续伤害/搜索链 |
| 埋地 | `BurrowRavagerDown/Up` 对应本地链 |
| 不接 | 官方 `RavagerAbathurCorrosiveBile`、德哈卡 `PrimalRavager` |

验收标准：能生产，能看到技能，能对合法目标施放，能产生效果，冷却/费用/目标过滤正常。

### 单位购买升级

源 Mod 中大量按钮是“单位购买升级”，不是新单位。

接入原则：

| 规则 | 说明 |
|---|---|
| 只给当前正向单位 | 未选择的变体不显示它的购买升级 |
| 买完后隐藏或显示已拥有 | 依赖 Requirement/Behavior，不能重复购买导致堆叠失控 |
| 费用和效果一起接 | 只接按钮会导致花费或效果异常 |
| 同族升级不外溢 | 例如蟑螂升级不能错误作用到其他指挥官蟑螂 |

## 幼虫命令卡设计

源 Mod 的幼虫命令卡同格塞了大量按钮。XM 接入时不要照搬。

建议幼虫最终只保留这些“槽位按钮”：

| 行列建议 | 槽位 |
|---|---|
| 第 0 行 | 工蜂、领主、跳虫、毒爆 |
| 第 1 行 | 蟑螂、刺蛇、飞龙、宿主 |
| 第 2 行 | 雷兽、施法者、巨型飞行、终局槽 |

每个按钮背后的实际单位由当前选择决定。

如果 SC2 数据层不方便动态替换按钮，首版可采用“每个候选按钮都有独立 Requirement”的方式，但同一槽位仍必须保证只有一个按钮可见。

## 与当前 XM 接入的关系

优先把重生阿巴瑟自己的数据和规则放在：

`合作指挥官版起义狂潮/Mods/XM/XMAbathurReborn.SC2Mod`

| 层级 | 建议 |
|---|---|

## 需要避免的错误实现

| 错误做法 | 后果 |
|---|---|
| 把 `LarvaTrainSwarm2` 全部 Train 项塞进幼虫 | 面板爆炸、同格按钮冲突、平衡失控 |
| 只接按钮不接效果 | 技能可点但无效果 |
| 直接改共享 `Ravager`、`Roach`、`Hydralisk` | 其他指挥官或源单位被污染 |
| 把 `NydusNetwork` 当重生阿巴瑟建筑 | 重复之前的坑道误纳问题 |
| 把 `Leviathan` 写成默认英雄 | 它同时出现在其他链路，归属会混乱 |
| 把 `Naktul` 训练链并入阿巴瑟 | 这是另一个 commander/英雄链 |
| 把源 Mod 工蜂卡面照搬 | 会带入原始虫群、人族、坑道和其他候选建筑 |

## 最终口径

重生阿巴瑟的兵种融入方案应是：

1. 工蜂建筑白名单。
2. 每个虫群族系一个当前主变体。
3. 进化菜单负责选择方向，不负责同时开放所有单位。
4. 巨型单位走终局槽和限制机制。
5. 技能、购买升级、效果链必须和单位一起闭包。
6. `NydusNetwork`、`Naktul`、跨链 `Leviathan` 等对象默认隔离。

一句话概括：重生阿巴瑟不是全虫群单位展示柜，而是“每个生物族系选择一种进化方向”的模块化虫群指挥官。
