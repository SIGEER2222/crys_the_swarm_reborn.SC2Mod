# 指挥官兵种

日期：2026-05-27

## 职责边界

本模块负责每个 commander 的可用兵种清单、兵种阶段、最终强度融合 roster、训练来源和测试台生成清单。

它不直接定义每个技能闭包，也不直接定义科技建筑按钮，但要引用对应 profile。

## 三阶段 roster

必须区分：

| Stage | 含义 |
|---|---|
| `initial` | 官方基础状态审计清单，只用于对照和排错 |
| `level15` | 当前满级对照状态，全解锁后 |
| `power_fusion` | 满级 + 精通全满 + 威望正面融合后 |

测试台默认 `full_units` 应等价于 `power_fusion`。`initial_units` 只是审计入口，不是当前默认玩法清单。

## 测试台验证

测试场景：

```text
initial_units
level15_units
fusion_final_units
full_units
```

验证项：

1. 三阶段清单能读取。
2. `level15` 相比 `initial` 的新增/替换有记录。
3. `power_fusion` 相比 `level15` 的威望/精通变化有记录。
4. 单位能创建，模型和 Actor 正常。
5. 预期武器、行为、核心技能存在。
6. 被替换单位不会误进入最终清单。

## 剩余风险

- 不同来源里的单位名可能不同，必须用官方提取数据和 CASC 闭包确认。
- 有些“兵种”实际是英雄、召唤物、面板召唤单位，需要标记 owner。
- 满级清单和威望融合清单不能混为一谈。
