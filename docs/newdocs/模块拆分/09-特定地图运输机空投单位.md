# 特定地图运输机空投单位

日期：2026-05-27

## 职责边界

本模块负责特定地图中的运输机、货舱、空投单位、救援单位和地图场景小队。

地图只描述场景，例如 `cargo_light`、`cargo_heavy`、`cargo_air`，不直接写每个 commander 的货舱单位。

本模块不是从官方合作文本或 `command_cards.json` 直接提取的。`command_cards.json` 只能说明某个单位或面板上存在运输、卸载、坑道、空投等按钮，不能证明该地图应该投放哪些单位。

当前应以 `原始mod/` 里已经存在的运输机、空投、货舱、坑道、狮鹫运输和医疗运输机流程作为实现线索；没有现成实现的 commander，再使用 `CommanderCargoLoadoutProfile` 做设计草案。

运输机单位选择应基于 commander 的最终 roster。当前 commander 默认 15 级，强度融合默认使用 `power_fusion` 阶段；如果地图剧情要求弱化单位，要显式声明专用场景或审计用 `LevelStage = initial`，不能把 `initial` 当作默认状态。

## Loadout 设计规则

1. 优先保留 `原始mod` 的流程语义，例如运输机单位、到达点、卸载方式、返航/消失、货舱死亡规则、视觉演员和音效。
2. 把地图里硬编码的单位 ID 替换为 `CommanderCargoLoadoutProfile` 查询结果。
3. `commanders/<Commander>/units.json`、`roster.json` 只用于确认单位可用性和满级最终形态，不直接等同于“全部可投放”。
4. 英雄、首领、终极进化、航母、战列巡航舰等高价值单位默认只能进入 `bonus_reward` 或显式允许英雄的地图场景。
5. 没有现成 `原始mod` 流程时，先使用设计草案，并在 profile 中标记 `AuditStatus = design_pending_runtime_test`。

## 运行时入口

```galaxy
XM_CreateCommanderCargoSquad(container, commander, scenarioKind)
XM_CreateCommanderMapDrop(player, commander, mapId, scenarioKind, point)
XM_CreateCommanderScenarioSquad(player, commander, scenarioKind, point)
XM_ResolveCommanderCargoLoadout(commander, mapId, scenarioKind)
```

建议运行时流程：

1. 地图触发器只传 `mapId`、`scenarioKind`、目标点和运输模式。
2. `CommanderMapDropProfile` 判断当前地图是否有原始流程模板，例如 `SpecOpsDropshipTransport`、`NovaGriffinTransport`、`TychusMedicTransport`。
3. `CommanderCargoLoadoutProfile` 按 commander 和 `scenarioKind` 返回单位清单。
4. `CommanderScenarioFallbackProfile` 在缺少专用 loadout 时降级，例如 `cargo_air -> cargo_heavy -> cargo_light`。
5. 创建货舱/空投单位后输出 `[XM_DBG]`，记录 commander、mapId、scenarioKind、unit、count、transportUnit、ability、fallback。

## 剩余风险

- 运输机地图常有剧情专用限制，不能只按通用 roster 判断。
- 同一个 commander 在不同地图可能需要不同 loadout。
- 货舱单位如果使用满级最终形态，可能破坏剧情难度；需要由场景显式决定。
- 现阶段指挥官细化文档里的 loadout 是设计草案；其中部分单位名仍需在落代码前用 `游戏数据/官方合作指挥官/commanders/<Commander>/` 和 CASC Catalog ID 做二次校验。
