# 指挥官个性化机制

日期：2026-05-27

## 职责边界

本模块负责各 commander 独有但不一定构成完整特殊资源系统的个性化机制。

例子：

- 雷诺星轨、矿骡。
- 思旺建筑灭火。
- 阿塔尼斯守护之壳。
- 凯拉克斯建筑自动维修。
- 其它 commander 的局部被动、全局增益、单位自动行为。

这些机制通常横跨单位、建筑、面板、触发器和升级，不能塞进单个科技建筑或地图。

## 处理原则

1. 能静态表达的行为优先 Catalog。
2. 需要全局事件、计时器、玩家状态的行为进入 runtime hook。
3. 精通和威望修正通过强度融合层进入，不让机制自己读 Bank 或启用官方 `PlayerPrestige`。
4. 机制必须说明 owner，避免分散到地图、建筑、单位三处。

## 示例口径

| 机制 | Owner | 注意点 |
|---|---|---|
| 雷诺矿骡 | personal mechanic + panel/building link | 威望 P1 跳过禁用矿骡，不能误锁按钮 |
| 雷诺星轨/空军面板联动 | personal mechanic + panel modifier | P3 空军人口加速顶部技能充能需要 runtime 或 panel modifier |
| 思旺建筑灭火 | building passive / runtime hook | 受影响建筑、触发条件、治疗或灭火效果要声明 |
| 阿塔尼斯守护之壳 | death prevention | 冷却、目标过滤、威望/精通修正要审计 |
| 凯拉克斯建筑自动维修 | building passive | 维修范围、目标类型、消耗和频率要验证 |

## 测试台验证

测试场景：

```text
personal_mechanic_smoke
building_passive_smoke
death_prevention_smoke
panel_link_smoke
```

验证项：

1. 机制 profile 能读取。
2. 相关对象存在。
3. 触发条件能被模拟。
4. 效果能生效。
5. 精通和威望修正进入最终值。
6. 被跳过的威望负面不会残留。

## 剩余风险

- 个性化机制最容易被误放进地图或建筑本地逻辑。
- 很多机制依赖事件触发，静态存在不等于运行正确。
- 同一个机制可能同时受等级、精通、威望影响，必须走强度融合排序。
