# 英雄单位及其技能

日期：2026-05-27

## 职责边界

英雄模块负责指挥官专属英雄单位、英雄形态、英雄技能、英雄复活、英雄等级和英雄技能树。

典型对象：

- 凯瑞甘。
- 诺娃及其形态。
- 德哈卡。
- 泰凯斯及亡命徒。
- 泽拉图。
- 阿拉纳克。
- 菲尼克斯及冠军体系。

它不负责顶部技能栏，也不负责普通兵种的研究按钮。

## 运行时入口

```galaxy
XM_InitCommanderHero(player, commander)
XM_SetCommanderHeroMode(player, commander, heroMode)
XM_ApplyCommanderHeroLevel(player, commander)
XM_ApplyCommanderHeroModifiers(player, commander)
XM_ReviveCommanderHero(player, commander)
```

英雄技能本体尽量保留 Catalog 机制。只有形态切换、复活、等级同步、精通/威望运行时补偿这类动态行为进入 hook。

## 诺娃形态口径

诺娃形态不能当作简单换模型。形态会影响：

- 攻击方式。
- 武器。
- 行为。
- 命令卡。
- 可用技能。
- 生产建筑和装备体系。
- 威望正面与负面拆分。

因此诺娃必须同时进入：

```text
CommanderHeroProfile
CommanderHeroModeProfile
CommanderHeroAbilityProfile
CommanderPrestigeEffectProfile
CommanderRosterProfile
```

## 测试台验证

测试场景：

```text
hero_modes
hero_abilities
power_fusion_hero
```

验证项：

1. 英雄能按 commander 创建。
2. 英雄命令卡按钮完整。
3. 主动技能能释放，冷却和资源消耗正确。
4. 被动行为、武器、护甲、检测等属性符合最终状态。
5. 形态切换后攻击方式、技能和行为切换成功。
6. 复活或重建后状态不丢失。
7. 精通和威望对英雄技能的修正已应用。

## 剩余风险

- 英雄能力经常跨 Unit、Abil、Effect、Behavior、Actor、Sound、Requirement，多文件闭包必须完整。
- 同局测试只能验证闭包和状态切换，不能完全证明剧情地图里的复活/任务语义。
- 英雄威望可能同时修改面板、英雄和兵种，不能只在英雄模块内处理。
