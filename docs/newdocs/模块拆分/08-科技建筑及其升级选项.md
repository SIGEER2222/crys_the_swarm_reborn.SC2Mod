# 科技建筑及其升级选项

日期：2026-05-27

## 职责边界

本模块负责科技建筑承载哪些升级按钮、研究能力、需求条件、升级效果和被影响对象。

科技建筑只做承载容器，不应该自己判断每个 commander 的所有兵种规则。

## 建议 Profile

```text
CommanderUnitTechProfile
```


## 升级分类

```text
attack
armor
shield
unit_unique
hero_unique
building_unique
panel_modifier
special_mechanic
```

攻防升级和专属科技要分开声明，避免科技建筑把所有规则都写死。

## 生成方式

科技链大多是静态 Catalog，建议由工具生成或校验：

```text
AbilData.xml
ButtonData.xml
RequirementData.xml
UpgradeData.xml
UnitData.xml
GameStrings.txt
```

运行时只负责应用强度融合、验证升级状态和处理无法静态表达的 hook。

## 测试台验证

测试场景：

```text
tech_smoke
tech_attack
tech_armor
tech_unique
```

验证项：

1. 科技建筑存在。
2. 研究按钮存在。
3. Requirement 正确。
4. 研究能力能执行。
5. Upgrade 能加到玩家。
6. 目标单位、武器、技能、行为受到影响。
7. 精通和威望对费用/时间/效果的最终修正正确。

## 剩余风险

- Requirement 断链会导致按钮显示但不可点。
- Upgrade 生效对象可能不是 tooltip 写的对象。
- 威望跳过负面费用时，不能让科技建筑自己做 commander 分支。
