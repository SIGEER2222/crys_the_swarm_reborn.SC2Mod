# 雷诺精通、威望、加点融合设计

日期：2026-05-27

## 结论

雷诺先按“强度融合版”设计：等级加点默认视为 15 级全解锁，精通点默认 6 项全部满点，三个威望只取正面效果，不保留负面限制。

这里需要先统一术语：

- 官方合作模式的“有优缺点的三选一”是 `威望` / `Prestige`，不是精通点。
- 官方雷诺的精通点是 3 组 6 项，正常玩法每组二选一分配点数。
- 本 mod 的目标是战役爽度和测试效率，所以雷诺试点采用 `AllPositiveFusion`：不做二选一，也不保留官方为了平衡设计的代价。

## 数据来源

本设计以当前仓库内的官方提取数据和官方 CASC 导出为准。`合作指挥官版起义狂潮` 目录里的文件目前只能作为半成品实现参考，不能作为威望/精通取舍和最终数值的依据。

| 类型 | 路径 | 用途 |
|---|---|---|
| 官方提取数据 | `游戏数据/官方合作指挥官/commanders/Raynor/commander.json` | 雷诺默认升级、默认能力命令、威望 id |
| 官方提取数据 | `游戏数据/官方合作指挥官/commanders/Raynor/progression.json` | 1-15 等级加点、6 项精通点 |
| 官方提取数据 | `游戏数据/官方合作指挥官/commanders/Raynor/prestiges.json` | 三个威望的主升级、禁用能力、supplement、suppress |
| 官方 CASC 导出 | `references/sc2-build-96883-casc-export` | 追官方 Catalog、UserData、本地化和效果闭包 |

注意：`docs/指挥官威望/雷诺.md` 可作为中文阅读材料，但其中等级 14/15 的顺序和官方提取数据不一致。本设计以 `progression.json` 为准：14 级是休伯利安号高级瞄准系统，15 级是佣兵军火。

## 目标模型

建议新增一个独立 profile，不要把融合规则塞回官方 `PlayerPrestige`。

建议名：

```text
CommanderPowerFusionProfile
RaynorAllPositiveFusion
```

核心字段：

```text
Commander = Raynor
LevelMode = FullLevel15
MasteryMode = AllSixMax
PrestigeMode = AllPositive
ApplyOrder = BaseCommander -> LevelUnlocks -> Masteries -> PositivePrestige -> Compensation -> Verify
DebugTag = RAYNOR_FUSION
```

运行时入口建议后续放在统一 runtime owner 中，下面以函数名表达职责，不绑定当前半成品目录里的具体实现：

```galaxy
XM_ApplyCommanderPowerFusion(player, commander)
XM_ApplyCommanderFullLevel(player, commander)
XM_ApplyCommanderAllMasteries(player, commander)
XM_ApplyCommanderPositivePrestige(player, commander)
XM_VerifyCommanderPowerFusion(player, commander)
```

地图和测试台只调用统一入口，不判断雷诺内部细节。

## 精通点设计

雷诺融合版不做每组二选一，6 项全部按 30 点满点生效。

| 组别 | 官方精通 | 当前升级 ID | 满点效果 | 融合版处理 |
|---|---|---|---|---|
| 第 1 组 | 资源费用 | `MasteryRaynorResearchCost` | 研究资源费用 -60% | 生效 |
| 第 1 组 | 空投舱急速 | `MasteryRaynorDropPodHaste` | 空投舱单位急速 +60% | 生效 |
| 第 2 组 | 休伯利安号冷却 | `MasteryRaynorHyperionCooldown` | 冷却 -120 秒 | 生效 |
| 第 2 组 | 女妖冷却 | `MasteryRaynorDuskWingCooldown` | 冷却 -120 秒 | 生效 |
| 第 3 组 | 医疗兵额外目标治疗 | `MasteryRaynorMedicSecondaryHeal` | 额外目标治疗 +90% 基础治疗 | 生效 |
| 第 3 组 | 机械部队攻击速度 | `MasteryRaynorMechAttackSpeed` | 机械部队攻击速度 +30% | 生效 |

推荐实现：

```galaxy
TechTreeUpgradeAddLevel(player, "MasteryRaynorResearchCost", 30);
TechTreeUpgradeAddLevel(player, "MasteryRaynorDropPodHaste", 30);
TechTreeUpgradeAddLevel(player, "MasteryRaynorHyperionCooldown", 30);
TechTreeUpgradeAddLevel(player, "MasteryRaynorDuskWingCooldown", 30);
TechTreeUpgradeAddLevel(player, "MasteryRaynorMedicSecondaryHeal", 30);
TechTreeUpgradeAddLevel(player, "MasteryRaynorMechAttackSpeed", 30);
```

不要依赖玩家 Bank 里的 0-5 号加点值。融合版应该可控、可测试、可复现，不应要求人工改进度 Bank。

风险点：`MasteryRaynorResearchCost` 在官方数据里属于可能依赖触发器或额外费用修正的精通。仅加这个升级等级可能只让 tooltip 显示，不一定真的降低研究费用。第一版必须从官方 CASC 追完整闭包，并在测试台里实测研究费用。

## 威望融合设计

### 不直接使用官方三选一

不要直接把 `PlayerPrestige` 三个实例全部启用。原因：

- `CommanderPrestigeRaynorBio` 的 `PlayerPrestige` 会禁用 `CalldownMULE`。
- `CommanderPrestigeRaynorMechAfterburners` 的 `PlayerPrestige` 会 suppress `RaynorCommanderMechCostReduction`。
- `CommanderPrestigeRaynorMechAfterburners` 的升级本体还包含推进器移速削弱和生命消耗。
- `CommanderPrestigeRaynorAir` 的升级本体同时包含空军气耗降低和全作战单位晶矿费用增加。

融合版必须把“正面效果”和“负面效果”分离。

### 威望 1：死水元帅

取：

- 生化部队基础生命值提升。
- 战斗盾牌、火蝠装甲、步兵护甲研究的补充生命值升级。

不取：

- 禁用矿骡。
- 指挥中心命令卡上的矿骡锁定按钮。

建议实现：

```text
RaynorFusionPrestigeBioPositive
  copy positive LifeMax/LifeStart effects from CommanderPrestigeRaynorBio

RaynorFusionPrestigeBioSupplements
  grant or supplement:
    CommanderPrestigeRaynorBioMarineUpgrade
    CommanderPrestigeRaynorBioFirebatUpgrade
    CommanderPrestigeRaynorBioUpgradeTerranInfantryArmorLevel1
    CommanderPrestigeRaynorBioUpgradeTerranInfantryArmorLevel2
    CommanderPrestigeRaynorBioUpgradeTerranInfantryArmorLevel3
```

矿骡必须保持可用：

```text
CalldownMULE remains enabled
CommanderPrestigeRaynorMULELocked is not shown in fusion path
```

### 威望 2：狂暴骑手

取：

- 推进器使机械单位攻击速度 +100%。
- 推进器冷却减少 50%。
- 推进器生命消耗。
- 机械单位气耗 -20% 的 1 级天赋失效。

不取：
- 推进器移动速度加成减少 50%。

建议实现：

```text
RaynorFusionPrestigeMechAfterburnersPositive
  EffectArray Reference="Behavior,VehicleAfterburners,Modification.AttackSpeedMultiplier" Value="1"
  EffectArray Operation="Subtract" Reference="Abil,VehicleAfterburners,Cost[0].Cooldown.TimeUse" Value="30.000000"
  EffectArray Reference="Abil,VehicleAfterburners,Cost[0].Vital[Life]" Value="10"
  SuppressUpgrade RaynorCommanderMechCostReduction
```

不要复制这些负面项：

```text
Operation="Subtract" Reference="Behavior,VehicleAfterburners,Modification.MoveSpeedMultiplier" Value="0.5"
```

测试目标：推进器保留原本移速收益并新增攻速收益；推进器生命消耗存在；机械单位气耗减免被威望 2 取舍主动关闭。

### 威望 3：起义军游骑兵

取：

- 星港不再需要兵营/重工厂前置。
- 星港单位气耗 -30%。
- 维京、女妖、战列巡航舰按人口提高顶部面板技能充能速率。

不取：

- 军械库和轨道基地相关前置放宽。
- 星港建造不需要气体。
- 所有作战单位晶体矿费用 +50%。

实现注意：

- 官方威望 3 同时包含正面和负面效果，不能直接启用完整 `PlayerPrestige`。
- 星港前置放宽、空军气耗降低、空军人口加速面板技能三件事要分别建 profile 字段，避免误带军械库/轨道基地前置和星港免气。
- 面板充能加速可能依赖触发器或 caster 状态，必须从官方 CASC 追完整闭包，不能只看单个升级 id。

推荐实现有两个方案。

方案 A：干净方案，适合长期维护。

```text
RaynorFusionPrestigeAirPositive
  Enable trigger add/remove chance
  Relax Starport prerequisite only
  Subtract Viking / Banshee / Battlecruiser vespene
  Count Viking/Banshee/Battlecruiser supply for top-bar charge rate
  Do not relax Armory / Orbital Command prerequisite
  Do not reduce Starport building vespene cost
  No mineral cost increase

Requirement bridge:
  CanBuildStarport checks RaynorFusionPrestigeAirPositive

Tooltip bridge:
  add validator for RaynorFusionPrestigeAirPositive

Runtime hook:
  count Viking/Banshee/Battlecruiser supply
  update Hyperion and Banshee charge/cooldown rate
```

方案 B：兼容方案，适合第一版快速验证。

```text
grant CommanderPrestigeRaynorAir
grant RaynorFusionPrestigeAirNoMineralPenalty immediately after it
```

`RaynorFusionPrestigeAirNoMineralPenalty` 抵消这些晶矿增加：

```text
Marine -25 minerals
Medic -38 minerals
Marauder -50 minerals
Firebat -50 minerals
Vulture -38 minerals
SiegeTank -75 minerals
SiegeTankSieged -75 minerals
VikingAssault -75 minerals
VikingFighter -75 minerals
Banshee -75 minerals
Battlecruiser -200 minerals
```

方案 B 的好处是现有 requirement 和 tooltip 不用大改；坏处是依赖升级叠加顺序，后续容易遗漏新的负面项。长期仍建议迁移到方案 A。

## 推荐第一版落地策略

第一版以“可验证、少动地图”为目标：

1. 在 `XMRaynor.SC2Mod` 增加正面融合升级：
   - `RaynorFusionPrestigeBioPositive`
   - `RaynorFusionPrestigeMechAfterburnersPositive`
   - `RaynorFusionPrestigeAirPositive`
   - 必要时增加 `RaynorFusionPrestigeAirNoMineralPenalty`
2. 在 `XMFinal.SC2Mod` 增加 `XM_ApplyCommanderPowerFusion`，在普通 `CommanderAch` 加点之后执行。
3. 默认只对 Raynor 开启，避免一次影响全部指挥官。
4. 精通点不走 Bank，直接由 fusion profile 加 6 项 30 级。
5. 等级加点补齐 15 级，不受当前 8 个 `Upg` 槽位限制。
6. 威望正面效果走独立融合升级，不通过 `PlayerPrestige` 的 disable/suppress。
7. `MasteryRaynorResearchCost` 和 P3 面板充能加速必须做实测，不能只看 tooltip。

建议配置开关：

```text
Debug Bank / XMDev:
  PowerFusionEnabled = 1
  PowerFusionCommander = Raynor
  PowerFusionMode = AllPositive
```

发布版如果希望默认强力，也可以把 Raynor 固定开启；但调试阶段先保留开关，方便和官方行为对比。

## 测试方案

### 静态验证

新增或扩展验证脚本，检查：

| 检查项 | 通过条件 |
|---|---|
| 融合升级存在 | `RaynorFusionPrestige*` 都能在目标 Catalog 找到 |
| 不禁用矿骡 | 融合 profile 不引用 `DisableAbil CalldownMULE` |
| 威望 2 取舍 | 融合 profile 主动关闭 `RaynorCommanderMechCostReduction`，保留推进器生命消耗 |
| 不保留推进器移速负面 | 融合升级不包含 `MoveSpeedMultiplier -0.5` |
| 不保留晶矿惩罚 | 融合最终路径不让作战单位晶矿成本高于基础值 |
| 威望 3 取舍 | 只放宽星港前置，不放宽军械库/轨道基地前置，不让星港建筑免气 |
| 精通满点 | 6 个 `MasteryRaynor*` 都按 30 级应用 |
| 等级全解锁 | 15 级涉及的升级和能力命令都有入口 |
| 研究费用精通 | `MasteryRaynorResearchCost` 有真实 hook 或 catalog patch |
| P3 面板加速 | 空军人口 -> 面板充能/冷却有 runtime 或触发器证据 |

### 测试台验证

在 `CommanderTestBench.SC2Map` 里增加 Raynor 测试按钮：

| 按钮 | 验证点 |
|---|---|
| 应用雷诺融合 | 调用 `XM_ApplyCommanderPowerFusion(1, "Raynor")` |
| 检查等级 | 输出 15 级关键升级状态 |
| 检查精通 | 输出 6 个精通等级和关键数值 |
| 检查威望 | 输出矿骡、机械气耗、推进器、星港前置、星港单位气耗、作战单位晶矿成本 |
| 生成生化 | 生成枪兵、劫掠者、火蝠、医疗兵，检查生命值 |
| 生成机械 | 生成秃鹫车、坦克、维京、女妖、战列，检查推进器和攻击速度 |
| 生成空军人口 | 逐步增加维京/女妖/战列人口，检查面板技能充能变化 |
| 研究全科技 | 自动研究兵营/重工厂/星港/工程站/军械库科技，检查 supplement 是否生效 |

### 实机验收点

最小验收不是“按钮出现”，而是下面这些行为都成立：

1. 进图后雷诺拥有 15 级能力。
2. 6 项精通同时满点。
3. 矿骡仍可用。
4. 机械单位气耗 -20% 被威望 2 取舍主动关闭。
5. 推进器同时有原移速收益和威望 2 攻速收益，且保留生命消耗。
6. 星港可提前建造，但星港建筑本身不免气。
7. 星港单位气耗降低，作战单位晶矿费用不增加。
8. 空军人口能实际加快休伯利安号和女妖空袭。
9. 生化部队生命值提升，护甲/战斗盾牌/火蝠装甲的 supplement 继续追加生命值。
10. 研究费用精通实际降低费用，而不是只显示 tooltip。

## 后续推广规则

雷诺试点通过后，其它指挥官照同一套规则处理：

1. 先从官方提取数据列出等级、精通、威望。
2. 把每个威望拆成 `PositiveEffects`、`NegativeEffects`、`PrereqBridges`、`RuntimeHooks`。
3. 精通点默认 6 项满点，除非某项正面效果会破坏剧情脚本。
4. 等级默认满级全解锁，但剧情特殊限制可以通过场景 profile 临时关闭。
5. 不直接启用官方 `PlayerPrestige` 的 disable/suppress 字段。
6. 所有跳过的负面效果都要有日志，避免后续 AI 误以为漏做。

## 当前未闭环风险

- `MasteryRaynorResearchCost` 需要从官方 CASC 追完整闭包，并补真实降价实现或测试证据。
- P3 面板充能加速需要从官方 CASC 确认触发器、caster 或行为闭包；若没有可复用链路，应在统一 runtime 中自己统计空军人口并调整面板冷却/充能。
- 旧 8 槽 `CommanderAch.Upg` 思路不能当作完整 15 级设计来源。
- 如果采用方案 B 抵消 P3 晶矿惩罚，要特别验证升级叠加顺序；长期建议改成方案 A。
