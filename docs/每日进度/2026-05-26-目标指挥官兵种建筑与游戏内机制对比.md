# 2026-05-26 目标指挥官兵种建筑与游戏内机制对比

## 口径

- 当前环境没有 SC2，只能静态读取 XML/Galaxy/localization，不能进图验证。
- 本文只统计当前约定的 11 个目标指挥官：阿巴瑟、重生阿巴瑟、阿拉纳克、阿塔尼斯、菲尼克斯、凯拉克斯、凯瑞甘、雷诺、沃拉尊、扎加拉、泽拉图。
- `XMFinal.SC2Mod` 是当前运行时 owner；各 `XM*.SC2Mod` 源模块用于反推游戏内真实机制。
- 旧的 `UnitData.xml` 静态表只能说明对象存在，不能说明玩法迁移完成。本文额外检查训练技能、变形技能、升级 patch、攻击效果、行为效果和 `XMFinal` 当前创建单位。
- 中文名优先，括号内保留 XML ID，避免后续替换时丢失可搜索标识。

## 分指挥官明细

### 阿巴瑟（`XMAbathur`）

**静态建筑**：阿巴瑟孵化场（`HatcheryAbathur`）、孵化场、虫穴、主巢、孵化池、进化腔、蟑螂温室、刺蛇兽穴、潜伏者巢穴、尖塔、巨型尖塔、爆蚊巢、毒性巢穴（`ToxicNest` / `ToxicNestBurrowed`）、进化深渊（`EvolutionPit`）、菌毯瘤。

**静态核心兵种/对象**：邪恶蟑螂、刺蛇、女王、破坏者、穿刺者、虫群宿主、爆蚊、暴虐兽、利维坦、生物质、共生体。

**游戏内机制证据**：

- 源模块有 `EvolveToBrutalisk`、`EvolveToLeviathan` 相关变形链。
- 单位身上有生物质显示/拾取/叠层相关行为，如 `AbathurCollectBiomass`、`BiomassBuff*`。
- 源模块单位卡中存在蟑螂/邪恶蟑螂变破坏者、单位进化暴虐兽/利维坦的按钮链。

**当前对比**：`XMFinal` 已覆盖邪恶蟑螂、刺蛇、女王、破坏者、虫群宿主、暴虐兽、利维坦这类主要战斗单位，但轻型仍给普通 `Zergling`。阿巴瑟正常合作指挥官核心不是普通跳虫，而是生物质、终极进化、毒性巢穴。后续不应把“有跳虫对象”当成阿巴瑟完成标准。

### 重生阿巴瑟（`XMAbathurReborn`）

**静态建筑**：重生阿巴瑟孵化场（`HatcheryAbathurReborn`）、孵化场、虫穴、主巢、孵化池、进化腔、蟑螂温室、刺蛇兽穴、潜伏者巢穴、尖塔、巨型尖塔、爆蚊巢、毒性巢穴、进化深渊、菌毯瘤。

**静态核心兵种/对象**：重生生物质、重生共生体、重生熔岩蠕虫、重生蝗虫、重生穿刺者、重生破坏者（`RavagerAbathurReborn`）、重生利维坦相关对象、吞噬者、守护者、虫群宿主。

**游戏内机制证据**：

- 源模块有 `AbathurRebornCollectBiomass`、`AbathurRebornSymbiote*`、`RavagerAbathurReborn` 等专属对象。
- `XMFinal` 只在阿巴瑟 helper 内根据 `commander == "AbathurReborn"` 替换破坏者、虫群宿主、女王、利维坦。

**当前对比**：重生阿巴瑟不是完整独立初始化；当前是“阿巴瑟 helper + 少量重生分支”。后续应检查所有源模块专属单位是否都需要进入分支，尤其是生物质拾取、重生共生体、重生变形按钮是否只靠单位 ID 替换就能生效。

### 阿拉纳克（`XMAlarak`）

**静态建筑**：传送门、折跃门、机械台折跃、黄昏议会、光子炮台。

**静态核心兵种/对象**：阿拉纳克、死徒（`Supplicant`）、追猎者、浩劫（`Monitor`）、塔达林不朽者、塔达林巨像、塔达林虚空辉光舰、塔达林航母、塔达林折跃棱镜。

**游戏内机制证据**：

- `AbilData.xml` 中死徒训练一次写入两个 `Supplicant`，说明死徒不是普通单个训练单位。
- `EffectData.xml` 有 `AlarakEmpowerMe`。
- `UpgradeData.xml` 有 `AlarakHavocAbilityRange`、`AlarakImprovedDeathFleet`、死徒献祭/护盾升级等。

**当前对比**：`XMFinal` 创建的死徒、浩劫、塔达林机械单位方向基本正确。缺口主要不是单位 ID，而是强化我、死亡舰队、献祭收益等全局/英雄机制是否每图初始化时启用。

### 阿塔尼斯（`XMArtanis`）

**静态建筑**：枢纽、水晶塔、同化气矿、传送门、折跃门、控制芯核、锻炉、机械台、机械研究所、星门、舰队航标、圣堂档案馆、黄昏议会、光子炮台、护盾充能器。

**游戏内机制证据**：

- `AbilData.xml` 训练链直接指向 `ZealotAiur`、`Dragoon`、`ImmortalAiur`、`Reaver`、`PhoenixAiur`、`CarrierAiur`、`Tempest`。
- `BehaviorData.xml` 有守护之壳链：`SOAHeroicShield*`。
- `UpgradeData.xml` 有 `SOAHeroicShield`、`SOAOrbitalStrike`、`SOAWarpGateCharges`、`SOAWarpTech`。

**当前对比**：`XMFinal` 使用 `ZealotAiur`、`Dragoon`、`ImmortalAiur`、`Reaver`、`PhoenixAiur`、`CarrierAiur`、`Tempest`，单位 ID 与源训练链对齐。后续重点是确认地图初始化是否给亚顿之矛、守护之壳、折跃科技/充能这些全局升级，而不是继续纠结兵种名。

### 菲尼克斯（`XMFenix`）

**静态建筑**：枢纽、水晶塔、同化气矿、传送门、折跃门、控制芯核、锻炉、机械台、机械研究所、星门、舰队航标、黄昏议会、光子炮台、护盾充能器、净化者议会（`FenixAltarOfPsiStorms`）、菲尼克斯技能面板。

**静态核心兵种/对象**：净化者狂热者（`ZealotPurifier`）、使徒（`AdeptFenix`）、保护者（`SentryFenix` / `SentryFenixPhasing`）、净化者追猎者、净化者巨像、侦察机、航母、菲尼克斯三形态、六个冠军：卡尔达利斯、塔里斯、摩约、塔尔达林、战争使者、科罗拉里昂。

**游戏内机制证据**：

- `AbilData.xml` 的 `FenixAltarOfPsiStormsTrain` 是冠军相关建筑训练入口。
- `AbilData.xml` 中 `Research1..Research6` 分别解锁六个冠军下载：卡尔达利斯、塔里斯、摩约、塔尔达林、战争使者、科罗拉里昂。
- `AbilData.xml` 有多个冠军 morph：`FenixKaldalisZealotMorph`、`FenixTalisAdeptMorph`、`FenixMojoScoutMorph`、`FenixTaldarinImmortalMorph`、`FenixWarbringerColossusMorph`、`FenixClolarionCarrierMorph`。
- `BehaviorData.xml` 有 `FenixChampionSwapBoost*`，说明冠军替换/下载不是单纯创建单位。

**当前对比**：`XMFinal` 基础单位方向基本对，但 ultimate 只创建卡尔达利斯、塔里斯、科罗拉里昂，没有覆盖摩约、塔尔达林、战争使者。后续应把“冠军 AI/下载/替换链”作为菲尼克斯完成标准，不要只看净化者单位是否存在。

### 凯拉克斯（`XMKarax`）

**静态建筑**：枢纽、水晶塔、同化气矿、传送门、折跃门、控制芯核、锻炉、机械台、机械研究所、星门、舰队航标、黄昏议会、光子炮台、护盾充能器、凯达琳巨石、太阳锻炉、受损太阳锻炉。

**静态核心兵种/对象**：哨兵（`ZealotPurifier`）、激励者（`SentryPhasing`）、艾尔不朽者（`ImmortalAiur`）、净化者巨像（`ColossusPurifier`）、艾尔航母（`CarrierAiur`）、亚顿之矛面板、自动修理/时空波动/轨道轰炸相关对象。

**游戏内机制证据**：

- 中文本地化明确 `Unit/Name/ZealotPurifier=哨兵`、`Unit/Name/SentryPhasing=激励者`。
- `BehaviorData.xml` 有 `SOARepairBeam`、`SOAMapWideChrono`。
