## 仍需实机验证

这些不能只靠静态 XML 和 Galaxy 字符串判断，需要进图点击验证：

| 模块 | 需验证内容 |
|---|---|
| 英雄复活 | 杀死 `ZeratulCoop` 后是否出现正确复活建筑、倒计时、复活点、复活后技能状态 |
| 预言/神器碎片 | `ProphecyVision` 点击、镜头/揭示、碎片拾取、神器等级升级、后续碎片刷新 |
| 顶部面板 | 每个按钮的冷却、费用、目标类型、召唤单位、建筑投放是否真实生效 |
| 传奇军团/化身 | 召唤单位、持续时间、可控/不可控语义、升级后技能是否符合官方 |
| 单位技能效果 | 虚空圣堂武士闪现伤害/回撤、观察者形态切换、禁绝者净化新星、伏击者闪现效果 |
| UI 热键 | `ZeratulDarkTemplarBlink`、`ZeratulStalkerShadowBlink` 无官方热键建议；`ZeratulCoop` 的 `T` 键在普通/威望虚空追寻者按钮复用，需要确认 UI 口径 |

## 当前判断口径

1. 不再把 7v1 的 `TechUnit.Commander` 命中直接写成当前 Mod 正向闭包。
2. 不再把官方 JSON 缺失直接视为“官方没有”。泽拉图尤其要追 raw XML。
3. `Observer` 是官方导出槽位/旧线索，当前 runtime 必须映射到 `ZeratulObserver`。
4. `ZeratulDarkTemplar` 是官方 raw 正链，但官方 JSON 缺口，当前 Mod 纳入 runtime 是正确方向。
5. “静态通过”只能说明按钮、Ability、Requirement、runtime profile 入口存在；“功能对齐”必须由实机测试确认。
