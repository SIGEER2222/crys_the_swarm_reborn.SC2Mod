# 挑战、成就与恩赐奖励系统设计

日期：2026-05-28

## 设计目标

当前系统要新增一条独立于指挥官等级、精通、威望之外的长期成长线：

1. 挑战提供额外规则和通关目标。
2. 成就记录跨局完成情况。
3. 奖励解锁为每局可选的“恩赐”。
4. 每局只能选择一个恩赐，避免多项永久叠加破坏平衡。
5. 指挥官类恩赐通过指定指挥官完成指定任务解锁；经济类恩赐通过不同挑战解锁。

该系统应落在当前统一 runtime owner：

`原始mod/Mods/XM/XMFinal.SC2Mod`

旧 `crys_the_swarm_reborn.SC2Mod` 只可参考 Bank、胜利结算、UI 写法，不作为新系统 owner。

## 核心规则

### 每局多选一

玩家在 Launcher 或开局前 UI 中从已解锁恩赐里选择 0 或 1 个。

- 未选择：纯净模式，无额外奖励。
- 已选择：本局开始时应用对应恩赐。
- 挑战可以标记为“禁用恩赐”，用于保留高难挑战含金量。
- 胜利结算记录本局使用的恩赐、挑战完成情况、新解锁成就。

### 解锁来源

成就分两类：

1. 指挥官传承成就：用指定指挥官完成指定任务或条件，解锁该指挥官代表性被动。
2. 挑战成就：完成资源、限时、生存、全额外目标等挑战，解锁地图规则类恩赐。

### Bank 存储建议

继续使用 `CampaignXCore.SC2Bank`，但不要复用现有 `Ach/Commander` 和各指挥官精通字段。

建议新增 section：

| Section | Key | Value | 用途 |
|---|---|---|---|
| `Achievement` | `<achievementId>` | `0/1` | 成就是否已完成 |
| `AchievementProgress` | `<achievementId>` | `int` | 可累计成就进度 |
| `Blessing` | `<blessingId>` | `0/1` | 恩赐是否已解锁 |
| `Blessing` | `Selected` | `string` | 下一局选择的恩赐 |
| `Challenge` | `Active` | `string` | 下一局选择的挑战 |
| `ChallengeBest` | `<challengeId>:<mapId>` | `int/string` | 挑战最佳记录 |

## 第一批恩赐

### 1. 资源富集

ID：`BlessingResourceRich`

效果：

- 全地图矿物和瓦斯资源储量翻倍。
- 偏长线经济，适合消耗战、防守战、后期科技指挥官。

解锁方式：

- 完成“资源贫瘠”挑战。
- 示例成就：`ACH_CHALLENGE_RESOURCE_SCARCE_CLEAR`
- 条件：在资源总量降低或采集受限的挑战规则下通关。

实现建议：

- 第一阶段在地图初始化后扫描资源单位，并把剩余资源量设置为当前值的 2 倍。
- 需要在实现前确认当前地图资源单位类型和可用 Galaxy API；如直接设置资源量不稳定，可改为初始化时替换为高储量自定义资源节点。

### 2. 黄金矿脉

ID：`BlessingGoldenMinerals`

效果：

- 全地图普通矿替换为黄金矿。
- 偏前期爆发经济，适合限时推进、快攻、速科技打法。

解锁方式：

- 完成“限时推进”挑战。
- 示例成就：`ACH_CHALLENGE_SPEED_CLEAR`
- 条件：在指定时间内完成任务主目标。

实现建议：

- 第一阶段优先只处理普通矿物，不改变瓦斯。
- 初始化时扫描普通矿物单位并替换为黄金矿物等价单位。
- 若不同地图矿物单位 ID 不一致，需要先做资源单位 ID 白名单。

### 3. 守护之壳

ID：`BlessingGuardianShell`

来源指挥官：阿塔尼斯

效果：

- 玩家单位受到致死伤害时触发一次保命。
- 触发后短时间无敌或保留少量生命。
- 每个单位应有较长冷却，避免形成永久不死。

解锁方式：

- 使用阿塔尼斯完成指定关键任务。
- 示例成就：`ACH_ARTANIS_CLEAR_KEY_MISSION`
- 进阶条件可设计为“阿塔尼斯通关且英雄/关键单位未死亡”。

实现建议：

- 优先复用官方合作指挥官数据中的守护之壳行为。
- 如果官方行为移植成本高，第一阶段可用触发器简化实现：监听玩家单位濒死或死亡前事件，满足冷却则恢复生命并添加短暂无敌行为。
- 需要记录单位级冷却，避免同一单位连续触发。

### 4. 相位维修

ID：`BlessingPhaseRepair`

来源指挥官：凯拉克斯

效果：

- 玩家机械单位自动缓慢维修。
- 只影响机械单位，不影响生物单位。
- 偏续航，适合斯旺、雷诺机械、诺娃、蒙斯克皇家卫队等机械体系。

解锁方式：

- 使用凯拉克斯完成指定任务。
- 示例成就：`ACH_KARAX_CLEAR_KEY_MISSION`
- 进阶条件可设计为“机械单位损失少于指定数量”。

实现建议：

- 优先复用凯拉克斯官方自动维修相关行为。
- 如果官方行为未完整落地，第一阶段可用周期触发器扫描玩家机械单位并回血。
- 需要限制回血速率，避免战斗中维修过强；可设计为脱战维修更强、战斗中维修较弱。

### 5. 菌毯再生

ID：`BlessingCreepRegeneration`

来源指挥官：凯瑞甘

效果：

- 玩家生物单位在菌毯上获得生命恢复。
- 只影响生物单位。
- 对虫族体系收益高，对机械体系收益低，形成选择差异。

解锁方式：

- 使用凯瑞甘完成指定任务或菌毯相关挑战。
- 示例成就：`ACH_KERRIGAN_CREEP_CLEAR`
- 进阶条件可设计为“在菌毯覆盖相关目标达标后通关”。

实现建议：

- 优先复用凯瑞甘恶性菌毯/合作指挥官相关效果。
- 若官方效果依赖复杂触发器，第一阶段可用周期触发器扫描玩家生物单位，判断是否位于菌毯上并回血。
- 需要确认 Galaxy 中检测菌毯的稳定 API 或现有地图/官方库写法。

## 第一批挑战

### 资源贫瘠

ID：`ChallengeResourceScarce`

规则：

- 降低全地图矿物和瓦斯资源储量，或降低玩家采集收益。
- 通关后解锁 `资源富集`。

目标：

- 让玩家先经历资源压力，再奖励资源掌控能力。

### 限时推进

ID：`ChallengeSpeedClear`

规则：

- 必须在指定时间内完成主目标。
- 可按地图配置不同时间阈值。

奖励：

- 通关后解锁 `黄金矿脉`。

### 全额外目标

ID：`ChallengeFullBonus`

规则：

- 必须完成当前地图全部额外目标。

用途：

- 可作为高级通用挑战，也可用于解锁部分展示徽章或挑战点数。

### 无关键单位死亡

ID：`ChallengeNoHeroDeath`

规则：

- 英雄或指定关键单位不能死亡。

用途：

- 适合与 `守护之壳` 的解锁链分离：先通过阿塔尼斯任务解锁保命，再用保命挑战冲更高记录。

## Runtime 架构建议

### 新增文件

建议在 `原始mod/Mods/XM/XMFinal.SC2Mod/Base.SC2Data/` 下新增：

- `LibE0EAE146_AchievementCore.galaxy`
- `LibE0EAE146_ChallengeCore.galaxy`
- `LibE0EAE146_BlessingCore.galaxy`

并在 `LibE0EAE146.galaxy` 中 include。

如果后续逻辑不大，也可以先合并为：

- `LibE0EAE146_ProgressionRewards.galaxy`

但长期更推荐按职责拆开，保持 runtime 文件不过大。

### 主要函数草案

```galaxy
void XMProgression_Init(int player);
void XMBlessing_LoadSelected(int player);
bool XMBlessing_IsUnlocked(int player, string blessingId);
void XMBlessing_ApplySelected(int player);
void XMAchievement_Unlock(int player, string achievementId);
bool XMAchievement_IsUnlocked(int player, string achievementId);
void XMChallenge_LoadActive(int player);
void XMChallenge_RecordEvent(int player, string eventId, int value);
void XMChallenge_EvaluateOnVictory(int player, string mapId, string commanderId);
void XMProgression_Save(int player);
```

### 接入点

1. `libE0EAE146_gf_Initialize(bool lp_rpg)`
   - 读取当前指挥官。
   - 初始化挑战、成就、恩赐状态。

2. `libE0EAE146_gf_InitializeBase(...)`
   - 基地和初始单位创建后应用本局恩赐。
   - 经济类恩赐可在更早阶段应用，避免矿物节点已被玩家采集后再变化。

3. `libE0EAE146_gf_FinishLevel()`
   - 结算挑战。
   - 解锁成就。
   - 写入 Bank。
   - 在胜利界面或 Debug 输出中显示本局解锁结果。

4. 地图脚本
   - 只上报地图事件，不直接写 Bank。
   - 示例：额外目标完成、关键单位死亡、主目标完成时间。

## 第一阶段竖切

建议第一阶段只做最小闭环：

1. Bank 新 section：`Achievement`、`Blessing`、`Challenge`。
2. Launcher 或测试入口写入 `Blessing/Selected`。
3. runtime 读取并应用一个恩赐，优先选择实现风险最低的 `相位维修` 或 `菌毯再生`。
4. `FinishLevel()` 解锁一个成就，并写入对应 `Blessing/<id>=1`。
5. 测试台增加 smoke 场景，输出 Debug：
   - 当前指挥官
   - 当前地图
   - 当前挑战
   - 当前恩赐
   - 新解锁成就
   - 新解锁恩赐

## 后续扩展

可继续添加其他指挥官传承：

| 指挥官 | 恩赐方向 |
|---|---|
| 雷诺 | 轨道补给、空投支援、快速补兵 |
| 阿巴瑟 | 少量生物质掉落、生物单位成长 |
| 斯旺 | 瓦斯采集辅助、机械防御强化 |
| 沃拉尊 | 一次紧急召回或隐形救援 |
| 德哈卡 | 英雄成长加速或首次吞噬强化 |
| 蒙斯克 | 帝国支援、皇家卫队经验加速 |
| 诺娃 | 精英单位补给或战术空运 |
| 斯台特曼 | 小范围加速场或能量场恢复 |

## 风险与约束

1. 不要复用现有 `AchBit` 作为新成就存储位；该字段已承担指挥官等级/加点融合含义。
2. 不要把所有恩赐做成永久叠加；第一版必须保持每局多选一。
3. 资源改造类需要逐地图验证资源单位 ID 和可用 API。
4. 指挥官被动类优先复用官方数据，但第一阶段可以用触发器实现简化版以先跑通系统。
5. 挑战禁用恩赐的规则要从第一版就预留，否则后续高难记录会失去区分度。
