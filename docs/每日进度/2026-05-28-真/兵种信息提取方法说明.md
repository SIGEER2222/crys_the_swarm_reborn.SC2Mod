# 兵种信息提取方法说明

## 目标

- 从本机官方 SC2 安装中重新提取合作指挥官兵种/建筑/英雄信息
- 输出为可读 JSON 与中文总表
- 后续可据此反向校对当前指挥官实现与 smoke 用例

## 当前官方源口径

- 官方安装目录：`E:\SC2\SC2new\StarCraft II`
- 实际读取入口：`E:\SC2\SC2new\StarCraft II\SC2Data`
- 当前仓库内官方缓存目录：`游戏数据/官方合作指挥官/_source-cache/live-casc-export`
- 当前中文整理输出目录：`游戏数据/官方合作指挥官`

## 提取链路

### 1. 从本机 SC2Data 导出官方合作数据

使用脚本：

```powershell
python .\scripts\sc2\export-official-coop-game-data.py --storage-path 'E:\SC2\SC2new\StarCraft II\SC2Data' --force-live-refresh
```

这个脚本会做两件事：

1. 调用 `tools/casc/CascDump/bin/Debug/net9.0/CascDump.exe`
2. 从 CASC 中提取合作模式相关 XML/TXT 到：
   `游戏数据/官方合作指挥官/_source-cache/live-casc-export`

### 2. 生成按指挥官拆分的 JSON

上面的脚本在提取官方 XML/TXT 后，会继续生成：

- `游戏数据/官方合作指挥官/commanders/<Commander>/commander.json`
- `游戏数据/官方合作指挥官/commanders/<Commander>/units.json`
- `游戏数据/官方合作指挥官/commanders/<Commander>/buildings.json`
- `游戏数据/官方合作指挥官/commanders/<Commander>/heroes.json`
- `游戏数据/官方合作指挥官/commanders/<Commander>/command_cards.json`
- `游戏数据/官方合作指挥官/commanders/<Commander>/upgrades.json`

### 3. 生成人类可读的中文总表

使用脚本：

```powershell
python .\scripts\sc2\render-official-coop-roster-markdown.py
```

输出文件：

- `游戏数据/官方合作指挥官/官方合作指挥官兵种建筑总表-中文.md`

## 关键脚本

### `scripts/sc2/export-official-coop-game-data.py`

职责：

- 从本机 `SC2Data` 提取 `mods/starcoop/...`
- 额外覆盖：
  - `mods/starcoop/commanders/egonstetmann.sc2mod`
  - `mods/starcoop/commanders/arcturusmengsk.sc2mod`
- 解析 `userdata.xml / unitdata.xml / abildata.xml / gamestrings.txt`
- 按指挥官输出兵种、建筑、英雄、面板、加点、威望、精通等 JSON

### `scripts/sc2/render-official-coop-roster-markdown.py`

职责：

- 基于 `commanders/*/*.json` 生成中文总表
- 当前口径不是机械平铺原始 `TechUnit`
- 当前重点按“最终可玩形态”做了人工归并

## 关键数据文件怎么读

### `commander.json`

看指挥官基础信息：

- 指挥官 ID
- 中文名
- 简介
- 默认升级
- 默认能力命令

### `units.json`

看兵种主表。常用字段：

- `name`
  - 中文展示名
- `unit_id`
  - 真实单位 ID
- `tooltip`
  - 描述
- `production`
  - 代表性生产入口
- `production_options`
  - 所有候选生产/进化入口
- `unit`
  - 解析后的单位 Catalog 信息
- `abilities`
  - 单位面板按钮和技能摘要

重点字段：

- `production.base_unit_id`
  - 用于判断某单位是否是由别的单位进化而来
- `production.producer_unit_id`
  - 用于判断谁生产/触发了这个单位

### `buildings.json`

看建筑主表。字段结构和 `units.json` 类似，但对象类型通常是 `Structure`。

### `heroes.json`

看英雄对象。很多指挥官的英雄并不会出现在普通兵种里，要单独读这里。

### `command_cards.json`

看单位/建筑/英雄的命令面板按钮归属。做 smoke 时很关键。

## 当前提取规则

### 基础规则

- 先按官方 `TechUnit` 把名册拉出来
- 再结合 `UnitData / AbilData / ButtonData / UserData / GameStrings`
  补生产链、按钮、图标、中文名

### 当前人类可读规则

- 不是把所有解析到的单位对象全部平铺
- 优先整理成“最终会给玩家看的兵种/建筑/英雄”
- 对升级替代、进化分支、姿态体、埋地体、模式体要人工归并

## 当前已知坑

### 1. 不能只看 `TechUnit`

只看 `TechUnit` 会把：

- 基础体
- 替换体
- 进化体
- 姿态体
- 模式体

全部混在一起，最后给人的清单会错。

### 2. 不能把 `production.base_unit_id` 直接当成唯一真相

它能帮助识别进化链，但不总是完整。

例如：

- 阿巴瑟 `莽兽 / 利维坦`
  - 不是固定单线升级
  - 应理解为“满生物质后的终极进化项”

### 3. 官方 JSON 生成后，还需要人工归并规则

当前已明确需要人工归并的至少包括：

- 凯瑞甘：
  - 跳虫 -> 腾跃虫
- 阿巴瑟：
  - 蟑螂 -> 尸毒蟑螂 / 恶毒蟑螂 -> 秽形虫
  - 异龙 -> 守护者 / 吞噬者
  - 莽兽 / 利维坦 = 终极进化项
- 斯台特曼：
  - 跳虫 -> 爆虫
  - 刺蛇 -> 潜伏者
  - 腐化者 -> 巢式战列空母
- 斯旺 / 霍纳与汉 / 蒙斯克 / 德哈卡
  - 仍有姿态体、等级体、模式体清理空间

## 当前推荐操作顺序

1. 先跑官方导出脚本，刷新 live export
2. 再看 `commanders/<Commander>/units.json / buildings.json / heroes.json`
3. 然后跑中文总表脚本
4. 最后对照总表做人类校对，并把归并规则补到渲染脚本里

## 一句话总结

- “提取兵种信息”分两层：
  1. 机器层：从 SC2Data 抽官方 XML/TXT，再生成指挥官 JSON
  2. 人类层：基于生产链和升级链，把 JSON 归并成最终可玩的兵种/建筑/英雄清单

- 当前仓库里真正可复用的入口已经有了，后面主要工作是继续补“最终形态归并规则”，而不是再去重新猜官方源。
