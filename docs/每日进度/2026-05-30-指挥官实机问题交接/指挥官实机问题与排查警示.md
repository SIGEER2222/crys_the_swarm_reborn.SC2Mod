# 指挥官实机问题与排查警示

日期：2026-05-30  
目的：把当前实机暴露的问题整理给后续 AI。不要再只看静态清单、字符串命中、`CatalogEntryIsValid` 或 smoke 日志里的“created/missing=0”就判断完成；本轮问题的共同点是“面板/单位看起来存在，但实机点击、生产、进化链不工作或不是该指挥官版本”。

## 当前已暴露的问题

### 1. 凯瑞甘英雄单位与技能链

- 实机现象：凯瑞甘英雄形态已经比之前更接近正确，但技能点了没有效果。
- 之前现象：凯瑞甘曾经只剩一个技能；也出现过英雄没生成、或不是刀锋女王/合作模式应有形态的问题。
- 关键风险：`K5Kerrigan`、`CoopCasterKerrigan`、顶栏技能、英雄本体技能不是同一条链。把英雄单位生出来，不等于技能面板、效果、验证器、升级、冷却、费用、目标类型都通了。
- 重点核查：
  - 英雄单位实际 ID 是否为合作凯瑞甘链路需要的 `K5Kerrigan`，而不是战役/突变/其它凯瑞甘。
  - 英雄命令卡里的按钮是否绑定到正确 `Abil` 和正确 `Cmd`。
  - 点击技能后是否真的触发 `Effect`，而不是只满足“按钮存在”。
  - `Requirement` / `Validator` / `Behavior` / `Upgrade` 是否完整解锁。
  - 顶栏技能如果由 `CoopCasterKerrigan` 承载，要确认 caster 单位真实存在、归属正确、技能 owner 正确。

### 2. 虫族基地产兵不对

- 实机现象：虫族基地/幼虫产出的兵仍和当前指挥官不一致。
- 典型表现：凯瑞甘、阿巴瑟、斯托科夫、扎加拉、斯台特曼等虫族指挥官容易被普通虫族、战役虫族或其它指挥官共享对象污染。
- 关键风险：虫族产兵不是只看 `Hatchery` 或 `Larva`。生产链通常经过基地命令卡、幼虫单位、`Train/Morph` 能力、按钮、需求、升级替换和指挥官专属变体共同决定。
- 重点核查：
  - 当前基地实际 ID、幼虫实际 ID、命令卡、`Train/Morph` InfoArray 是否来自该指挥官链路。
  - 基地产出的单位实际 ID 必须在日志里打印，而不是只打印预期 ID。
  - 如果某指挥官复用共享 `Hatchery` / `Larva`，必须追到指挥官专属 `Requirement` / `Upgrade` / replacement，而不是把共享对象直接当最终答案。

### 3. 单位技能不生效

- 实机现象：技能按钮可能显示，但点击无效果。
- 旧问题样本：雷诺的机枪兵、劫掠者、火蝠没有兴奋剂；凯瑞甘技能点击无效果。
- 关键风险：单位清单正确不代表单位技能正确。技能生效至少需要单位命令卡、能力、按钮、费用、需求、效果、目标过滤、行为/升级全部闭合。
- 重点核查：
  - 打印每个单位的实际 `UnitType`、命令卡按钮、绑定 `Abil`、`Cmd`。
  - 实机点击后验证可观察结果：冷却变化、能量/资源变化、buff 出现、目标受伤、单位生成、形态变化。
  - 不要只检查 `AbilData.xml` 里有这个技能 ID。

### 4. 进化关系不对

- 实机/人工校验发现：部分进化关系混入普通虫族或其它指挥官逻辑。
- 凯瑞甘重点：
  - 跳虫应按凯瑞甘合作指挥官升级链变为腾跃虫。
  - 跳虫/迅猛虫不应该变成爆虫。
  - 刺蛇应能按凯瑞甘链路变为潜伏者。
  - 凯瑞甘雷兽应是带复活链路的雷兽。
- 阿巴瑟重点：
  - 蟑螂升级/变体不能重复列出三种“蟑螂”后不分关系。
  - 满生物质后莽兽是所有地面单位的满生物质升级项，不能写成某个单一单位的普通生产单位或普通进化描述。
- 重点核查：
  - 进化关系必须从官方合作指挥官数据追 `Morph` / `Requirement` / `Upgrade` / `Behavior`，不能靠普通 melee 虫族关系推断。
  - smoke 应增加“进化后实际单位 ID”打印。

### 5. 人族建筑/工人混用战役版本

- 已知样本：
  - 雷诺的 SCV 看起来是战役 SCV，建造建筑也是战役建筑。
  - 诺娃的基地是战役基地。
  - 诺娃的 SCV 是战役 SCV。
  - 诺娃兵营是战役兵营。
  - 诺娃重工厂没出来。
  - 诺娃 smoke 没有把诺娃英雄单位搞出来。
- 关键风险：`CommandCenter`、`SCV`、`Barracks` 这些名字很容易命中战役/通用对象。合作指挥官实际用的是带指挥官规则、训练限制、科技需求、英雄/精英单位链的版本。
- 重点核查：
  - 工人实际 ID、基地实际 ID、建筑实际 ID、建造菜单实际按钮必须打印。
  - 对诺娃尤其要确认精英单位生产建筑、英雄单位、科技需求和 charges/cooldown 链。

### 6. 斯托科夫链路混乱

- 已知样本：
  - 出现非该指挥官单位/建筑，如 `siwiaith`、跳虫。
  - “被感染的基地”疑似和战役或其它指挥官混用。
  - 缺少被感染基地两项升级：提升王虫移动速度、降低感染技能冷却。
  - 面板没有。
- 重点核查：
  - 斯托科夫的感染人族建筑、被感染基地、菌毯/感染技能、顶栏或面板能力要作为独立链路查，不要从普通虫族或人族共享对象硬套。

## 现在最容易误判的地方

- “单位/建筑清单输出正确”不等于“实机可用”。当前问题多数在命令卡、能力命令、效果、需求、升级、caster、生产者、进化目标这些第二层链路。
- “官方合作指挥官数据”不能从 `合作指挥官版起义狂潮/` 反推。该目录是当前实现目标，不是官方事实源。
- `references/` 旧导出已经废弃；不要再作为官方依据。
- 共享 ID 不等于错，但共享 ID 必须追完整上下文。比如 `Hatchery`、`Larva`、`SCV`、`CommandCenter`、`Zergling` 可能只是入口名，真正差异在升级、需求、命令卡或替换链。
- smoke 当前偏静态，容易只证明“ID 存在”。它还不能充分证明“玩家实机点击这个按钮后得到正确结果”。

## 建议的最小排查闭环

### 每个指挥官至少打印这些内容

- 当前选择的 commander key。
- 起始基地、工人、英雄、caster、幼虫的实际单位 ID。
- 每个建筑的实际单位 ID，以及它的命令卡按钮、`Abil`、`Cmd`。
- 每个生产按钮点击/下令后的实际产物单位 ID。
- 每个英雄技能/单位技能点击后的实际结果：冷却、能量/资源变化、buff、伤害、召唤物、形态变化。
- 每个进化命令执行前单位 ID、技能 ID、目标 ID、执行后单位 ID。

### 每类问题的验收标准

- 英雄技能：按钮存在、能点击、点击后有正确效果，且日志记录实际效果或可观察状态变化。
- 基地产兵：从基地/幼虫实际下令，产出的单位 ID 与该指挥官官方链路一致。
- 单位技能：技能不是只显示，必须能触发对应效果。
- 进化关系：进化前后单位 ID 和官方合作指挥官关系一致；禁止把普通 melee 或战役关系直接套进合作模式。
- 建筑链：工人实际建出的建筑 ID、建筑命令卡、建筑产兵结果都要一致。

## 当前排查方向建议

1. 先不要大面积继续“补清单”。清单已经多次证明会误导，下一步应补实机行为日志。
2. 对凯瑞甘先追英雄技能点击无效果：从 `K5Kerrigan` 命令卡 -> `Abil`/`Cmd` -> `Effect` -> `Validator/Requirement` -> 所需 `Upgrade/Behavior`。
3. 对虫族基地先追实际生产链：基地/幼虫实际 ID -> 命令卡 -> train/morph 能力 -> 产物实际 ID -> 指挥官升级替换。
4. 对雷诺/诺娃先追工人与建筑来源：SCV 实际 ID -> build ability -> 建筑实际 ID -> 建筑生产菜单。
5. smoke 日志要从“列出预期项”改成“记录实机实际项”。否则后续 AI 还会被假阳性骗一遍。

## 不要做的事

- 不要把 `合作指挥官版起义狂潮/` 当前实现当官方数据源。
- 不要只因为 `CatalogEntryIsValid` 为真就认定链路正确。
- 不要只补 `UnitData.xml` 里的 ID，而不追命令卡、能力、效果、需求、升级。
- 不要直接把普通战役/多人/突变单位当合作指挥官单位。
- 不要修改 `合作指挥官版起义狂潮/Mods/XM/XMFinal.SC2Mod/DocumentHeader` 源文件。

## 一句话结论

当前不是“缺几个单位 ID”的问题，而是“指挥官专属 runtime 闭包没有按实机链路验证”的问题。后续修复必须从官方合作数据追到实机行为：实际单位、实际建筑、实际按钮、实际技能、实际产物、实际进化结果。
