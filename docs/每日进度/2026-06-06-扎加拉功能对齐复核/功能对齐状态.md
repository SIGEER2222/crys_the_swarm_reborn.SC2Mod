## 7v1 对照结论

7v1 的扎加拉是 `ZergZagara`。它的核心做法是：

| 项 | 7v1 参考 | 对当前 Mod 的意义 |
|---|---|---|
| 开局 | `Race=Zerg`、`SpawnRace=Zerg`，普通 Zerg 开局外壳 | 不能作为当前 Mod 私有基地完成证据 |
| 英雄 | `HeroUnit=ZagaraVoidCoop` | 可作为英雄 ID 参考 |
| 复活建筑 | `ZagaraReviveCocoon` | 可作为复活链参考 |
| 默认升级 | `ZagaraCommander`、`K5TwoDrones`、`MasteryZagaraLarvaRatePassive` | 可作为满级/精通授予参考 |
| 默认能力 | `ZagaraVoidCoopBanelingBarrage`、`ZagaraVoidCoopMassFrenzy`、`ZagaraVoidCoopSpawnHunterKillers`、部分 `ZergBuild/evolutionchamberresearch` | 可作为能力开放参考 |
| 单位归属 | 依赖 `TechUnit.Commander` 和 Requirement | 当前 Mod 不照搬，仍优先私有 Unit ID |

判断：7v1 能帮助确认“扎加拉英雄、复活虫茧、默认技能/升级”的官方运行口径，但它不是当前 Mod 私有基地/私有兵种闭包的证明。

## 当前判断口径

1. `CoopCasterZagara` 是兼容/global caster shell；当前四个顶部面板 profile 实际 caster 是 `ZagaraVoidCoop`。
2. `ZagaraVoidCoop` 是玩家扎加拉英雄正向 ID；`MutatorAmonZagara*` 是敌方/突变链，不计入玩家闭包。
3. 7v1 的共享 Zerg 开局不能反证当前 Mod 的私有基地需求；当前 Mod 必须继续验证 `HatcheryZagara/DroneZagara/OverlordZagara`。
4. 不能把卡面里出现的坑道虫/历史技能直接写成当前扎加拉正向功能；必须看当前威望、升级授予和面板 profile。
5. “静态通过”只说明入口、按钮、Ability、Effect、产物 ID、Requirement 和 smoke 检查存在；“功能对齐”必须由实机测试确认。
