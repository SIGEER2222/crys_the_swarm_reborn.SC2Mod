# 2026-05-26 官方合作指挥官 runtime 生效链对比

## 结论先行

这轮按“实机是否可能生效”的口径重看了一遍，结论是：不能再用“官方主表同 ID 已闭环”直接判断玩法完成。

静态主表只能说明单位、升级、按钮等对象大体存在；runtime 还要看 `XMFinal.SC2Mod/Base.SC2Data/LibE0EAE146.galaxy` 是否真的做了这些事：

1. 是否从 Bank 读取指挥官等级加点和精通点，并实际发放对应升级。
2. 是否创建对应指挥官的技能面板单位、英雄单位或专用 caster。
3. 地图开局队伍、货舱队伍是否直接写死普通单位，从而绕过官方的进化、替换、英雄或精通链。
4. 指挥官是否依赖自己的专用初始化库，而不是通用开局队伍 helper。

当前最明确的 runtime helper 偏差已先修三类：阿巴瑟 helper 不再创建刺蛇、跳虫、腐化者；凯瑞甘开局/货舱 helper 不再创建普通跳虫和普通女王，改为腾跃虫与合作女王；沃拉尊货舱空军分支已改回海盗船、虚空辉光舰、先知。顺带修正了扎加拉 hero 队伍里的支援女王为合作女王。冻结模块仍不能因为 `XMFinal` 有 caster 初始化就判定完成。

## 通用加点和精通链

`InitializeBase` 开头会先做一层通用发放：

- 读取 `CampaignXCore` Bank。
- 读取当前指挥官的 `AchBit`，按 bit 0 到 7 给 `CommanderAch.Upg[1..8]` 加 1 级。
- 读取 Bank 里的 `"0"` 到 `"5"` 六组精通点，给 `CommanderAch.Poi[1..6]` 加对应等级。
- 然后创建主基地、工人和 `SecondUnit`，最后进入各指挥官分支。

也就是说，多数指挥官的“等级加点/精通”并不是在每个指挥官分支里逐条写死，而是靠 `CommanderAch` 这套 UserData 统一映射。分支里出现的额外处理，才是需要单独盯的 runtime 特例。

当前能直接看到的特例：

| 指挥官 | runtime 特例 | 当前能确认的具体效果 |
|---|---|---|
| 凯瑞甘 | 分支内硬发升级 | 直接给 15 级、凯瑞甘指挥官标记、感染皮肤、英雄坚韧、原始突袭、灵能打击、连锁闪电、冷却缩减、狂怒、能量回复。 |
| 泰凯斯 | 精通点影响亡命徒出场计时 | Bank 第 4 组精通点每点折算 3 秒；创建英雄时用 `90 - 点数*3`，非英雄场景用 `240 - 点数*3`。 |
| 蒙斯克 | 多组精通直接改全局倍率 | 第 1 组每点给普通士兵生成/训练相关倍率加 1%；第 2 组每点给皇家卫队相关倍率加 1%；第 6 组每点给皇家卫队经验加 0.5；第 5 组每点给 caster 能量加 2；第 6 个等级 bit 额外给经验加 50。 |
| 诺娃 | 精通点进粘滞线升级 | 第 2 组精通点传给 `SOAStickyLineUpg`，直接影响诺娃面板线。 |

| 德哈卡 | 等级 bit 控制额外单位 | 第 1 个等级 bit 为真时，会在德哈卡英雄初始化后调用兄弟单位逻辑。 |

## 高风险项

### 阿巴瑟

这条需要修正前面的判断：阿巴瑟不是单纯“双版本并存下的中风险”，而是已经能从 `XMFinal` 看到明确 runtime 偏差。本轮已修复 helper，剩余状态是“待实机验证”。

官方阿巴瑟主表里没有刺蛇。当前静态总表中，阿巴瑟官方条目包括虫道网络、虫后、虫群宿主、穿刺者、利维坦、莽兽、破坏者、守护者、吞噬者、眼虫、异龙、蟑螂、飞蛇、孢子爬虫、脊针爬虫等；`TechUnit` 归属里阿巴瑟对应的是蟑螂、异龙、虫群宿主、虫道网络、脊针爬虫、孢子爬虫、守护者和吞噬者，没有 `Hydralisk`。

修复前，`XMFinal` 的阿巴瑟开局/货舱 helper 直接创建了刺蛇：

- 轻型队伍：跳虫、恶毒蟑螂、刺蛇。
- 英雄队伍：恶毒蟑螂、刺蛇、虫后。
- 货舱轻型：跳虫、恶毒蟑螂、刺蛇。
- 货舱英雄：恶毒蟑螂、刺蛇、虫后。

Reborn 分支虽然会把破坏者、虫群宿主、虫后、利维坦切到 Reborn/合作 ID，但原先没有处理刺蛇问题。所以阿巴瑟曾和凯瑞甘一样属于“主表静态存在不等于 runtime 队伍正确”的高风险项。

本轮已执行的替换：

- map light：`RoachVile x2 + Ravager/RavagerAbathurReborn x1`
- map air：`Mutalisk x2 + Devourer x1`
- map hero：`RoachVile x2 + Ravager/RavagerAbathurReborn x1 + SwarmHost/SwarmHostMP x1 + Queen/QueenCoop x1`
- cargo light：`RoachVile x3 + Ravager/RavagerAbathurReborn x1`
- cargo air：`Mutalisk x2 + Devourer x1`
- cargo hero：`RoachVile x2 + Ravager/RavagerAbathurReborn x1 + SwarmHost/SwarmHostMP x1 + Queen/QueenCoop x1`

已静态确认阿巴瑟 helper 块里不再包含 `Hydralisk`、`Zergling`、`Corruptor`。下一步只需要实机验证这些替换队伍是否强度合适。

### 凯瑞甘

当前不能再写“凯瑞甘静态闭环所以暂不用动”。更准确的说法是：凯瑞甘主表对象存在，但 runtime 生效链要拆成 helper、训练入口、英雄按钮分别验证。本轮先修了 helper 里能直接确定的单位偏差。

已确认的具体偏差：

- 数据层有 `KerriganZerglingEvo -> CoopZerglingRaptor -> HotSRaptor`。
- 数据层有 `K5Kerrigan` 多技能按钮和 `HaveK5Fury / HaveK5Cooldowns` 等显示条件。
- `XMFinal` 初始化会硬发一批凯瑞甘英雄升级。
- 修复后 `KerriganCreateMapStartSquad` 和 `KerriganCreateCargoSquad` 直接创建：
  - 轻型：腾跃虫、刺蛇。
  - 重型：刺蛇、合作女王、雷兽。
  - 空军：异龙、巢虫领主。
  - 英雄：凯瑞甘英雄、腾跃虫、刺蛇、合作女王。

所以用户实测“跳虫还是普通跳虫”的旧判断有代码证据支撑；现在 helper 这一层已改掉。下一步应优先查训练入口是否仍会产出普通跳虫，英雄技能则要查实际进场单位、按钮卡布局和等级/需求是否被上层覆盖。

### 沃拉尊

沃拉尊主表是 10/10 同 ID，货舱 air 分支原本明显可疑，本轮已修。

- 地图开局 air：海盗船、虚空辉光舰、先知。
- 修复前货舱 air：追猎者、黑暗圣堂武士、不朽者。
- 修复后货舱 air：海盗船 x2、虚空辉光舰 x1、先知 x1。

这不是“官方主表缺不缺”的问题，而是同一个指挥官的地图开局和货舱队伍不一致。现在静态 helper 已一致，剩余是进图确认货舱 air 地图是否按预期调用。

### 冻结且主表未闭环的模块

这些模块即使 `XMFinal` 有初始化入口，也不能判定玩法完成：

- 霍纳与汉：7 缺失，2 异 ID。
- 诺娃：2 缺失，2 异 ID。
- 斯托科夫：1 缺失。
- 斯旺：4 缺失，1 异 ID。

它们本轮仍按冻结处理，只记录风险，不建议直接改数据。

## 中风险项

### 菲尼克斯

菲尼克斯有 caster、英雄和开局 helper，静态主表闭环，但 helper 里有两个需要复核的点：

- 重型队伍直接给普通不朽者，而不是明确的菲尼克斯/净化者不朽者。
- 空军队伍直接给普通航母。
- 冠军三人组只在有 `FenixChampionClolarionCarrier` 时出现；货舱 helper 没有同样的 ultimate 分支。

这不一定是错误，但不能只用 12/12 同 ID 说明冠军、替换和升级链已经在实机里完整生效。

### 凯拉克斯

凯拉克斯 helper 会直接给狂热者、相位哨兵、不朽者、航母、巨像。这个层面不像凯瑞甘那样明显错给普通跳虫，但凯拉克斯的核心不只在兵种：

- 亚顿之矛 caster 是否完整。
- 修复光束是否实际挂上。
- 太阳能矩阵、顶栏技能和建筑科技是否完整。
- 相位哨兵的接管、能量恢复等升级是否会被精通/等级正确影响。

所以凯拉克斯应标成“主表闭环，但 topbar/修复/太阳能链待实机或专项校验”。

### 阿拉纳克

阿拉纳克现在已经有 `CoopCasterAlarak`、`AlarakCoop` 和专用开局 helper。运行时主入口比早先状态好很多。

需要继续盯的是：

- 模块里前面已经发现过 Karax 混链，虽然清过两轮，仍应按剩余外来链继续扫。
- helper 里的虚空辉光舰、航母是当前扩展队伍，不一定来自官方主表，需要确认这是项目设计还是混入残留。

### 雷诺

雷诺 helper 是标准人族队伍，主表也闭环。当前风险主要是终极分支：

- 有战列解锁时，终极队伍给战列巡航舰和休伯利安。
- 没有战列解锁时，回退到重型队伍。

这说明雷诺比凯瑞甘更像“runtime 已按升级条件分支”，但仍要进图确认休伯利安、佣兵面板、空投/轨道技能是否完整。

### 阿塔尼斯

阿塔尼斯 helper 基本使用艾尔特化单位，风险较低。唯一要记一笔的是：

- 地图 ultimate 会检查风暴战舰解锁。
- 货舱 ultimate 直接给航母和风暴战舰。

如果货舱队伍是调试/奖励用，这可能可接受；如果它代表同等进度队伍，就需要补同样的解锁检查。

## 低风险项

### 扎加拉

扎加拉 helper 已经使用虫群跳虫、爆虫、爆蚊、扎加拉腐化者等特化单位，整体不像凯瑞甘那样明显绕过进化结果。本轮顺手修了一处同类女王 ID：

- map hero 支援女王从普通 `Queen` 改为训练入口使用的 `QueenCoop`。
- 扎加拉英雄和群体狂暴、孵化室/爆虫链需要进图或专项脚本验证。

### 泽拉图

泽拉图 helper 基本都在用泽拉图特化 ID，包括狂热者、追猎者、机械哨兵、不朽者、干扰者、虚空阵列、英雄和构造体。当前不应再把风险放在主表单位替换上，而应转到：

- 神器碎片。
- 投影/召唤单位。
- 顶栏技能。
- 泽拉图专用科技和神器等级。

## 专用库优先项

以下指挥官没有在 `XMFinal` 里看到和凯瑞甘同类的通用开局/货舱 helper。它们主要靠自己的专用初始化库、caster、英雄或顶栏逻辑生效：

- 德哈卡
- 霍纳与汉
- 蒙斯克
- 诺娃
- 斯台特曼
- 斯托科夫
- 斯旺
- 泰凯斯

这些指挥官的正确检查口径不是“开局队伍是否创建了正确单位”，而是：

- caster 是否创建。
- 专用库是否初始化。
- 英雄或主建筑是否接到专用系统。
- 精通点是否传入专用变量或触发器。
- 主表缺口是否已经先闭环。

## 后续建议

1. 凯瑞甘 helper 已修，下一步查训练入口和英雄按钮链，不要再用 9/9 主表闭环作为完成判断。
2. 沃拉尊货舱 air 分支已修，下一步只需进图确认货舱空军地图调用。
