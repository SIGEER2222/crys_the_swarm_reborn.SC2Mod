# 2026-05-31 凯瑞甘开发问题收口

## 当前现象

- 凯瑞甘的出生链已经能走到英雄本体，但实机表现仍然不稳定，核心问题不是“没进图”，而是“进图后拿到的英雄内容不完整或不一致”。
- 英雄卡片、单位形态、技能按钮和实际可用能力之间存在错位，表现上像是用了混杂来源拼出来的半成品，而不是单一确定版本。
- 跳虫/迅猛虫这类共享虫族模板还混入了不该出现的变异入口，导致错误按钮继续出现在实机里。
- 当前问题更像“数据源叠加”和“共享模板污染”，不是单个字段漏填。

## 主要判断

- 凯瑞甘相关定义被拆成了多段，部分内容像是官方风格、部分像是旧线或别的分支，最后落到同一个英雄上时产生了覆盖和缺失。
- 只检查表面存在性不够，必须确认“这个技能在图里能不能点、点了有没有效果、形态有没有切对、卡片是不是对的”。
- 共享单位模板如果不做隔离，别的指挥官的变异/进化按钮很容易串到凯瑞甘线上。

## 改进方案

1. 先把凯瑞甘收敛成单一英雄主线，避免同名定义叠加出多个版本。
2. 把凯瑞甘专属技能、形态、头像和状态框统一到同一套来源，确保卡片、模型、可用按钮一致。
3. 把跳虫/迅猛虫这类共享模板上的错误变异入口清掉，只保留该指挥官真正需要的入口。
4. 把验证标准从“数据存在”升级成“实机可点、可放、有效果”，否则很容易继续误判。
5. 后续所有改动优先按“一个问题一个收口”推进，先稳定凯瑞甘，再考虑其他指挥官的同类问题。

## 交付边界

- 这份记录只作为凯瑞甘问题收口，不再扩展到其他线。
- 后续若继续修，优先沿“单一英雄定义 + 共享模板隔离 + 实机验证”这条思路推进。
