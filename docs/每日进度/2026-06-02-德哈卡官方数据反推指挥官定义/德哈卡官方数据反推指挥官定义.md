# 从官方德哈卡数据反推 Mod 指挥官定义

日期：2026-06-02

## 结论

官方数据基本可以反推出一个合作指挥官 Mod 应该如何定义。德哈卡是一个很好的样例：官方数据能给出指挥官身份、英雄、全局面板单位、默认升级、威望、皮肤、单位 roster、建筑 roster、按钮面板、生产链路、技能和效果闭包。

需要注意的是，官方数据只能告诉我们“玩法事实”和“Catalog 链路”，不能直接告诉我们当前工程里应该把内容放在 `XMFinal.SC2Mod` 还是 `XMDehaka.SC2Mod`。模块归属、runtime hook、launcher/bank/测试台这些是本 Mod 框架自己的工程决策。

建议原则：

- 官方数据作为事实源。
- `XMFinal.SC2Mod` 只保留统一注册、runtime hook、测试台和共享框架。
- 指挥官私有的 `UnitData/AbilData/ButtonData/EffectData/ActorData/UpgradeData/RequirementData` 应尽量放入对应 commander module，例如 `XMDehaka.SC2Mod`。


## 工蜂建造链与建筑产出链

基础农民能变成什么建筑、建筑能生产什么单位，都可以从官方数据看出来，而且适合自动化抽取。

这类信息不能只看一个文件，应按下面的闭包追：

```text
UnitData 的 AbilArray
-> CommandCard 暴露的 AbilCmd
-> AbilData 中 AbilCmd 对应的 Build/Train/Effect
-> 如果产物是蛋、茧、临时单位或召唤占位，再递归追它自己的 Ability/Effect
```


需要额外注意：

- 有些单位是建筑直接 `CAbilTrain` 出最终单位。
- 有些单位像德哈卡一样先出蛋，再由蛋 morph 成最终单位。
- 有些 topbar 或召唤单位走 `CAbilEffectTarget -> EffectData -> CreateUnit`。
- 一个按钮是否显示或可用，还要继续追 `RequirementData`、等级解锁、科技升级和威望升级。
- 因此，生产关系的权威判断应以 raw XML 闭包为准，结构化 `commanders/<Commander>/*.json` 更适合作为快速入口和校验表。

## 从官方数据生成 Mod 定义的推荐流程

第一步：生成 `CommanderData.xml`。

```xml
<CCommander id="Dehaka">
    <UserReference value="PlayerCommanders;ZergDehaka"/>
</CCommander>
```

第二步：生成或覆盖 `PlayerCommanders/ZergDehaka`。

```text
HeroUnit = DehakaCoop
HeroReviveUnit = DehakaCoopReviveCocoon
GlobalCastUnit = CoopCasterDehaka
CommanderSkin = DehakaPrimal
DefaultUpgrades = DehakaCommander, SwarmHostFakeWeapon
Prestige = CommanderPrestigeDehakaDevour, CommanderPrestigeDehakaPackLeaders, CommanderPrestigeDehakaClone
```

第三步：建立 runtime module registry。

```text
OfficialCommander = Dehaka
RuntimeCommander = Dehaka
RuntimeModule = XMDehaka.SC2Mod
OfficialId -> RuntimeUnit
```

第四步：从 `heroes.json/buildings.json/units.json` 生成或校验 `UnitData.xml`。

第五步：从 `command_cards.json` 生成或校验 `ButtonData.xml` 和每个单位的 `CardLayouts`。

第六步：从 `abil_cmd` 和 `production_options` 生成或校验 `AbilData.xml`。

第七步：从 raw XML 追 `Ability -> Effect -> CreateUnit/ApplyBehavior/LaunchMissile/Damage/Search` 闭包，补齐 `EffectData.xml`。

第八步：从 `requirements/progression/upgrades/prestiges` 生成或校验 `RequirementData.xml`、`UpgradeData.xml`、威望和等级解锁。

第九步：如果目标 Mod 不直接依赖官方数据，则继续从官方 raw XML 追 `ActorData/ModelData/SoundData` 闭包并复制必要资源引用。
