# 2026-06-02 阿巴瑟生物质链复核

这次复核的核心不是“生物质有没有做”，而是“为什么实机里看起来只剩生命加成、宿主小蝗虫也没吃到”。我把 `XMAbathurReborn`、`XMFinal` 和官方镜像又对了一遍，并把当前源目录同步到 live 目录了。

## 一、先确认的事实

- `BiomassBuff1 / BiomassBuff10 / BiomassBuff100` 不是只加生命。
- 当前源数据里，这三个 buff 都包含：
  - 攻速加成
  - 生命上限加成
  - 能量回复加成
  - `AbathurRebornPropArmor` 属性点数变化
- 对照官方镜像后，当前实现和官方生物质 buff 结构是一致的，问题不在 buff 数值本体。
- 这次又复核了小蝗虫 biomass 传递的 `LaunchUnit`。旧阿巴瑟线里这三条 transfer 用的是 `Source`，当前已把误改回来的 `Caster` 再撤掉，恢复成 `Source`。

## 二、宿主小蝗虫的问题点

- 宿主小蝗虫的关键不在 `BiomassBuff` 本体，而在创建链。
- 经过复核，`XMFinal` 里的通用小蝗虫创建集已经补上了：
  - `AbathurBiomassLocust100Transfer`
  - `AbathurBiomassLocust10Transfer`
  - `AbathurBiomassLocust1Transfer`
- 这三条 transfer 已经接到：
  - `LocustCreateSetA`
  - `LocustCreateSetB`
- `XMAbathurReborn` 里的阿巴瑟专用创建集也已经补同样的 transfer。
- 这次又补了一处更细的差异：`XMAbathurReborn` 的 `AbathurRebornLocustCreateSetA/B/C` 已回到只保留
  - `AbathurRebornBiomassLocust100Transfer`
  - `AbathurRebornBiomassLocust10Transfer`
  - `AbathurRebornBiomassLocust1Transfer`
  的基础转移链，不再把 `PlusLife` 版本挂进主创建集。

## 三、触发链补充

- `BiomassPickup` 这条链不是单纯一个 data effect 就完事，实际是 trigger 驱动。
- 当前代码里可以看到：
  - `BiomassPickupDummy` 作为效果入口
  - `AbathurBiomassPickup` trigger 监听 `BiomassPickupDummy`
  - `AbathurBiomassTrain` 会把训练完成单位的 biomass 传给目标单位
  - `AbathurBiomassScaler` 会随着 `BiomassBuff1 / 10 / 100` 的变化刷新外观

## 四、已经做的动作

- 已把以下目录同步到 live：
  - `XMFinal.SC2Mod`
  - `XMAbathurReborn.SC2Mod`
  - `XMAbathur.SC2Mod`
- 同步时没有改 `DocumentHeader` / `DocumentInfo`。

## 五、当前还要继续盯的点

- 如果进图后还是只看到生命变化，要优先怀疑：
  - live 侧是否真的加载了这次同步
  - 当前测试时实际走的是不是这套 `XMFinal`
  - 还有没有别的 mod 或旧缓存覆盖了当前链路
- 需要下一轮做的最小验证是只测阿巴瑟生物质，不要一次拉太多指挥官一起混测。
- 这次新确认的根因是：`SetUnitFullBiomass` 会把生命直接回满，所以“只看到生命变化”不等于 biomass buff 真正生效；真正该盯的是那三条 `TransferBehavior` 是否用对了宿主上下文。
- 另外，如果进图后还是只能看到生命变化，下一步就要优先怀疑 live 侧加载的是旧缓存，或者还有别的模组覆盖了当前链路。

- 这轮实测反馈说明：`PlusLife` 不能作为阿巴瑟主加成链的永久挂载项，否则表现会偏向“只看见生命变化”。
- 现在已把 `XMFinal` 和 `XMAbathurReborn` 的主加成链收回到基础版：
  - `AbathurAddBiomassStacks` 重新使用 `BiomassBuff100 / BiomassBuff10 / BiomassBuff1`
  - 计数回到只按基础 buff 统计

- 下一步只需要做一次针对阿巴瑟生物质和宿主小蝗虫的实机回归，确认回到基础 buff 后，攻击/攻速/能量/属性与继承都正常。

## 2026-06-02 继续修正

- 进一步定位到实机里“只有生命涨”的直接原因之一，是 `XMFinal` 里的 `Locust` / `AbathurLocust` / `LocustMP` 没有和源模组对齐，缺少关键的 `AbathurPropArmor`，部分单位还少了 `TriggerInheritsParentBuffs` / `AllUnitBehaviorController`。
- 这会让生物质的属性点数和继承链断掉，所以看起来就像只剩生命在变化。
- 这次已经把这几个 locust 单位按源数据补回，并把 `XMFinal` 里多出来的 `AbathurBiomassLocust*PlusLifeTransfer` 清掉，回到和源模组一致的基础转移链。
- 这次还把 `XMFinal` 里阿巴瑟的开局编队和运输舱重新切回 `AbathurCreateUnitsWithFullBiomass` / `AbathurCargoCreateWithFullBiomass`，避免测试时把“满生物质”误降级成普通创建。
- 下一轮如果还异常，就只需要盯实机日志里 locust 的创建单位 id 和行为计数，不用再怀疑主 buff 本体。

## 2026-06-02 再修正
