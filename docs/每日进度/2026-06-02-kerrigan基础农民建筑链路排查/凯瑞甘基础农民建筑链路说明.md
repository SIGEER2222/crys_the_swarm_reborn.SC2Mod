# 凯瑞甘基础农民与建筑链路私有化说明

## 结论

凯瑞甘的基础经济链路应当独立。否则多个虫族/跨种族指挥官在同一个 Mod 运行环境里共用 `Drone`、`ZergBuild`、`Hatchery`、`SpawningPool`、`NydusNetwork` 这类 Catalog ID 时，后续给某个指挥官加按钮、需求、产出或形态变换，都会有机会污染其他指挥官。

本轮已完成第一阶段私有化：

- 开局工蜂从共享 `Drone` 切到 `DroneKerrigan`。
- 工蜂建造能力从共享 `ZergBuild` 切到 `ZergBuildKerrigan`。
- 工蜂可变形出的基础/科技/防御建筑切到凯瑞甘私有建筑 ID。
- 主基地升级链切到 `HatcheryKerrigan -> LairKerrigan -> HiveKerrigan`。
- 大螺旋塔升级链切到 `SpireKerrigan -> GreaterSpireKerrigan`。
- 坑道网络召唤链切到 `NydusNetworkKerrigan -> BuildNydusCanalKerrigan -> NydusCanalKerrigan`。
- 地刺/孢子拔根扎根链切到凯瑞甘私有 uprooted/root 形态。
- `XMFinal` runtime roster、建筑测试名册和 ability smoke 已同步这些私有 ID。

当前仍不能称为“凯瑞甘完整玩法全部闭环”，因为幼虫生成/幼虫训练、皇后训练、所有作战单位正式私有 ID、建筑研究面板继承清理还没有完整迁移。

## 仍未闭合的部分

这些不是遗漏，而是下一阶段要继续做的链路：

1. 幼虫生成与幼虫训练

当前仍没有 `LarvaKerrigan` / `LarvaTrainKerrigan`。现有 `Larva` 面板仍通过 `LarvaTrainSwarmling` / `LarvaTrain` 产出 `HotSRaptor`、`Hydralisk`、`Mutalisk`、`Ultralisk`。要完全私有化，需要追 `HatcheryLarvaDeath`、`SpawnLarva` behavior/effect 以及幼虫出生单位 ID。

2. 皇后训练

当前主基地继承链里仍能看到 `TrainQueen -> QueenCoop`。如果要避免共享 `QueenCoop` 影响其他虫族指挥官，应补 `TrainQueenKerrigan` 和正式的 `QueenKerrigan` 或保留明确 alias。

3. 作战单位正式 ID

凯瑞甘当前作战单位仍使用不少共享 ID 或 alias，例如 `Hydralisk`、`Ultralisk`、`MutaliskBroodlord`、`HotSRaptor`。这和本轮“基础农民/建筑链路”不同，属于下一层单位私有化。

4. 建筑研究面板

`SpawningPoolKerrigan`、`HydraliskDenKerrigan`、`EvolutionChamberKerrigan`、`UltraliskCavernKerrigan` 等当前先通过 parent 继承现有凯瑞甘/虫族面板。后续要把研究 ability、requirement、passive 按凯瑞甘私有 ID 逐个复制/改名，避免共享研究按钮污染。

5. 私有 requirement

本轮新建的部分按钮使用 `State="Available"` 或继承旧 requirement。下一阶段应补 `HaveSpawningPoolKerrigan`、`HaveHiveKerrigan` 等私有 requirement，避免需求检查继续落在共享建筑 ID 上。

6. 运行时实测

本轮完成的是 Catalog 静态闭包和 XML/Galaxy 静态验证，没有 SC2 客户端内实测。需要进测试图确认出生、建造、变形、扎根、坑道召唤的视觉和实际单位 ID。
