# 合作指挥官建筑单位逐个对比：修复优先级与排查入口

- 生成依据：`commander-unit-building-wiki-vs-active-mod.md`
- 明细目录：`by-commander/`
- 对比脚本：`scripts/sc2/compare-wiki-commander-roster-vs-active-mod.mjs`
- 当前实现目标：`合作指挥官版起义狂潮`

## 当前结论

本轮已完成 18 个官方合作指挥官的建筑/单位名册三方对比：

1. wiki `主要部队` 作为中文真实名单。
2. `游戏数据/官方合作指挥官/commanders/<Commander>/` 作为 ID、生命、护盾、人口、费用、生产/变形链来源。
3. `合作指挥官版起义狂潮/Mods/XM/<Commander>.SC2Mod` 加 `XMCore/XMFinal` 作为当前 active Mod 静态命中对象。

当前所有 wiki 主要部队都已经映射到官方 JSON 或补充 ID，没有剩余“中文名完全对不上”的空洞。剩余问题主要是两类：

- `仅文本/引用命中`：XML/Galaxy 里出现过该 ID，但本扫描范围没有同 ID `CUnit` 定义。可能是依赖外部 Catalog，也可能是当前指挥官模块没有真正落单位。
- `生产链异常`：单位 `CUnit` 已有，但训练/建造/变形技能没有在当前扫描范围闭合。

## 下一步建议

先按“凯瑞甘 -> 斯托科夫 -> 斯旺 -> 霍纳与汉 -> 扎加拉”的顺序进入 XML 修复。每个指挥官修复时按这个顺序查：

1. `UnitData.xml` 是否有目标 `CUnit`。
2. 生产者 `CUnit` 是否存在。
3. `AbilArray` / `CardLayouts` 是否挂了训练、建造、变形技能。
4. `AbilityData.xml` 或同目录其他 XML 是否定义该技能。
5. 如果当前 active 线使用旧 ID，优先补脚本别名和报告说明；只有确认没有等价实现时再补 Catalog。
