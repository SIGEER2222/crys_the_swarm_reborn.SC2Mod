# 凯瑞甘独立训练链样板修复清单

## 当前结论

当前 `合作指挥官版起义狂潮/Mods/XM/XMKerrigan.SC2Mod` 不是“少改几个按钮”，而是整套虫族基地/幼虫训练链仍在复用一套被污染的共享底座。

已确认：

- `Hatchery/Lair/Hive` 命令卡仍是共享虫族底座，包含 `TrainQueen`、`RespawnZergling`、`K5TwoDrones` 等混杂按钮。
- `Larva` 命令卡直接暴露大量混杂条目：`Hydralisk`、`Ultralisk`、`Corruptor`、`Viper`、`SwarmHostMP`、`Defiler`、`Scourge`、`QueenClassic`。
- `LarvaTrain` / `LarvaTrainSwarm` 存在多个空 `Unit value=""` 和明显跨指挥官/跨玩法产物。
- `LarvaTrainSwarmling` 当前仍为空产物，但旧文档说明 `UpgradeData.xml` 期望把它补成 `HotSSwarmling`。
- 文档证据已确认凯瑞甘静态核心链同时包含：`K5Kerrigan`、`HotSRaptor`、`HotSSwarmling`、`MorphZerglingToBaneling`、`ZerglingArmorShred`。

## 样板修复目标

先把凯瑞甘做成“独立训练链样板”，不要继续依赖共享虫族脏底座。

目标不是一次修完所有虫族指挥官，而是先让凯瑞甘满足：

1. 基地/幼虫面板只显示凯瑞甘需要的训练入口。
2. 训练能力只产出凯瑞甘自己的兵种或其变形分支。
3. 跳虫链不再落回普通 `Zergling` 作为最终状态。
4. 爆虫、刺蛇/潜伏者、异龙/巢虫领主、女王、雷兽这些核心链条都能从凯瑞甘自己的训练体系推出。

## 建议保留的凯瑞甘核心对象

优先以当前文档证据为准，保留这些对象进入独立链：

- 英雄：`K5Kerrigan`
- 跳虫链候选：`HotSRaptor`、`HotSSwarmling`
- 跳虫变形：`MorphZerglingToBaneling`
- 刺蛇/潜伏者链：`Hydralisk` 或 `HydraliskLurker`，以及对应潜伏者分支
- 女王：`QueenCoop`
- 雷兽：`Ultralisk`
- 空军：`Mutalisk`、巢虫领主分支
- 被动/升级证据：`ZerglingArmorShred`、`CoopSwarmlingRequirements`

## 当前必须清理的污染项

这些对象至少不该继续直接出现在凯瑞甘幼虫主训练面板上：

- `SwarmHostMP`
- `Defiler` / `DefilerMP`
- `Scourge`
- `QueenClassic`
- `Brutalisk`
- `Viper`
- `Corruptor`
- `DehakaHatcheryTrainEgg`

其中 `DehakaHatcheryTrainEgg` 出现在 `XMKerrigan.SC2Mod/AbilData.xml`，属于明确污染证据。

## 先修对象顺序

建议按这个顺序改，避免一上来全量重写：

1. `LarvaTrainSwarmling`
- 明确 `Train1` 最终产物到底取 `HotSSwarmling` 还是别的凯瑞甘跳虫对象。
- 这一步决定凯瑞甘跳虫主链的最终对象。

2. `Larva` 命令卡
- 删除明显不属于凯瑞甘的训练按钮。
- 只保留凯瑞甘需要的主训练入口和变形入口。

3. `LarvaTrain` / `LarvaTrainSwarm`
- 把空 `Unit value=""` 补齐。
- 去掉 `DefilerMP`、`Scourge`、`Brutalisk`、`QueenClassic` 这类污染产物。
- 把训练索引重新对齐到凯瑞甘所需对象。

4. `Hatchery/Lair/Hive`
- 保留升本、集结、女王、菌毯瘤等合理能力。
- 删除或替换和凯瑞甘无关的共享脏按钮。

5. `XMFinal` helper
- 训练链稳定后，再决定 `KerriganCreateMapStartSquad` / `KerriganCreateCargoSquad` 里轻型单位到底改成 `HotSRaptor` 还是 `HotSSwarmling`。
- 这一步不该先于数据层清理。

## 当前关键未决点

最需要先定的是：凯瑞甘跳虫主链到底应该以哪个对象作为最终训练结果。

目前存在两套证据：

- `HotSRaptor`：文档把它列为凯瑞甘核心对象，且带 `ZerglingArmorShred` 被动证据。
- `HotSSwarmling`：文档也明确写到 `LarvaTrainSwarmling` 最终会被 upgrade patch 指向 `HotSSwarmling`。

因此后续修复时需要先决定：

- 是把凯瑞甘最终幼虫训练结果统一成 `HotSSwarmling`
- 还是保留 `HotSRaptor` 作为凯瑞甘主跳虫，而把 `HotSSwarmling` 视作旧 patch 残留或另一条链

这一步不定，后面 `XMFinal` 开局 helper 和数据训练链会继续打架。

## 本阶段产出

- 已确认凯瑞甘不是单点问题，而是共享虫族训练底座污染。
- 已把“样板修复”需要先动的对象和污染项列清。
- 下一步应进入实际 XML 清理，而不是继续泛查全仓。
