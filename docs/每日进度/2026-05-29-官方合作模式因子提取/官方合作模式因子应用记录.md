## 重要边界

这一步是把合作模式因子的官方数据表应用进 Mod，解决的是“因子元数据、组合、中文显示文本可被 Mod 读取”的问题。

当前还不能视为所有因子效果都已经可运行，原因是：

- `XMMutator.SC2Mod` 目前仍有部分突变相关 Catalog 和 Amon 英雄 AI 函数，但官方合作因子新 runtime owner 已拆为 `XMCoopMutators.SC2Mod`。
- 官方核心运行时 `libCOMU` 的完整启用、注册、触发器闭包尚未全量迁移到 `XMCoopMutators.SC2Mod`。
- `LauncherAuto.SC2Map` 的 `TriggerStrings.txt` 中能看到官方 `COMU` / `COUI` 文本，但当前地图脚本和 `XMMutator.SC2Mod` 中没有完整 `libCOMU` 实现。
- 当前环境没有 SC2，黑死病只做了静态验证，尚未在编辑器或游戏内验证行为实际触发。

## 后续推进建议

1. 继续在 `原始mod/Mods/XM/XMCoopMutators.SC2Mod` 中把官方 `libCOMU` 按职责拆分迁入，不要直接塞一个 14000 行大文件。
2. 优先迁移低依赖、易验证的因子：
   - 黑死病 `Plague`
   - 自毁程序 `DeathAOE`
   - 异形寄生 `SpawnBroodlings`
   - 行尸走肉 `WalkingInfested`
   - 速度狂魔 `UnitSpeed`
3. 每迁一个因子，补一条静态校验：
   - `Mutators` 中有实例。
   - 中文名/说明存在。
   - 初始化函数存在。
   - 初始化函数已注册。
   - 启用入口能调用到该初始化函数。
4. 再处理依赖地图目标、攻击波、资源点、玩家镜头或 UI 的高耦合因子。
