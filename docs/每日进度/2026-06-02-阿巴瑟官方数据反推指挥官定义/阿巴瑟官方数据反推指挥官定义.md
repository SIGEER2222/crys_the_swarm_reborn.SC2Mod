# 从官方阿巴瑟数据反推 Mod 指挥官定义

日期：2026-06-02

## 结论

官方数据可以反推出阿巴瑟合作指挥官的主体定义，但阿巴瑟和德哈卡的形态差异很大：

- 德哈卡是英雄型指挥官，官方入口直接给 `HeroUnit`、复活行为和英雄 roster。
- 阿巴瑟不是英雄型指挥官，`PlayerCommanders/ZergAbathur` 没有 `HeroUnit`，核心入口是 `GlobalCastUnit = CoopCasterAbathur`、默认升级、默认能力命令、普通虫族生产链、生物质、终极进化、共生体和剧毒巢穴。
- 官方结构化目录中，阿巴瑟 `heroes.json` 为空，`units.json` 有 12 个兵种，`buildings.json` 只有 2 个静态防御建筑。
- 本轮 raw XML 检索没有在官方原始镜像中找到 `HatcheryAbathur`、`DroneAbathur`、`OverlordAbathur` 这类官方 catalog 单位。当前工程里的 `HatcheryAbathur` 更像本 Mod 的运行时基地壳体或映射，不应当写成官方事实。

建议原则：

- 官方数据作为事实源。
- `XMFinal.SC2Mod` 只保留统一注册、runtime hook、测试台和共享框架。
- 阿巴瑟私有的 `UnitData/AbilData/ButtonData/EffectData/BehaviorData/UpgradeData/RequirementData/ActorData` 应尽量放在 `XMAbathur.SC2Mod`。
- 当前工程里的 `HatcheryAbathur`、`DroneAbathur`、`OverlordAbathur`、`CommanderAch/Abathur` 只能当作当前 Mod 工程映射，不能反推为官方原始对象。

### 工蜂 ID 和工蜂可变异建筑

官方工蜂单位 ID：

```text
Drone
```

不是：

```text
DroneAbathur
```

### 生物质吸收后的实际加成和状态变化（施工闭包）

结论：官方阿巴瑟的生物质不是“捡到后只加一个计数”。真正生效链条是：

```text
敌方单位死亡
-> CM_Abathur_BiomassDrop 计算掉落数量
-> 创建 BiomassPickup 单位
-> custom value 63 写入该掉落物含有的生物质量
-> BiomassPickup / BiomassPickupMarked 自动拾取
-> BiomassPickupDummy 触发 CM_Abathur_BiomassPickup
-> 拆成 BiomassBuff100 / BiomassBuff10 / BiomassBuff1
-> 目标单位获得生命、攻速、能量恢复、护甲属性点、体型/视觉变化
-> 达到 10/100 时自动折叠层级
-> 死亡时按 AbathurBiomassRefundDummy.Amount 随机返还掉落物
```

施工时必须闭合上面整条链；只做 `BiomassPickup` 单位或只做拾取按钮，会变成“能吸收但没有实际效果”。

#### 1. 掉落物生成和数量写入

普通敌人死亡触发器是 `CM_Abathur_BiomassDrop`：

- 入口：`libcomi.galaxy:15189`，事件是 `TriggerAddEventUnitDied`。
- 条件：击杀者有效、死亡单位不是 `NoBiomassDrop`、不是 remove death、不是突变因子生成单位、击杀者阵营里存在 `ZergAbathur`。
- 掉落数量：读取死亡单位 `Unit.Food`，按难度倍率计算，普通/休闲 `2.5`，困难 `2.0`，残酷 `1.25`；小动物/特殊低补给、混合体等有分支值。
- 剧毒巢穴：若阿巴瑟已完成 `AbathurToxicNestIcreasedBiomass`，且死亡单位有 `ToxicNestVirulentNest`，则 `lv_biomassToxicNestMultiplier = 1.5`，即受到剧毒巢穴影响的敌人额外掉落 50% 生物质。
- 双倍生物质精通：若完成 `MasteryAbathurDoubleBiomass` 且随机数命中 `MasteryAbathurDoubleBiomassDisplayDummy.Amount`，则掉落倍率改为 `2.0`。`MasteryAbathurDoubleBiomassDisplayDummy.Amount` 由精通每点 `+1.5%` 写入，不只是 tooltip。
- 创建掉落物：生成 `BiomassPickup`，调用 `CM_Abathur_BiomassSetStack` 把数量写进该单位 `custom value 63`，同时写入信息提示文本，然后 `CM_Abathur_BiomassScale` 调整掉落物模型大小，`CM_Abathur_BiomassMerge` 合并 4 范围内其他生物质团。

#### 3. 拾取后如何变成单位 Buff

`BiomassPickup` / `BiomassPickupMarked` 的数据效果只把 `BiomassPickupDummy` 打出来；真正把掉落物数量转成单位 Buff 的是触发器 `CM_Abathur_BiomassPickup`：

- 入口：`libcomi.galaxy:15316`，事件是 `TriggerAddEventPlayerEffectUsed(..., "BiomassPickupDummy")`。
- 读取掉落物：从 caster 的 `custom value 63` 取 `lv_biomassCountStored`。
- 读取目标当前层数：`BiomassBuff100 * 100 + BiomassBuff10 * 10 + BiomassBuff1`。
- 读取上限：`AbathurBiomassMaxStacksDummy.Amount`，默认 `100`。
- 若拾取后超过上限：只给目标补到上限，剩余数量写回掉落物并重新缩放；目标加 `BiomassMaxedMarker`。
- 若未超过上限：掉落物加 `BiomassTravelling`，发射 `BiomassPickupFullLM` 到目标。
- 实际加 Buff：按数量拆成 `100/10/1` 三档，给目标加 `BiomassBuff100PlusLife`、`BiomassBuff10PlusLife`、`BiomassBuff1`。

`BiomassBuff10PlusLife` 与 `BiomassBuff100PlusLife` 是触发器转移用的短时辅助 Buff，`Duration=0.03`，注释写明“used for the trigger transfer, so when it happens the units will heal”。它们用于让单位在吃到 10/100 档生物质时当前生命值也跟上最大生命变化；短时结束/周期效果后，长期效果仍归入正常的 `BiomassBuff10` / `BiomassBuff100` 档。

#### 4. 三档 Buff 的实际属性

长期加成来自 `BiomassBuff1`、`BiomassBuff10`、`BiomassBuff100` 三个隐藏 Buff。三档不是三个不同设计倍率，而是为了减少层数和支持 10/100 折叠。

| Buff | 含义 | 每个 Buff stack 的长期属性 | 最大层数 |
| --- | --- | --- | --- |
| `BiomassBuff1` | 1 点生物质 | 攻速 `+0.01`，最大生命 `+0.03`，能量恢复 `+0.05`，`AbathurPropArmor +1 point` | `120` |
| `BiomassBuff10` | 10 点生物质 | 半径 `x1.025`，攻速 `+0.1`，最大生命 `+0.3`，能量恢复 `+0.5`，`AbathurPropArmor +10 point` | `20` |
| `BiomassBuff100` | 100 点生物质 | 半径 `x1.25`，攻速 `+1.0`，最大生命 `+3.0`，能量恢复 `+5.0`，`AbathurPropArmor +100 point` | `2` |

换成玩家可读效果：

- 每 1 点生物质约等于 `+1%` 攻速、`+3%` 最大生命、`+5%` 能量恢复。
- 护甲不是直接 `+1 armor`。`BiomassBuff*` 增加的是 `AbathurPropArmor` 属性点；`AbathurPropArmor` 每点 `LifeArmorBonus=0.05`，所以默认每 1 点生物质折算约 `+0.05` 护甲，100 点约 `+5` 护甲。
- 能量恢复只对有能量的单位有意义；没有能量条的单位仍会获得生命/攻速/护甲属性。
- 体型变化不只靠 Buff 的 `RadiusMultiplier`，`CM_Abathur_BiomassScaler` 还会在 Buff 增加时按总生物质量给目标发 `SetScale` 和 `BiomassAnimGroupA/B/C` actor 信号。

## 从官方数据生成 Mod 定义的推荐流程

第一步：生成或校验 `CommanderData.xml`。

```xml
<CCommander id="Abathur">
    <UserReference value="PlayerCommanders;ZergAbathur"/>
</CCommander>
```

第二步：生成或覆盖 `PlayerCommanders/ZergAbathur`。

```text
GlobalCastUnit = CoopCasterAbathur
CommanderData = Abathur
DefaultUpgrades = AbathurCommander
DefaultAbilityCommands =
  MutaliskMorphToDevourer
  MutaliskMorphToGuardian
  TrainQueen
  MorphRoachToRavager
  SpireResearch,6
  MorphRoachVileToRavager
Prestige =
  CommanderPrestigeAbathurBiomass
  CommanderPrestigeAbathurDeepTunnel
  CommanderPrestigeAbathurUltimateEvo
```

第三步：建立 runtime module registry。

```text
OfficialCommander = Abathur
RuntimeCommander = Abathur
RuntimeModule = XMAbathur.SC2Mod
OfficialId -> RuntimeUnit
```

第四步：从 `units.json/buildings.json` 生成或校验 `UnitData.xml`。

第五步：从 `command_cards.json` 和 raw `CoopCasterAbathur` 生成或校验 `ButtonData.xml`、`CardLayouts` 和 panel profile。

第六步：从 `production_options` 与 raw `AbilData.xml` 生成或校验：

```text
ZergBuild
LarvaTrain
TrainQueen
MutaliskMorphToGuardian
MutaliskMorphToDevourer
MorphRoachToRavager
MorphRoachVileToRavager
EvolveToBrutalisk*
EvolveToLeviathan*
AbathurDeepTunnel*
SpawnToxicNest
AbathurMend
BiomassTargetMark
BiomassPickup*
AbathurSymbioteHanger*
```

第七步：从 raw XML 追 `Ability -> Effect -> Behavior/ModifyUnit/CreateUnit/LaunchMissile/Teleport/Damage/Search` 闭包，补齐 `EffectData.xml` 和 `BehaviorData.xml`。

第八步：从 `progression/upgrades/prestiges` 生成或校验等级、精通、威望、Requirement 与 Upgrade。

第九步：如果目标 Mod 不直接依赖官方数据，则继续从官方 raw XML 追 `ActorData/ModelData/SoundData` 闭包并复制必要资源引用。

- `HatcheryAbathur`、`DroneAbathur`、`OverlordAbathur` 属于当前 Mod 映射，不是本轮官方 raw 事实。
- 当前 Mod 映射不等于专属开局实现；请把它当作 runtime alias，而不是“完全 bespoke”的开局依据。
