# 当前实际兵种建筑落地对比

日期：`2026-05-25`

## 口径

- 当前侧只读取 `合作指挥官版起义狂潮/Mods/XM/XM*.SC2Mod` 里的实际文件。
- 参考侧主要取 `docs/维基指挥官/兵种/all_commanders_data.json`；阿拉纳克因维基 JSON 缺失，临时取 `docs/指挥官威望/阿拉纳克.md` 的主要战斗单位。
- “本地 starcoop 导出候选”来自仓库已有的 `references/official-casc-export/mods/starcoop/starcoop.sc2mod`，只作为本地导出数据对照；本轮没有从游戏运行时、战网或其它线上官方接口重新取数。
- 本轮没有进游戏验证，也没有修改 `XMFinal.SC2Mod/DocumentHeader` / `DocumentInfo`。
- `Abil生产/建造引用` 表示当前模块 `AbilData.xml` 有 `Unit="..."` 引用。
- `GameData创建/引用` 表示当前模块其它 `GameData/*.xml` 有 `Unit="..."` 引用，但不一定是训练按钮。
- `UnitData已定义` 表示当前模块定义了单位对象，但本轮未证明它已接入训练/建造链。
- `仅本地化命名` 表示只有中文名 key，未在当前模块找到对应 `UnitData` 或 `Unit="..."` 引用。

## 当前判断

1. 如果目标是“当前目录里有没有实际做进来”，那么大部分指挥官的主条目已经不是纯文本，至少有 `UnitData` 或 `Unit="..."` 引用证据。
2. 真正一眼能看出的硬缺口集中在 `Karax`、`Zagara`、`Stukov`、`Swann`、`Vorazun`、`Zeratul`、`Alarak`。
3. `Zeratul` 的问题最特殊：6 个主力兵种只有本地化 key，没有当前模块对象或引用；另外 2 个建筑落到非本地 starcoop 导出候选 ID。
4. `Han & Horner / Mira` 和 `Swann` 大多不是缺对象，而是当前使用自定义 ID。是否要改成本地 starcoop 导出 ID，需要单独决定，不宜批量硬换。
5. `Alarak` 在当前扫描口径下缺口最大：参考的 8 个主战条目都没在 `XMAlarak.SC2Mod` 当前模块里以中文名、UnitData 或 Abil 引用命中。
