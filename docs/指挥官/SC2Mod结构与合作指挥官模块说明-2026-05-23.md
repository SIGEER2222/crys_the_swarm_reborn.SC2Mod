# SC2Mod 结构与合作指挥官模块说明

生成日期：2026-05-23

## 目的

本文说明本仓库中 `.SC2Mod` 解包目录的结构、指挥官模块的职责、公共模块之间的依赖关系，以及新增/完善合作指挥官时应如何组织数据。

## 主目录

```text
合作指挥官版起义狂潮/Mods/XM
```

## SC2Mod 解包目录常见结构

典型指挥官模块：

```text
XM<Commander>.SC2Mod
├─ DocumentHeader
├─ DocumentInfo
├─ GameData.version
├─ GameText.version
├─ Triggers.version
├─ PreloadAssetDB.txt
├─ Base.SC2Data
│  ├─ GameData
│  │  ├─ UnitData.xml
│  │  ├─ AbilData.xml
│  │  ├─ ButtonData.xml
│  │  ├─ EffectData.xml
│  │  ├─ BehaviorData.xml
│  │  ├─ UpgradeData.xml
│  │  ├─ RequirementData.xml
│  │  ├─ ValidatorData.xml
│  │  ├─ ActorData.xml
│  │  ├─ ModelData.xml
│  │  ├─ SoundData.xml
│  │  └─ UserData.xml
│  └─ Lib*.galaxy
└─ zhCN.SC2Data
   └─ LocalizedData
      └─ GameStrings.txt
```

不是每个模块都有所有文件；已有模块通常按实际需要裁剪。

## 关键 GameData 文件职责

| 文件 | 职责 |
|---|---|
| `UnitData.xml` | 单位、建筑、英雄、隐藏 caster、投射物 |
| `AbilData.xml` | 训练、建造、英雄技能、顶部技能、变形、复活 |
| `ButtonData.xml` | 命令卡按钮、图标、tooltip、锁定按钮 |
| `EffectData.xml` | 技能效果链、伤害、搜索、创建单位、set/switch |
| `BehaviorData.xml` | buff、光环、被动、叠层、持续效果 |
| `UpgradeData.xml` | 科技升级、等级解锁、威望、精通 |
| `RequirementData.xml` | 命令卡显示/隐藏/灰显条件 |
| `ValidatorData.xml` | 效果和 tooltip 条件判断 |
| `ActorData.xml` | 视觉 actor、模型绑定、事件响应 |
| `ModelData.xml` | 模型资源引用 |
| `SoundData.xml` | 声音资源引用 |
| `UserData.xml` | 指挥官等级、战役自定义数据、扩展表 |

## XMCore.SC2Mod 的关键职责

### CommanderAch

文件：

```text
XMCore.SC2Mod/Base.SC2Data/GameData/UserData.xml
```

`CommanderAch/<Commander>` 是标准基地初始化的核心数据源。

关键字段：

```text
CommandCenter
Worker
SecondUnit
CommanderIcon
Upg[]
Poi[]
```

标准基地图通过 `XMFinal` 读取这些字段来生成基地、工人和第二单位。

### 顶部面板框架

文件：

```text
XMCore.SC2Mod/Base.SC2Data/Lib67C0F0E7.galaxy
XMCore.SC2Mod/Base.SC2Data/Lib67C0F0E7_h.galaxy
XMCore.SC2Mod/Base.SC2Data/UI/Layout/Coop_GlobalCastingTemplates.SC2Layout
```

关键函数：

```galaxy
lib67C0F0E7_gf_CU_GPInit
lib67C0F0E7_gf_CU_GPShowHide
```

按指挥官分派：

```text
CU_GPInitDehaka
CU_GPInitAbathur
CU_GPInitKerrigan
CU_GPInitAlarak
...
```

顶部面板本质：

```text
Layout CommandPanel + 隐藏/全局 caster 单位的 CardLayouts
```

## XMFinal.SC2Mod 的关键职责

文件：

```text
XMFinal.SC2Mod/Base.SC2Data/LibE0EAE146.galaxy
```

职责：

1. 读取当前指挥官。
2. 设置控制台皮肤。
3. 读取 `CommanderAch`。
4. 创建标准基地。
5. 创建英雄或复活茧。
6. 创建顶部面板 caster。
7. 初始化指挥官特殊机制。

新增指挥官时，优先把运行时逻辑放在 `XMFinal`，不要散到每张地图。

## 指挥官模块导入原则

官方数据来源：

```text
references/official-casc-export/mods/starcoop/starcoop.sc2mod/base.sc2data/gamedata
```

不应直接使用：

```text
crys_the_swarm_reborn.SC2Mod
```

该模块可以参考，但不能作为直接来源。

## 已有官方导入脚本

| 脚本 | 目标 |
|---|---|
| `scripts/import-official-abathur-data.ps1` | 导入官方 Abathur 数据 |
| `scripts/import-official-kerrigan-data.ps1` | 导入官方 Kerrigan 数据 |
| `scripts/import-official-alarak-data.ps1` | 导入官方 Alarak 数据 |

| 脚本 | 目标 |

| `scripts/validate-kerrigan-port.ps1` | 检查 Kerrigan 接入 |
| `scripts/validate-kerrigan-tech-chain.ps1` | 检查 Kerrigan 科技链 |
| `scripts/validate-alarak-port.ps1` | 检查 Alarak 接入 |


## 新增指挥官标准流程

1. 建立验证脚本，让它先失败。
2. 新建或启用 `XM<Commander>.SC2Mod`。
3. 从官方 `starcoop` 导入数据。
4. 在 `XMCore CommanderAch` 注册基地、工人、第二单位、升级、精通。
5. 在 `LauncherAuto CommanderPreset` 追加候选。
6. 在 `XMFinal` 添加标准初始化分支。
7. 如果有顶部面板，补 `XMCore` 面板初始化。
8. 补关键地图分支。
9. 跑 port 验证和 tech-chain 验证。
10. 更新 `docs/指挥官/<Commander>移植进度-日期.md`。

## 完成标准

不能只算“名字进了 Launcher”。至少要满足：

1. 指挥官模块存在且关键 catalog 对象导入。
2. `CommanderAch` 注册。
3. `XMFinal` 能标准初始化。
4. 关键地图有分支。
5. 验证脚本通过。
6. 进度文档写明已完成和风险。

## 当前备注

`Kerrigan` 和 `Alarak` 已经有模块和验证脚本，但 `LauncherAuto` 候选数据曾出现回退。后续新增指挥官时，必须把 Launcher 候选检查加入验证脚本，并以验证脚本结果为准。
