# 当前架构与接入原则

日期：2026-05-22

这份文档替代原先两份重复的“战役中接入指挥官方向”说明，也吸收了一部分阶段经验，但只保留当前仍成立的口径。

## 核心结论

指挥官移植到战役里，正确目标不是“把合作模式依赖直接塞进地图”，而是：

1. 官方或可靠来源的数据进入独立指挥官模组。
2. 战役运行时逻辑统一收口到 `XMFinal.SC2Mod`。
3. 地图只依赖 `XMFinal.SC2Mod`，只保留 mission-specific 分支。
4. Launcher 只负责选择入口和 Bank 写入，不负责玩法逻辑。

对阿巴瑟尤其要继续坚持：

- `crys_the_swarm_reborn.SC2Mod` 只能参考 XML / Galaxy 写法。
- 不能把它当对象、数值、触发、文案或素材来源。

## 推荐分层

### 1. 指挥官数据层

每个指挥官独立一个 `XM*.SC2Mod`，例如：

- `XMAbathur.SC2Mod`
- `XMKerrigan.SC2Mod`

这里承载：

- `UnitData`
- `AbilData`
- `ButtonData`
- `BehaviorData`
- `EffectData`
- `RequirementData`
- `UpgradeData`
- `ValidatorData`
- `ActorData`
- `ModelData`
- `SoundData`
- `WeaponData`
- `GameStrings`

这一层只解决“对象存在且依赖闭环”。

### 2. 公共核心层

`XMCore.SC2Mod` 负责公共 UI、面板模板、`CommanderAch` 和通用分发逻辑。

这里应该放：

- `CommanderAch/<Commander>`
- `CU_GPInit<Commander>`
- 指挥官标题、描述、巅峰文本
- 公共顶部面板模板和路由

### 3. 战役运行时层

`XMFinal.SC2Mod` 是指挥官在战役中的唯一 runtime owner。

这里负责：

- 读取 `CampaignXCore.SC2Bank`
- 开局基地/工人/初始人口单位
- `CoopCaster<Commander>` 创建
- 顶部面板初始化
- 成长和升级发放
- 生物质、英雄、地图 helper 等运行时触发
- 与任务脚本、Bank、特殊地图分支接线

一个直接判断标准是：通用玩法逻辑不应同时散落在 `XMFinal`、指挥官子模组和地图脚本三处。

### 4. 地图层

地图层只做：

- 自己的 mission trigger
- 自己的奖励/运输/无基地/阵容替换分支
- 调用统一 helper

不应该在每张地图里重写整套指挥官实现。

## 依赖链要求

当前应保持：

1. 地图依赖 `XMFinal.SC2Mod`
2. `XMFinal.SC2Mod` 依赖 `XMCore.SC2Mod`
3. `XMFinal.SC2Mod` 再依赖具体指挥官模组

例如当前仓内已经存在：

- `XMFinal -> XMAbathur`
- `XMFinal -> XMKerrigan`

如果只把名字接进 Launcher，而没有把指挥官模组接入 `XMFinal`，就会出现“能选、能写 Bank、但单位和技能找不到”的假阳性。

## Launcher 的职责边界

Launcher 只应该承载：

- 候选列表
- 头像和标题
- 文案
- `CommanderPreset`
- `CampaignXCore.SC2Bank` 写入

Launcher 能显示指挥官，不代表：

- 数据已加载
- 标准基地图能开局
- 英雄或小队会创建
- 顶部技能面板可用

## 地图适配的正确做法

优先复用统一 helper，例如：

- `CreateStartBase(...)`
- `CreateMapStartSquad(...)`
- `CreateCargoSquad(...)`
- `InitCommanderPanel(...)`

地图只保留例外逻辑，例如：

- 无基地图给兵
- 运输图塞货舱
- 奖励给兵
- 阵容替换
- 特殊剧情变量绑定

## 实机验证口径

不要再用“字符串存在”代替验证。

最小闭环应该同时确认：

1. Launcher 选择和 Bank 写入正常
2. 地图读到了正确 commander
3. 标准基地图能生成对应开局单位
4. `CoopCaster<Commander>` 和面板被实际创建
5. 至少一个主动技能能正常下发
6. 无基地图/运输图/特殊分支没有掉回默认逻辑

## 当前项目中最值得坚持的约束

1. 新指挥官先完成依赖链和标准基地闭环，再补复杂机制。
2. `XMFinal` 继续作为阿巴瑟 runtime 唯一所有者。
3. 地图脚本只补差异，不回到“每图一套指挥官实现”的老路。
4. 旧阶段文档只做追溯，不再作为当前判断依据。
