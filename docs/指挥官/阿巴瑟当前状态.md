# 阿巴瑟当前状态

日期：2026-05-22

这份文档替代旧的阿巴瑟阶段成果、handoff 和部分经验总结，只描述当前仓内代码层面已经成立的状态，以及仍需继续验证的缺口。

## 已经成立

### 入口与依赖

- Launcher 已有 `Abathur` 候选。
- `XMFinal.SC2Mod` 已依赖 `XMAbathur.SC2Mod`。
- `XMFinal` 里存在 `Commander == "Abathur"` 的运行时分支。

### 运行时归属

- 阿巴瑟 runtime 已收口到 `XMFinal.SC2Mod`。
- `XMAbathur.SC2Mod` 当前定位应视为数据模组，不再承担 gameplay 事件入口。

### 开局与面板

- 标准基地开局已映射到阿巴瑟体系：
  - `CommandCenter -> HatcheryAbathur`
  - `Worker -> DroneAbathur`
  - `SecondUnit -> OverlordAbathur`
- `CoopCasterAbathur` 已在 `XMFinal` 初始化中创建。
- `CU_GPInitAbathur` 已接入顶部面板初始化链。

### 生物质与调试

- `AbathurBiomassDrop` 和 `AbathurBiomassPickup` 触发已在 `XMFinal` 中初始化并按阿巴瑟分支启用。
- 默认 debug Bank 写盘已通过代码常量关闭：
  - `libE0EAE146_gv_allowAbathurDebugBank = false`
- `XMAbathurDebug.SC2Bank` 只有在代码开关和 Bank 标志同时放开时才会写入。

### 地图适配

- `ttychus03` 的阿巴瑟占位 `Overlord` 分支已经被正式 helper 调用替换。
- 仓内已存在 `AbathurCreateMapStartSquad(...)` 一类的统一 helper 思路，说明地图适配方向已经从“硬写占位单位”转到“按指挥官给正式小队”。

### 成长映射

- `CommanderAch/Abathur` 已存在。
- `AbathurCommander` 和相关升级/巅峰映射已经进入 `XMCore` 的用户数据层。

## 当前仍不该夸大的地方

### 面板还不是德哈卡那种完成度

按当前 `XMCore.SC2Mod/Base.SC2Data/Lib67C0F0E7.galaxy`：

- `CU_GPInitAbathur` 仍使用 `ZergGlobalCommandPanelTemplate`
- 只初始化 2 个按钮
- 还没有独立的 `AbathurGlobalCommandPanelTemplate`

所以它已经不是“没入口”，但也还不算面板层完全收口。

### 生物质逻辑仍需继续以实机验证收口

当前仓内已经不是纯占位实现，但仍需要继续确认这些点：

- 掉落、拾取、叠层是否在 live 中稳定
- 属性增益是否完整兑现
- 终极进化阈值和触发链是否完全闭环
- 死亡返还或转移是否符合目标逻辑

### 单位与科技链不应只看静态存在

即便对象和映射已经在仓内，仍需要继续验证：

- 基础训练链
- 科技建筑点击
- 升级发放
- 地图特殊分支是否都落到阿巴瑟逻辑，而不是默认人族或占位逻辑

## 当前最准确的判断

可以确认的是：

- 阿巴瑟已经不是“只有名字”的状态。
- 依赖链、标准开局、运行时识别、生物质触发入口和部分地图 helper 已经落仓。
- 现在的重点已经从“把阿巴瑟接进来”转成“把阿巴瑟做完整并稳定验证”。

不应继续沿用旧稿里这些判断：

- “技能未实装，因此无法判断”
- “runtime 仍主要在 `XMAbathur`”
- “`ttychus03` 还是 Overlord 占位”
- “默认会生成调试 Bank”

## 建议后续顺序

1. 用标准基地图确认阿巴瑟开局、工蜂采矿、面板和基础训练链。
2. 用一张无基地图确认 helper 给兵。
3. 实机验证毒巢、修复和生物质循环。
4. 最后收口终极进化和更细的地图兼容。
