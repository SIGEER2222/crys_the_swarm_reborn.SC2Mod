# 战役中接入指挥官与兵种的正确方向

日期：2026-05-22

## 结论

当前这条移植方向，整体上是对的：

1. 不把官方合作模式依赖直接塞进战役地图。
2. 把指挥官数据拆到独立 `SC2Mod`。
3. 让战役运行时模组统一负责：
   - 开局单位生成
   - 顶部面板/全局施法者
   - 成长与 Bank
   - 地图分支适配
   - 战役目标、AI、特殊事件兼容

换句话说，`XMAbathur.SC2Mod` 放阿巴瑟数据，`XMFinal.SC2Mod` 做战役接线，这个架构方向是正确的。

真正错误、风险最高的方向，是“直接把 Coop 依赖和 Campaign 依赖一起挂到地图上，希望它自己能跑起来”。

## 为什么这个方向是对的

外部资料指向同一个结论：

1. SC2 的资产是通过 dependency mod 分发的，地图只是最终承载体。  
   这意味着“单位/技能/升级/按钮/音效”本来就应该优先放在 mod 里，而不是散落到每张地图中。

2. 战役资产和多人/合作资产是不同依赖栈。  
   Campaign 依赖提供单人剧情用数据；Coop 依赖是另一套数据生态。它们不是天然兼容。

3. 社区经验明确提到：  
   直接把 coop 和 campaign dependency 混在一起，通常会导致大量冲突，最后必须手工修到几乎等于“移植”。

所以，从“官方合作阿巴瑟”提取对象，再手工接入现有 XM 战役框架，而不是直接复用 coop 依赖，这条路线是合理的。

## 在战役里加入“指挥官 + 兵种”的正确做法

### 一、依赖层

正确顺序是：

1. 地图依赖 `XMFinal.SC2Mod`
2. `XMFinal.SC2Mod` 依赖：
   - `XMCore.SC2Mod`
   - 该指挥官自己的 mod，比如 `XMAbathur.SC2Mod`
   - 其他公共 XM 模组
   - 对应战役标准依赖

这样地图只认识统一入口，具体指挥官数据由 `XMFinal` 间接带入。

不建议让每张战役地图直接依赖每个指挥官 mod，更不建议把官方 coop dependency 直接挂到战役地图。

### 二、数据层

一个指挥官至少要有这几类对象：

1. `UnitData`
   - 基地
   - 工人
   - 初始人口单位
   - 指挥官兵种
   - 顶部面板施法者（如 `CoopCasterAbathur`）

2. `AbilData / ButtonData / EffectData / BehaviorData`
   - 主动技能
   - 被动成长
   - 单位训练/进化/科技

3. `RequirementData / UpgradeData / ValidatorData`
   - 解锁条件
   - 成长映射
   - 显示与使用判定

4. `ActorData / ModelData / SoundData`
   - 模型
   - 图标
   - 音效
   - 演员事件

### 三、运行时层

战役里“指挥官能不能用”，关键不只是数据存在，而是运行时有没有接线。

至少要接这几件事：

1. 开局单位创建
   - 读取当前 commander
   - 生成基地、工人、人口单位
   - 地图特殊开局时走 helper，而不是默认人族逻辑

2. 顶部面板创建
   - 生成 caster unit
   - 初始化 command panel
   - 挂按钮、冷却、充能、tooltip

3. 成长应用
   - 从 Bank / UserData 读取解锁项
   - 发放 Upgrade
   - 应用 mastery / 巅峰数值

4. 地图适配
   - 无基地图给兵
   - 空投图给 cargo squad
   - 特殊运输/奖励/分兵地图走专属 helper

5. 战役兼容
   - 不破坏原 mission trigger
   - 不破坏奖励目标、剧情、AI、胜负流程

### 四、地图层

战役地图最终只应该负责：

1. 自己的任务逻辑
2. 自己的硬编码例外分支
3. 调用统一 helper

不应该在每张图里重写整套指挥官逻辑。

更稳的方式是：

1. 地图判断 `Commander == "Abathur"`
2. 调用统一函数：
   - `CreateStartBase(...)`
   - `CreateMapStartSquad(...)`
   - `CreateCargoSquad(...)`
   - `InitCommanderPanel(...)`

## 对“阿巴瑟移植”这件事的判断

如果目标是“在战役里可交付地使用阿巴瑟”，那么正确目标不是：

- 让战役地图直接吃官方 coop 阿巴瑟

而是：

- 把官方 coop 阿巴瑟需要的数据搬到 XM 自己的 mod
- 再由 XM 战役框架统一接入

这点和网上的社区经验是吻合的。

## 对当前仓库的建议

结合当前仓库结构，更合理的收口方式是：

1. 保持 `XMAbathur.SC2Mod` 只做阿巴瑟数据承载
2. 保持 `XMFinal.SC2Mod` 作为唯一 runtime owner
3. 所有地图继续只依赖 `XMFinal.SC2Mod`
4. 地图脚本只保留调用 helper 的差异化分支
5. 不引入官方 coop dependency 到战役地图
6. 不用 `crys_the_swarm_reborn.SC2Mod` 当来源，只把它当写法参考

## 一个实用判断标准

如果某条方案满足下面 4 条，通常就是正确方向：

1. 地图依赖稳定，新增指挥官不需要重做全部地图依赖
2. 指挥官数据和战役逻辑分层清楚
3. 地图只写例外，不写整套指挥官实现
4. 替换一个指挥官时，不会把其他指挥官一起带崩

当前 XM 的“核心模组 + 指挥官模组 + 统一 runtime + 地图 helper”就是朝这个方向走的。
