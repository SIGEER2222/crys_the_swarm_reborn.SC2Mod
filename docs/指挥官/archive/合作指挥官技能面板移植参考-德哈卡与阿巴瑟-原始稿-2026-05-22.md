# 合作指挥官技能面板移植参考：德哈卡与阿巴瑟

本文用于给后续 AI/开发者快速理解当前工程的合作指挥官顶部技能面板实现方式，重点参考已经实装较完整的德哈卡，并对照阿巴瑟当前状态。

## 结论摘要

当前工程已经明确存在“合作指挥官顶部技能面板”体系。

德哈卡的技能面板已经是完整样板：

- 公共库 `XMCore.SC2Mod/Base.SC2Data/Lib67C0F0E7.galaxy` 负责创建顶部面板。
- `CU_GPInit(player, type, unit, secondUnit)` 根据 `type == "Dehaka"` 分派到 `CU_GPInitDehaka`。
- `CU_GPInitDehaka` 创建虫族顶部框架 `ZergCasterPanelTemplate`。
- 其内部再创建德哈卡专属命令面板 `DehakaGlobalCommandPanelTemplate`。
- 面板命令按钮绑定到全局施法单位 `CasterDehaka`。
- `CasterDehaka` 在 `UnitData.xml` 中挂载 4 个顶部面板技能。

阿巴瑟目前也有面板入口，但完成度明显低于德哈卡：

- `CU_GPInit` 已经有 `type == "Abathur"` 分支。
- `CU_GPInitAbathur` 目前使用通用 `ZergGlobalCommandPanelTemplate`。
- 只初始化 2 个按钮。
- 阿巴瑟官方技能数据已导入，例如 `AbathurMend`、`AbathurUltimateEvolution`、`ToxicNest`、`Symbiote*` 等。
- 但阿巴瑟顶部面板还没有像德哈卡一样建立专属 `AbathurGlobalCommandPanelTemplate`。
- 当前未确认 `CoopCasterAbathur` 是否已经作为完整全局施法单位接入到顶部面板按钮。

因此，阿巴瑟后续补面板时应以德哈卡为主要参考。

## 顶部技能面板整体机制

公共初始化入口是：

```galaxy
void lib67C0F0E7_gf_CU_GPInit (int lp_player, string lp_type, unit lp_unit, unit lp_secondUnit)
```

它的职责是：

1. 防止同一玩家重复初始化。
2. 记录全局施法单位：`lib67C0F0E7_gv_cU_GPUnit[lp_player] = lp_unit`。
3. 记录面板类型：`lib67C0F0E7_gv_commandPanelType[lp_player] = lp_type`。
4. 把施法单位加入 `lib67C0F0E7_gv_cU_GPCasterGroup[lp_player]`。
5. Hook 标准全屏面板容器：`UIContainer/FullscreenUpperContainer/GlobalCastingPanel`。
6. 根据 `lp_type` 分派到具体指挥官面板初始化函数。
7. 最后把命令面板绑定到施法单位组：

```galaxy
libNtve_gf_SetDialogItemUnitGroup(lib67C0F0E7_gv_cU_GPCmdPanel[lp_player], lib67C0F0E7_gv_cU_GPCasterGroup[lp_player], PlayerGroupSingle(lp_player));
```

这行很关键。顶部面板按钮不是单纯 Dialog 按钮，而是一个 `CommandPanel`，它显示的是某个隐藏/全局施法单位的命令卡。

换句话说：

```text
顶部面板按钮 = Layout CommandPanel + 全局施法单位 UnitData/CardLayouts/AbilArray
```

## 德哈卡技能面板实现链路

### 1. 地图/公共初始化创建 CasterDehaka

标准基地初始化中，当指挥官是德哈卡，会创建 `CasterDehaka` 并初始化面板：

```galaxy
libNtve_gf_CreateUnitsWithDefaultFacing(1, "CasterDehaka", c_unitCreateIgnorePlacement, 1, RegionGetBoundsMin(RegionEntireMap()));
lib67C0F0E7_gf_CU_GPInit(1, "Dehaka", UnitLastCreated(), null);
lib67C0F0E7_gf_CU_GPShowHide(true, 1, c_transitionDurationDefault);
lib67C0F0E7_gf_ShowChooseButton();
```

位置：

- `合作指挥官版起义狂潮/Mods/XM/XMFinal.SC2Mod/Base.SC2Data/LibE0EAE146.galaxy`

### 2. CU_GPInit 分派到德哈卡面板

公共函数中有：

```galaxy
else if (auto1CC9623D_val == "Dehaka") {
    lib67C0F0E7_gf_CU_GPInitDehaka(lp_player);
}
```

位置：

- `Lib67C0F0E7.galaxy` 的 `lib67C0F0E7_gf_CU_GPInit`

### 3. CU_GPInitDehaka 创建面板

德哈卡面板初始化函数做了这些事：

```galaxy
DialogControlCreateInPanelFromTemplate(lib67C0F0E7_gv_cU_GPPanelHolder, c_triggerControlTypePanel, "Coop_GlobalCastingTemplates/ZergCasterPanelTemplate");
lib67C0F0E7_gv_cU_GPPanel[lp_player] = DialogControlLastCreated();
DialogControlHookup(lib67C0F0E7_gv_cU_GPPanel[lp_player], c_triggerControlTypeCutscene, "ZergCommandCutscene");
lib67C0F0E7_gv_cU_GPCutscene[lp_player] = DialogControlLastCreated();
DialogControlHookup(lib67C0F0E7_gv_cU_GPPanel[lp_player], c_triggerControlTypePanel, "ButtonHolder");
lv_lastFrame = DialogControlLastCreated();
DialogControlCreateInPanelFromTemplate(lv_lastFrame, c_triggerControlTypeCommandPanel, "Coop_GlobalCastingTemplates/DehakaGlobalCommandPanelTemplate");
lib67C0F0E7_gv_cU_GPCmdPanel[lp_player] = DialogControlLastCreated();
```

之后循环 Hook 4 个按钮：

```galaxy
CommandButton00
CommandButton01
CommandButton02
CommandButton03
```

并绑定箭头：

```galaxy
AbilityArrow01
AbilityArrow02
AbilityArrow03
AbilityArrow04
```

最后播放德哈卡专属 cutscene：

```galaxy
libNtve_gf_SetDialogItemCutscene(lib67C0F0E7_gv_cU_GPCutscene[lp_player], "Cutscenes\\UI_DehakaCastingPanel.SC2Cutscene", PlayerGroupSingle(lp_player));
CutscenePlay(CutsceneGetTriggerControl(lib67C0F0E7_gv_cU_GPCutscene[lp_player]));
```

### 4. DehakaGlobalCommandPanelTemplate 提供 4 按钮布局

`Coop_GlobalCastingTemplates.SC2Layout` 中存在：

```xml
<Frame type="CommandPanel" name="DehakaGlobalCommandPanelTemplate" template="CommandPanel/CommandPanelTemplate">
```

它的职责是定义顶部面板的命令按钮控件，包括：

```text
CommandButton00
CommandButton01
CommandButton02
CommandButton03
```

模板级参数包括：

```xml
<HideUnusedButtons val="true"/>
<DisplayCancelCommandCard val="false"/>
<UseGridHotkeys val="false"/>
```

### 5. CasterDehaka 提供实际按钮和技能

`CasterDehaka` 位于：

```text
合作指挥官版起义狂潮/Mods/XM/XMDehaka.SC2Mod/Base.SC2Data/GameData/UnitData.xml
```

它继承：

```xml
<CUnit id="CasterDehaka" parent="CoopGlobalCaster">
```

挂载 4 个顶部技能：

```xml
<AbilArray Link="DehakaNydusDestroyerTopBar"/>
<AbilArray Link="DehakaGlevigTopBar"/>
<AbilArray Link="DehakaMurvarTopBar"/>
<AbilArray Link="DehakaDakrunTopBar"/>
```

命令卡按钮：

```xml
<CardLayouts>
    <LayoutButtons Face="DehakaNydusDestroyerTopBar" Type="AbilCmd" AbilCmd="DehakaNydusDestroyerTopBar,Build1" Row="0" Column="0"/>
    <LayoutButtons Face="DehakaGlevigTopBar" Type="AbilCmd" AbilCmd="DehakaGlevigTopBar,Build1" Row="0" Column="1"/>
    <LayoutButtons Face="DehakaMurvarTopBar" Type="AbilCmd" AbilCmd="DehakaMurvarTopBar,Execute" Row="0" Column="2"/>
    <LayoutButtons Face="DehakaDakrunTopBar" Type="AbilCmd" AbilCmd="DehakaDakrunTopBar,Execute" Row="0" Column="3"/>
</CardLayouts>
```

因此德哈卡面板的 4 个按钮实际来自 `CasterDehaka` 的命令卡，而不是来自地图脚本直接创建按钮。

## 德哈卡面板与英雄技能面板的区别

德哈卡有两类技能面板，不要混淆。

### 顶部技能面板

单位：

```text
CasterDehaka
```

用途：

```text
顶部全局技能，召唤原始首领/面板技能
```

按钮：

```text
DehakaNydusDestroyerTopBar
DehakaGlevigTopBar
DehakaMurvarTopBar
DehakaDakrunTopBar
```

UI 路径：

```text
GlobalCastingPanel -> ZergCasterPanelTemplate -> DehakaGlobalCommandPanelTemplate -> CasterDehaka CardLayouts
```

### 英雄命令卡

单位：

```text
DehakaCoop
```

用途：

```text
德哈卡英雄本体技能、学习、深槽、吞噬、跳跃等
```

单位技能包括：

```text
DehakaLearn
DehakaIntimidatingRoar
DehakaLeapStomp
DehakaConsume
DehakaMendingAura
DehakaDetector
DehakaDeepTunnel
MammothBreath
DehakaAirAttackUpgrade
DehakaArmorUpgrade
```

英雄命令卡存在于 `DehakaCoop` 的 `CardLayouts`，不是顶部全局面板。

### 4. 当前阿巴瑟需要重点核查的点

后续 AI 接手时，优先确认以下问题：

1. `XMAbathur.SC2Mod/Base.SC2Data/GameData/UnitData.xml` 中是否存在完整 `CoopCasterAbathur` 定义。

6. `CU_GPInitAbathur` 是否应从 `ZergGlobalCommandPanelTemplate` 改为专属 `AbathurGlobalCommandPanelTemplate`。
7. 阿巴瑟到底应显示几个顶部按钮，是 2 个、3 个还是 4 个。
8. 面板技能应绑定哪些：毒巢、治疗、终极进化、生物质收集、共生体相关技能。

## 建议的阿巴瑟面板目标结构

建议不要继续只用通用 `ZergGlobalCommandPanelTemplate`。可以仿照德哈卡建立完整结构：

```text
GlobalCastingPanel
└─ ZergCasterPanelTemplate
   └─ AbathurGlobalCommandPanelTemplate
      ├─ CommandButton00
      ├─ CommandButton01
      ├─ CommandButton02
      └─ CommandButton03
```

然后创建/修正全局施法单位：

```xml
<CUnit id="CoopCasterAbathur" parent="CoopGlobalCaster">
    <AbilArray Link="ToxicNest"/>
    <AbilArray Link="AbathurMend"/>
    <AbilArray Link="AbathurUltimateEvolution"/>
    <CardLayouts>
        <LayoutButtons Face="ToxicNest" Type="AbilCmd" AbilCmd="ToxicNest,Execute" Row="0" Column="0"/>
        <LayoutButtons Face="AbathurMend" Type="AbilCmd" AbilCmd="AbathurMend,Execute" Row="0" Column="1"/>
        <LayoutButtons Face="AbathurUltimateEvolution" Type="AbilCmd" AbilCmd="AbathurUltimateEvolution,Execute" Row="0" Column="2"/>
    </CardLayouts>
</CUnit>
```

以上只是建议结构，实际 `AbilCmd` 必须以 `AbilData.xml` 里的命令索引为准，例如有些技能可能是 `Execute`，有些可能是 `Build1` 或其他命令。

## 和地图移植的关系

技能面板通常不应该每张地图重复实现。

德哈卡的模式是：

```text
标准基地初始化 -> 创建 CasterDehaka -> CU_GPInit("Dehaka") -> 显示顶部面板
```

地图脚本只在特殊图补英雄、给兵、运输机、精华等逻辑。

阿巴瑟也应走类似模式：

```text
标准基地初始化 -> 创建 CoopCasterAbathur -> CU_GPInit("Abathur") -> 显示顶部面板
```

特殊地图只处理：

- 无基地剧情图是否也要创建 `CoopCasterAbathur`。
- 是否需要创建剧情代理单位并绑定 `gv_raynor`、`gv_nova` 等变量。
- 是否给生物质、毒巢、蟑螂、飞龙、守护者、吞噬者等地图专属支援。

## 对后续 AI 的执行建议

如果目标是让阿巴瑟面板达到德哈卡水平，建议按这个顺序做：

1. 先确认 `CoopCasterAbathur` 是否存在，以及其 `AbilArray/CardLayouts` 是否完整。
2. 确认 `XMFinal` 中阿巴瑟公共初始化创建的是 `CoopCasterAbathur`，而不是普通单位或空对象。
3. 复制德哈卡的模式，在 `Coop_GlobalCastingTemplates.SC2Layout` 添加 `AbathurGlobalCommandPanelTemplate`。
4. 修改 `CU_GPInitAbathur`，让它创建 `AbathurGlobalCommandPanelTemplate`。
5. 根据实际按钮数量把循环上限从 2 调整为实际数量。
6. 确认 `libNtve_gf_SetDialogItemUnitGroup` 能把命令面板绑定到 `CoopCasterAbathur`。
7. 进图验证：选择阿巴瑟后顶部面板是否显示、按钮是否显示、冷却是否正常、技能是否能释放。
8. 再逐个验证毒巢、治疗、终极进化、生物质/共生体相关技能。

## 参考判断

当前问题“技能面板有提到吗”的答案是：有，而且代码里已经有明确实现。

德哈卡：

```text
已完整提到并实装：专属 4 按钮顶部面板 + CasterDehaka + DehakaGlobalCommandPanelTemplate + UI_DehakaCastingPanel cutscene
```

阿巴瑟：

```text
已提到并有入口：CU_GPInitAbathur + 通用 ZergGlobalCommandPanelTemplate + 2 按钮初始化
但尚未形成德哈卡级别的专属完整面板
```

因此阿巴瑟后续移植时，技能面板不是从零开始，而是要把已有入口补齐成德哈卡同款结构。
