# 合作指挥官战役移植经验总结（2026-05-22）

## 结论

这次阿巴瑟和凯瑞甘的移植经验可以归纳成一句话：

**指挥官移植不是把一个名字塞进 Launcher，也不是把官方数据机械复制进项目；真正关键是数据依赖、运行时入口、地图分支、面板技能、验证链路五件事必须同时闭环。**

当前最有效的工程口径是：

1. 每个指挥官使用独立 `XM*.SC2Mod` 承载数据对象。
2. `XMFinal.SC2Mod` 作为统一战役整合层，依赖各指挥官模块。
3. 每张战役地图只依赖 `XMFinal.SC2Mod`，地图层只做必要的 mission-specific 分支。
4. Launcher 只负责把选择写入 Bank，不应该承载具体玩法逻辑。
5. 实机验证必须以 Bank、单位创建、面板技能、地图表现共同判断，不能只靠字符串扫描。

## 推荐架构

### 1. 指挥官数据层

每个指挥官单独一个模块，例如：

```text
Mods/XM/XMAbathur.SC2Mod
Mods/XM/XMKerrigan.SC2Mod
```

这一层负责让对象存在，包括：

```text
UnitData.xml
AbilData.xml
ActorData.xml
BehaviorData.xml
ButtonData.xml
EffectData.xml
ModelData.xml
RequirementData.xml
RequirementNodeData.xml
SoundData.xml
UpgradeData.xml
UserData.xml
ValidatorData.xml
WeaponData.xml
zhCN.SC2Data/LocalizedData/GameStrings.txt
```

这一层的目标不是让指挥官在战役里自动可玩，而是确保官方或自定义 Catalog 对象本身完整。

### 2. 核心公共层

公共 UI、通用面板、通用函数、CommanderAch 数据放在：

```text
Mods/XM/XMCore.SC2Mod
```

常见内容包括：

```text
CommanderAch/<Commander>
CU_GPInit<Commander>
CU_GPInit 分发分支
指挥官中文标题、描述、巅峰说明
通用面板模板初始化
```

`CommanderAch` 至少应包含：

```text
CommandCenter
Worker
SecondUnit
Upg[]
Poi[]
CommanderIcon
Text / DesP / TitU 等文本字段
```

### 3. 战役运行时整合层

运行时接线放在：

```text
Mods/XM/XMFinal.SC2Mod
```

这一层负责把“数据对象”变成“战役里能运行的指挥官”。

重点包括：

```text
读取 CampaignXCore.SC2Bank 中的 Commander
设置控制台皮肤
InitializeBase 中创建基地、工人、初始单位
创建 CoopCaster<Commander>
调用 CU_GPInit
显示全局技能面板
创建英雄或特殊开局单位
启用专属 runtime 触发器
执行调试 Bank 快照
```

### 4. 地图层

地图层只做少量特殊分支，例如：

```text
无基地剧情图给初始小队
运输机地图替换 cargo / escort 单位
特殊剧情英雄图避免刷错原版英雄
特殊目标图修正任务判定
```

地图层不应该复制大量指挥官数据，也不应该成为指挥官玩法主实现位置。

## 必查依赖链

这是最容易漏、也最致命的地方。

地图一般依赖：

```text
Maps/XM/<map>.SC2Map/DocumentInfo
  -> file:Mods\XM\XMFinal.SC2Mod
```

`XMFinal.SC2Mod` 必须继续依赖实际指挥官模块：

```text
Mods/XM/XMFinal.SC2Mod/DocumentInfo
  -> file:Mods\XM\XMCore.SC2Mod
  -> file:Mods\XM\XMAbathur.SC2Mod
  -> file:Mods\XM\XMKerrigan.SC2Mod
  -> 其他已接入指挥官模块
```

如果新增了 `XMKerrigan.SC2Mod`，但没有把它加入 `XMFinal.SC2Mod/DocumentInfo`，结果通常是：

```text
Launcher 可以看到 Kerrigan
Bank 也可能写入 Kerrigan
脚本分支也可能进入 Kerrigan
但是 K5Kerrigan / CoopCasterKerrigan / 技能 / Actor / Button 可能全部找不到或失效
```

因此每次新增指挥官，第一优先级检查是：

```text
1. 指挥官模块是否存在
2. 指挥官模块自身是否依赖 XMCore
3. XMFinal 是否依赖该指挥官模块
4. 地图是否依赖 XMFinal
```

## Launcher 接入经验

Launcher 的职责只应该是“可选择”和“写 Bank”。

需要检查：

```text
Maps/XM/LauncherAuto.SC2Map/MapScript.galaxy
Maps/XM/LauncherAuto.SC2Map/Base.SC2Data/GameData/UserData.xml
Maps/XM/LauncherAuto.SC2Map/zhCN.SC2Data/LocalizedData/GameStrings.txt
```

常见修改：

```text
gv_commanderNum 扩容
CommanderPreset Count 扩容
新增 CommanderPreset 实例值
新增头像路径
新增标题、描述、巅峰文本
```

注意：

```text
Launcher 能显示指挥官，只能证明选择入口存在；不能证明地图里能创建单位，也不能证明技能可用。
```

## Bank 验证经验

指挥官运行时一般从：

```text
Documents/StarCraft II/Banks/CampaignXCore.SC2Bank
```

或项目自定义 Debug Bank 中读取/写入。

本轮阿巴瑟调试中确认过一个重要问题：

```text
Bank 不一定在 Accounts 子目录下。
```

实际曾确认有效路径是：

```text
C:/Users/22448/Documents/StarCraft II/Banks/XMAbathurDebug.SC2Bank
```

调试 Bank 应记录至少这些字段：

```text
Commander
Map
Phase
CommandCenter
Worker
SecondUnit
关键单位计数
```

Bank 验证适合回答：

```text
是否读取到了指挥官
是否进入了 Initialize / InitializeBase
CommanderAch 映射是否正确
标准基地单位类型是否正确
无基地图特殊分支是否执行
```

Bank 验证不能回答：

```text
技能按钮是否能点
Actor 是否显示正常
升级效果是否真实生效
复杂触发器是否全部闭环
```

## 标准基地图验证顺序

对新指挥官，优先用标准基地图验证最小闭环。

顺序建议：

```text
1. Launcher 选择指挥官
2. 进入标准基地地图
3. Bank 确认 Commander 正确
4. Bank 或实机确认 CommandCenter / Worker / SecondUnit 正确
5. 确认 CoopCaster<Commander> 创建
6. 确认 CU_GPInit<Commander> 被调用
7. 确认面板出现且不报错
8. 确认英雄或专属开局单位创建
9. 测一个最简单主动技能
10. 再测升级、科技树、复杂机制
```

不要一开始就追求完整玩法。先证明最小链路，再扩展机制。

## 无基地剧情图经验

`traynor01` 这类地图不走普通基地开局，因此不能只改 `InitializeBase`。

无基地图要单独看地图脚本里的创建单位逻辑，例如：

```text
Maps/XM/traynor01.SC2Map/MapScript.galaxy
```

阿巴瑟经验：

```text
不能继续走默认 WarPig / 人族英雄分支
应为 Abathur 单独给 Hydralisk / Zergling / Queen 等虫族开局小队
```

凯瑞甘经验：

```text
只写一个 gf_KerriganCommanderBranchMarker，并不等于地图真的支持 Kerrigan
必须确认这个分支被实际调用，并替换掉对应出生单位、剧情单位或任务判定
```

判断地图分支是否有效，不能只看文件里有没有：

```text
== "Kerrigan"
```

而要看：

```text
这个判断是否在实际触发器路径上
判断后是否真的创建/替换/跳过了某些单位
是否会影响任务胜负、剧情镜头、AI 波次
```

## 面板技能经验

创建面板模板不等于技能可用。

一个完整面板至少需要闭环：

```text
1. 创建 CoopCaster<Commander>
2. 调用 CU_GPInit<Commander>
3. 使用正确面板模板
4. Hookup 正确 ButtonHolder / CommandButton
5. 按钮绑定到 caster 的 Ability Command
6. 冷却、费用、禁用状态能刷新
7. 点击按钮能下发命令
8. Ability / Effect / Validator / Requirement / Upgrade 数据全部存在
```

阿巴瑟面板当前重点：

```text
SpawnToxicNest
AbathurMend
```

凯瑞甘面板当前风险：

```text
CU_GPInitKerrigan 目前更像是 Zerg 面板壳
需要继续确认 CoopCasterKerrigan 的按钮命令和技能链是否真的适配当前项目
```

## 阿巴瑟经验

阿巴瑟已经证明有效的方向：

```text
独立 XMAbathur.SC2Mod 承载数据
XMFinal 负责运行时接线
CommanderAch/Abathur 映射到 HatcheryAbathur / DroneAbathur / OverlordAbathur
InitializeBase 中创建 CoopCasterAbathur
CU_GPInitAbathur 初始化顶部面板
无基地图单独给虫族小队
用 XMAbathurDebug.SC2Bank 做早期快照
```

阿巴瑟主要风险：

```text
生物质掉落、拾取、叠层、属性成长还需要完整闭环
终极进化触发链还需要实机确认
顶部面板显示正常不等于 SpawnToxicNest / Mend 效果完整
调试 Bank 如果被默认关闭，会显著降低排查效率
```

阿巴瑟移植的经验是：

```text
先让系统识别 Abathur，再让它能落地，再补面板，最后补完整生物质玩法。
```

不要反过来先做完整生物质，否则很难判断问题出在识别、依赖、单位、触发器还是效果链。

## 凯瑞甘经验

凯瑞甘另一个 AI 的方向总体正确：

```text
新建 XMKerrigan.SC2Mod
导入官方 K5Kerrigan / CoopCasterKerrigan / PsiStrike 等数据
Launcher 增加 Kerrigan
XMCore 增加 CommanderAch/Kerrigan
XMFinal 增加 Kerrigan 初始化分支
CU_GPInit 增加 Kerrigan 分发
```

但是当前必须优先修正：

```text
XMFinal.SC2Mod/DocumentInfo 缺少 file:Mods\XM\XMKerrigan.SC2Mod
```

这是比技能完整性更靠前的问题。模块没加载时，后续所有创建单位和技能测试都可能是假问题。

凯瑞甘的推荐验证链：

```text
1. 修 XMFinal 依赖 XMKerrigan
2. 验证 Launcher 能写 Commander=Kerrigan
3. 验证标准基地图能读到 Kerrigan
4. 验证 Hatchery / Drone / Overlord 正常创建
5. 验证 K5Kerrigan 正常创建
6. 验证 CoopCasterKerrigan 正常创建
7. 验证面板出现
8. 测一个基础英雄技能
9. 再处理同化光环、巅峰、科技链、剧情图兼容
```

凯瑞甘当前不应宣称“可玩完成”。更准确的判断是：

```text
数据和入口骨架已搭好，但依赖链、实机加载、面板命令和剧情图分支仍未收口。
```

## 验证脚本经验

验证脚本有价值，但必须避免“字符串存在即通过”。

结构检查可以搜：

```text
CommanderAch/<Commander>
CoopCaster<Commander>
CU_GPInit<Commander>
K5Kerrigan / HatcheryAbathur 等关键单位
Launcher CommanderPreset
地图中 Commander 分支
```

但必须额外检查：

```text
XMFinal.SC2Mod/DocumentInfo 是否依赖新增指挥官模块
指挥官模块 DocumentInfo 是否依赖 XMCore
关键 Unit / Ability / Button / Effect 是否在同一加载链中
头文件是否声明新增函数
脚本调用和声明是否一致
```

对地图分支，不要只检查：

```text
== "CommanderName"
```

还要检查附近是否有实际行为：

```text
CreateUnits
UnitIssueOrder
TriggerExecute
if / else 分支影响了原始创建逻辑
return / skip / replacement
```

## 常见假阳性

### 1. Launcher 有头像，不代表指挥官可玩

Launcher 只是入口。

### 2. Bank 写入 Commander，不代表数据已加载

Bank 只证明选择链路通了。

### 3. XML 中有 Unit id，不代表地图加载了这个 Unit

必须确认依赖链。

### 4. 面板出现，不代表技能可用

技能需要 Ability、Button、Effect、Requirement、Validator、Upgrade、Caster、Command 共同闭环。

### 5. 地图里有字符串判断，不代表分支执行

必须确认触发器路径。

### 6. 验证脚本通过，不代表实机通过

验证脚本主要用于防漏文件和防漏字符串，不能替代游戏测试。

## 推荐新增指挥官流程

以后新增任意指挥官时，按这个顺序做：

```text
1. 建立 XM<Commander>.SC2Mod
2. 导入或补齐关键 Catalog 数据
3. XM<Commander>.SC2Mod 依赖 XMCore
4. XMFinal.SC2Mod 依赖 XM<Commander>.SC2Mod
5. XMCore 增加 CommanderAch/<Commander>
6. Launcher 增加候选、头像、文本
7. XMFinal Initialize 增加控制台皮肤和补给等基础分支
8. XMFinal InitializeBase 增加 CoopCaster / Hero / 面板初始化
9. XMCore 增加 CU_GPInit<Commander> 和分发
10. 加 Debug Bank 或复用现有诊断链
11. 验证标准基地图
12. 再逐张处理无基地图和特殊剧情图
13. 最后补完整指挥官机制
```

## 推荐每次实机前检查清单

```text
git diff --stat 看是否改动范围合理
XMFinal DocumentInfo 是否包含新增指挥官模块
Launcher 是否包含新增 CommanderPreset
CommanderAch 是否包含 CommandCenter / Worker / SecondUnit
XMFinal 是否读取并分发 Commander
InitializeBase 是否存在该 Commander 分支
CU_GPInit 是否存在该 Commander 分支
头文件声明是否同步
游戏目录是否已同步 Mods 和 Maps
Bank 路径是否确认正确
```

## 一句话给后续接手者

**不要被“能选”“有字符串”“验证脚本通过”迷惑。指挥官移植真正的完成标准是：依赖链加载、Bank 识别、标准基地落地、专属单位创建、面板技能可用、核心机制生效、特殊地图不破。每一步都要用实机或可靠诊断证明。**
