## 当前仍需收口

### `CommanderAch/Kerrigan` 映射已开始纠偏

截至 `2026-05-23`，已确认旧阶段稿里沿用过来的几组 ID 已经过时，至少包括：

- `KerriganHeroicFortitude` 实际应落到 `VoidCoopHeroicFortitude`
- `CommanderPrestigeKerriganMalignantCreep` 实际应落到 `CommanderPrestigeKerriganCreep`
- `MasteryKerriganAttackDamage` 实际应落到 `MasteryKerriganAutoAttackDamage`

这一类问题和此前阿拉纳克的旧 ID 问题属于同一类：对象名看起来像对的，但并不对应当前仓内真实可用的官方升级对象。后续判断以 `XMKerrigan.SC2Mod/Base.SC2Data/GameData/UpgradeData.xml` 与官方导出为准。

### `XMFinal` 已补默认运行时接线

当前 `XMFinal` 已补入凯瑞甘专属 runtime 入口，用于把 `PlayerCommanders/ZergKerrigan` 的：

- `DefaultAbilityCommands`
- `DefaultUpgrades`
- `CommanderSkin`

真正应用到玩家运行时。

这一步很重要，因为仅仅“导入了 `K5Kerrigan` 和相关对象”并不等于它们会在进图后自动具备正确的默认解锁和升级状态。

### 面板仍是通用虫族模板

按当前 `CU_GPInitKerrigan` 实现：

- 仍使用 `ZergCasterPanelTemplate`
- 内层仍是 `ZergGlobalCommandPanelTemplate`
- 只初始化 2 个按钮

进一步静态核对官方 `PlayerCommanders/ZergKerrigan` 后，可以确认它的 `DefaultAbilityCommands` 主要指向 `evolutionchamberresearch` 相关命令，而不是像阿巴瑟/斯托科夫那样依赖独立的顶部主动技能链。因此 `CoopCasterKerrigan` 更像兼容当前 XM 框架的壳，后续应优先保证 `K5Kerrigan` 英雄本体命令卡，而不是继续把凯瑞甘当成重顶栏指挥官处理。

当前仓内已进一步收口为：

- 仍创建 `CoopCasterKerrigan`
- 仍初始化 `CU_GPInitKerrigan`
- 但 `XMFinal` 不再默认强制显示凯瑞甘顶部面板

这样做的目的不是放弃顶部面板，而是先避免出现“英雄技能主要在本体命令卡，但画面上额外再挂一个空壳顶栏”的中间态。

所以它现在更像“runtime 已有入口的第一阶段实现”，还不是完整的凯瑞甘专属顶部面板。

### Live 验证还不能省

当前仓内结论主要能证明：

- 依赖链在

凯瑞甘已经不是纯规划状态，而是：

- 模组已建
