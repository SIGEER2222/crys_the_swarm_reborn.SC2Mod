# SC2Map 结构与指挥官地图适配说明

生成日期：2026-05-23

## 目的

本文说明本仓库中 `.SC2Map` 解包目录的结构、运行时入口、与合作指挥官移植的关系。后续新增或完善指挥官时，应先理解地图脚本如何读取 Launcher 写入的 Bank、如何调用公共初始化、以及哪些地图需要逐图补分支。

```text

```


不是每张图都包含完整结构；多数任务图核心关注 `MapScript.galaxy`。

## LauncherAuto.SC2Map 的职责

`LauncherAuto.SC2Map` 是指挥官选择入口。它通过 `CommanderPreset` UserData 构建候选列表，并把选择写入 Bank。

关键文件：

```text
LauncherAuto.SC2Map/MapScript.galaxy
LauncherAuto.SC2Map/Base.SC2Data/GameData/UserData.xml
LauncherAuto.SC2Map/zhCN.SC2Data/LocalizedData/GameStrings.txt
```

关键字段：

```text
CommanderPreset.ID.Commander
CommanderPreset.ID.CommanderPortrait
CommanderPreset.ID.Por
```

关键常量：

```galaxy
const int gv_commanderNum = N;
```

含义：候选索引是 `0..N`，所以如果有 11 个候选，`gv_commanderNum` 应为 `10`。

## 当前工作区 LauncherAuto 候选状态

当前工作区 UserData 曾多次被改动，需以后续验证脚本为准。新增指挥官时必须同时检查：

```text
MapScript.galaxy 的 gv_commanderNum
UserData.xml 的 Fields Count
UserData.xml 的 Commander 字段
GameStrings.txt 的头像/文本
```

注意：实际游戏启动的 live `Launcher.SC2Map` 可能是单文件地图包，不等同于工作区 `LauncherAuto.SC2Map` 解包目录。用户已要求当前阶段不处理打包问题，因此本文只记录工作区结构。

## 任务图运行时入口

任务图通常通过 `XMFinal.SC2Mod` 的公共库读取当前指挥官，并调用标准初始化函数。

关键函数：

```galaxy
libE0EAE146_gf_InitializeBase(...)
```

该函数负责：

1. 从 Bank / 全局变量读取当前指挥官。
2. 根据 `XMCore` 的 `CommanderAch/<Commander>` 读取基地、工人、第二单位。
3. 创建标准基地开局。
4. 对特定指挥官创建英雄、面板 caster、顶部面板或特殊机制入口。

## 地图类型分类

### 1. 标准基地图

特征：`MapScript.galaxy` 中调用：

```galaxy
libE0EAE146_gf_InitializeBase
```

这类图优先依赖公共初始化，不应该为每个指挥官手写完整开局。

需要做：

- 确保 `CommanderAch/<Commander>` 有正确 `CommandCenter / Worker / SecondUnit`。
- 确保 `XMFinal` 对该指挥官有标准初始化分支。
- 实机验证任务触发是否被新英雄/单位阻塞。

### 2. 无基地剧情图

典型：

```text
traynor01.SC2Map
ttosh03b.SC2Map
tvalerian01.SC2Map
```

这类图通常不靠标准基地，必须在地图脚本里按指挥官补分支。

需要做：

- 创建英雄或等价剧情代理单位。
- 绑定原剧情变量，如 `gv_raynor`、`gv_nova`。
- 给少量起始小队。
- 避免隐形/空军/大体积单位破坏剧情触发。

### 3. 运输机/货舱图

典型：

```text
thorner02.SC2Map
ttychus02.SC2Map
```

需要按指挥官补：

```galaxy
UnitCargoCreate(...)
```

常见适配：

- 人族：Marine / Medic / Marauder
- 虫族：Zergling / Hydralisk / Baneling
- 星灵：Zealot / Stalker / Immortal
- 英雄型：必要时直接在落点创建英雄，而不是塞运输机

### 4. 奖励给兵图

典型：

```text
thorner05s.SC2Map
```

需要根据指挥官给一组等价兵种。

### 5. 空战支援图

典型：

```text
ttychus04.SC2Map
ttychus05.SC2Map
```

需要根据指挥官给空军支援。

### 6. 阵容替换图

典型：

```text
tvalerian01.SC2Map
```

需要为指挥官提供完整等价阵容，不只是一个英雄。

## 地图脚本中指挥官分支模式

常见形式：

```galaxy
if (autoXXX_val == "Dehaka") {
    ...
}
else if (autoXXX_val == "Kerrigan") {
    ...
}
else if (autoXXX_val == "Alarak") {
    ...
}
```

后续新增指挥官时，应优先沿用现有相邻分支的变量名和点位，不要重写整段逻辑。

## 地图适配风险

| 风险 | 说明 | 处理方式 |
|---|---|---|
| 剧情变量为空 | 无基地图常依赖 `gv_raynor/gv_nova` | 必须把新英雄或核心单位赋值给原变量 |
| 隐形单位绕过触发 | Vorazun/Zeratul 常见 | 给非隐形代理或额外小队 |
| 空军无法触发地面区域 | 空军指挥官常见 | 至少给一个地面核心单位 |
| 大体积单位卡路径 | Colossus/Ultralisk/Thor 类 | 控制数量和生成点 |
| 运输机不能装英雄 | 部分英雄/巨大单位 | 改为落点直接创建 |
| 阵营敌我关系错误 | 阵容替换图常见 | 使用地图原玩家变量，如 `gv_p12_MOEBIUS` |

## 验证要求

每个指挥官地图接入后至少检查：

1. 关键地图脚本包含 `== "Commander"` 分支。
2. `traynor01` 和 `ttosh03b` 有剧情变量绑定。
3. `tvalerian01` 有完整阵容替换。
4. `thorner02/ttychus02` 有货舱或落点单位。
5. `ttychus04/ttychus05` 有空军支援。
6. Galaxy 文件括号平衡。
7. 对应进度文档记录地图改动。
