# 技能面板移植参考：德哈卡与阿巴瑟

日期：2026-05-22

这份文档保留旧稿里最有价值的技术结论，但去掉了阶段性猜测和已经过时的判断。它只回答一个问题：当前工程里，合作指挥官顶部技能面板是怎么接入的，以及阿巴瑟还差什么。

## 结论

当前工程的顶部技能面板体系已经存在，而且德哈卡是最完整的现成样板。

阿巴瑟已经接进这套体系，但完成度明显低于德哈卡：

- 德哈卡：专属命令面板、4 按钮、专属 cutscene、完整 `CasterDehaka` 样板。
- 阿巴瑟：已接 `CU_GPInitAbathur` 和 `CoopCasterAbathur`，但仍使用通用虫族模板，当前只有 2 按钮。

因此，后续若要继续完善阿巴瑟或凯瑞甘顶部技能面板，德哈卡应该作为第一参考对象。

## 公共机制

统一入口在：

```galaxy
void lib67C0F0E7_gf_CU_GPInit (int lp_player, string lp_type, unit lp_unit, unit lp_secondUnit)
```

这套逻辑的关键点是：

1. 记录当前面板归属的全局施法单位。
2. 把施法单位加入命令面板绑定组。
3. Hook 顶部 `GlobalCastingPanel` 容器。
4. 按 `lp_type` 分发到具体指挥官的 `CU_GPInit<Commander>`。
5. 用 `SetDialogItemUnitGroup(...)` 把命令面板和全局施法单位绑定起来。

换句话说，顶部技能按钮不是脚本直接造出来的孤立按钮，而是：

```text
Layout 模板 + CommandPanel + 全局施法单位的 AbilArray / CardLayouts
```

## 德哈卡为什么是好样板

当前仓内，德哈卡这一套已经比较完整：

- `CU_GPInitDehaka`
- `DehakaGlobalCommandPanelTemplate`
- `CasterDehaka`
- 4 个顶部技能按钮
- 对应专属 cutscene

这说明一套成熟的实现至少需要：

1. 专属 `GlobalCommandPanelTemplate`
2. 专属 `CoopGlobalCaster` 子单位
3. 该单位上正确的 `AbilArray`
4. 该单位上与按钮对应的 `CardLayouts`
5. `CU_GPInit<Commander>` 中正确数量的按钮和箭头 Hook

## 阿巴瑟当前状态

按当前仓内代码：

- `CU_GPInitAbathur` 已存在。
- 已使用 `ZergCasterPanelTemplate` 接入顶部框架。
- 内层仍是 `ZergGlobalCommandPanelTemplate`。
- 当前只 Hook 2 个按钮。

这意味着：

- 阿巴瑟面板不是空白。
- 但它还不是“德哈卡同级”的专属面板实现。

## 后续如果继续补阿巴瑟面板，建议先查这几件事

1. `CoopCasterAbathur` 是否完整继承自 `CoopGlobalCaster`
2. `CoopCasterAbathur` 的 `AbilArray` 是否与目标面板技能一致
3. `CoopCasterAbathur` 的 `CardLayouts` 是否已经覆盖所需按钮
4. 是否需要新增 `AbathurGlobalCommandPanelTemplate`
5. `CU_GPInitAbathur` 的按钮数量是否应从 2 扩到正式值

## 凯瑞甘为什么也应该参考这份文档

当前 `CU_GPInitKerrigan` 和阿巴瑟类似：

- 也走虫族公共模板
- 也只初始化 2 个按钮

所以阿巴瑟和凯瑞甘都属于“已经接进公共面板体系，但还没进化成专属面板”的阶段。补这类指挥官时，技术路线应优先向德哈卡靠拢，而不是继续在通用模板上叠更多临时逻辑。
