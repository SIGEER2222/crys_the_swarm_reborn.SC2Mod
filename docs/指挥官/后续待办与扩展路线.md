# 后续待办与扩展路线

日期：2026-05-23

这份文档只记录收口后的下一步。当前基线是：18 个目标指挥官都已补齐到战役 mod，后续不再按旧的逐个扩展方式推进，而是做集中 live 回归和局部机制增强。

## 第一优先级：统一 live 回归

集中验证一次，避免频繁启动游戏打断工作。

1. 启动前先杀掉旧进程：
   - `taskkill /f /im "SC2_x64.exe"`
2. 再启动 Launcher：
   - `& "E:\SC2\SC2new\StarCraft II\Support64\SC2Switcher_x64.exe" "E:\SC2\SC2new\StarCraft II\Maps\XM\Launcher.SC2Map"`
3. Launcher 验证：
   - 18 个目标指挥官都能出现在候选中。
   - 重点确认补位项 `Abathur`、`Alarak`、`Kerrigan`。
   - 选择后 Bank 中的 `Ach/Commander` 与所选指挥官一致。
4. 标准基地图验证：
   - 基地、工人、初始补给单位正确替换。
   - 基础采集、基础建筑、训练链和核心科技链可用。
5. 无基地图验证：
   - 使用对应指挥官的初始部队或 helper 给兵。
   - 不落回默认人族、空分支或占位单位。
6. 运输、奖励、剧情特殊图验证：
   - cargo / squad helper 能按指挥官类型生成。
   - 过场后单位、英雄、面板仍存在。
7. 顶部面板和英雄技能验证：
   - 主动按钮能点击、冷却和效果一致。
   - 被动或触发机制不强行改成按钮，只验证实际玩法链路。

## 第二优先级：局部机制增强

这些不是“指挥官未补齐”，而是当前基线后的增强项。发现问题时写入对应指挥官状态文档。

| 类型 | 处理方式 |
|---|---|
| 官方机制差异 | 只补最小必要链路，避免整包搬入合作模式 |
| 顶部面板缺项 | 先确认官方机制是按钮、英雄技能还是被动触发，再补 UI |
| 训练或科技断链 | 优先修模块数据，再补 runtime helper |
| 地图特殊分支 | 优先加公共 helper，不逐图复制一套硬编码 |
| 成长与文案 | 以当前 `CommanderAch` / 模块数据为准，统一文案，不保留“预留”口径 |

## 第三优先级：文档同步

1. 每次 live 回归后，把结果写回对应指挥官目录或当前状态文档。
2. 如果验证发现通用问题，优先更新 `当前架构与接入原则.md` 或本文件。
3. 历史归档只用于追溯，不再改写旧规划。
4. 新文档必须明确区分：
   - 已补齐的当前基线
   - live 回归发现的问题
   - 可选的局部机制增强

## 不再使用的旧口径

- 不再写“后续扩展到更多指挥官”。
- 不再把 `Stukov`、`Dehaka`、`Tychus`、`Mira`、`Nova`、`Mengsk`、`Swann`、`Stetmann` 写成独立扩展对象。
- 不再把 Launcher 可见性等同于完整玩法完成；必须结合基地、兵种、建筑、英雄、面板和地图分支验证。
- 不再频繁单点启动游戏验证；优先积累静态改动后做集中 live 回归。
