# XMFinal 依赖二分记录

日期：2026-05-23

## 结论

当前不能把后来新增的指挥官模组一次性加回 `XMFinal.SC2Mod/DocumentInfo`。更重要的是，不能把这轮实验理解为“`XMFinal` 原始架构必须直接依赖 `XMCore`”。

已核对早期基线：`git show 3f94b3a:合作指挥官版起义狂潮/Mods/XM/XMFinal.SC2Mod/DocumentInfo` 中，`XMFinal` 只依赖自由之翼战役和已有 XM 公共/旧指挥官模块，没有 `XMCore.SC2Mod`。`XMCore` 是公共底库，当前地图通过 `XMAlarak.SC2Mod -> XMCore.SC2Mod` 间接加载它；因此 `XMFinal -> XMCore` 不是原始必需直依赖。

这轮 direct-map 验证只能说明：

- `XMFinal` 原有共享依赖可以进图。
- 在当时实验组合里，`XMCore.SC2Mod` 单独加到 `XMFinal` 可以进图。
- 在当时实验组合里，`XMCore + XMRaynor.SC2Mod` 可以进图。
- 在当时实验组合里，`XMCore + 其余单个后来指挥官模组` 会失败，表现为 `unable launch game`、`timeout` 或 `SC2_x64 is not running`。

因此问题不能归结为“缺少 `XMCore` 直依赖”。更准确的判断是：`XMCore` 本身是必要公共底库，但应优先由具体指挥官/地图链路间接加载；失败点需要继续定位到具体后加指挥官模组、`DocumentHeader`/`DocumentInfo` 一致性，或该模组自身数据链。当前至少这些模组不能直接挂到 `XMFinal` 共享入口后声明完成：

| 模组 | 结果 | 备注 |
|---|---|---|
| `XMAbathur.SC2Mod` | 失败 | `MAP_ENTRY_SIGNAL=timeout` |
| `XMKerrigan.SC2Mod` | 失败 | `SC2_x64 is not running` |
| `XMRaynor.SC2Mod` | 通过 | `MAP_ENTRY_SIGNAL=alerts` |
| `XMFenix.SC2Mod` | 失败 | `SC2_x64 is not running` |
| `XMArtanis.SC2Mod` | 失败 | `SC2_x64 is not running` |
| `XMKarax.SC2Mod` | 失败 | `MAP_ENTRY_SIGNAL=timeout` |
| `XMZagara.SC2Mod` | 失败 | `MAP_ENTRY_SIGNAL=timeout` |
| `XMVorazun.SC2Mod` | 失败 | `MAP_ENTRY_SIGNAL=timeout` |
| `XMZeratul.SC2Mod` | 失败 | `MAP_ENTRY_SIGNAL=timeout` |

## 已跑验证

测试入口：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\test-xmfinal-single-commander-deps.ps1 -MapName thanson03b.SC2Map -Commander Alarak -MapEntryTimeoutSec 120
```

关键对照：

```text
XMCore only: MAP_ENTRY_SIGNAL=alerts
XMRaynor:    MAP_ENTRY_SIGNAL=alerts
XMAbathur:  MAP_ENTRY_SIGNAL=timeout
```

## 对阿巴瑟的影响

`HatcheryAbathur`、`DroneAbathur`、`SpawnToxicNest`、`BiomassPickup` 等对象已经存在于 `XMAbathur.SC2Mod`，但当前不能只靠把 `XMAbathur.SC2Mod` 加回 `XMFinal` 来解决加载问题。

在 `XMAbathur` 自身的启动失败修好前，标准图里出现阿巴瑟对象找不到，不应再被误判为“对象未导入”。更准确的状态是：

1. 数据对象存在。
2. `XMFinal` 共享依赖链不能安全加载 `XMAbathur`。
3. 需要先修 `XMAbathur.SC2Mod` 作为依赖被 SC2 加载时的启动失败，再继续验证阿巴瑟单位和技能。

## 后续处理建议

1. 保持 `XMFinal.SC2Mod/DocumentHeader` 和当前可启动的 `DocumentInfo` 状态，不要把所有后加指挥官依赖一次性恢复。
2. 不要把 `XMCore.SC2Mod` 作为 `XMFinal` 的默认直依赖强行恢复；先确认当前地图是否已经通过 `XMAlarak.SC2Mod` 或其他指挥官模组间接加载 `XMCore`。
3. 以 `XMRaynor` 为可通过样本，对比失败模组的 `ComponentList.SC2Components`、`DocumentInfo`、`DocumentHeader`、`GameData.version`、`GameText.version`、`Base.SC2Data/GameData/*.xml`。
4. 对 `XMAbathur` 先做独立模组加载诊断，而不是继续调 `XMFinal` runtime。
5. 每次只加一个模组到 `XMFinal`，同步 `DocumentHeader` 后用 direct-map 验证；确认通过后再合并到共享依赖表。
